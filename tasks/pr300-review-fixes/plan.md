# PR #300 评审修复计划

日期：2026-10-26。用户授权先规划，再修复评审问题并更新现有PR。工作树为smart-collections-pr，起点6bf923d5。原tasks/plan.md和todo.md属于备份任务，保留其未完成项，本计划和任务表单独存放。

## 决策与顺序

1. **P2 大小精度。** 先以真实组件提交回调复现1.001、1.000001 MB错误；输入限定非负十进制和最多6位小数，以整数字符串表示字节并核对安全整数范围。空输入仍清除条件，严格上下界语义不变。不新增依赖。
2. **P2 指纹暂停。** 先验证任务领取后存储停用、保留既有重试/恢复预算、重新启用继续。执行捕获处使用现有analyzeMediaError的code；存储停用保持queued，由已有storage.enabled调度条件暂停。删除error LIKE恢复扫描。普通真实失败仍保留错误并要求既有重试，中断语义不变。
3. **P3 组件职责。** 将截图标签选择、创建、错误、pending及提交移至专有对话框。父组件只触发打开及应用已选模板，不再把screenshot与save/rename/delete混在同一mode中。不重写其余CRUD或公共组件。
4. **联验和复核。** 每个行为先失败后修复，执行相关单元/集成、lint、类型、格式、构建；正式浏览器验证小数筛选及截图模板。提交并批量推送，原两位评审者核对修复，更新PR描述和实际证据。暂不合并、发布或部署。

步骤1和2无依赖，可按文件边界并行；步骤3由前端负责，避免与步骤1同文件。步骤4在代码冻结后顺序构建，再运行依赖Standalone的检查，避免检查期间重建。

## 验收

- 合法十进制MB精确应用；非法值不提交且保留输入；相等/倒置上下界仍拒绝。
- 停用存储不转失败、不重置预算、不解析诊断字符串；启用后同一任务完成；真实读取失败不被文案里的STORAGE_DISABLED误触发恢复。
- 截图对话框拥有独立标签和提交状态；集合CRUD不携带截图分支；真实标签创建、已有标签选择、错误、会话失效及键盘关闭可用。
- 新增回归在修复前失败，修复后通过；原两位评审者复核，CI与本地结果分别记录。

## 风险和边界

- 领取后停用可能发生于读取或最终写摘要之前，测试需覆盖这些真实边界；永久删除与中断不得被暂停分支覆盖。
- 截图标签创建响应丢失仍保留未知结果提示，避免盲目重复创建。
- 上一轮CI的health/logging两项为2000ms请求超时，其他检查/媒体工具通过。只核查失败范围，不放宽超时、不跳过断言；若属无关运行环境问题，记录事实。
