## 当前交付与原型检查点

原型位于 `prototypes/browser-extension/`，使用隔离 Next.js 页面，端口为 `3176`。紧凑上传小窗入口为 `/`，网页右键收集演示入口为 `/?view=web`；连接、默认配置和主题收进设置视图。日常只显示 Ariso 小标题和设置图标、拖入／粘贴／选择、紧凑列表及上传／复制，移除大标题、全页导航、右侧设置栏和宣传说明卡。

上一轮实际命令、26 项页面检查、4 项文本输出测试和截图保留在[历史原型验证记录](../../prototypes/browser-extension/evidence/verification.md)。紧凑版的实际命令、24 项新版检查、截图和未验证项见[精简版验证](../../prototypes/browser-extension/evidence/compact-verification.md)，没有把旧版通过项当作新版验证。用户对上一轮界面大小的反馈已记录，新版布局和流程仍待体验。

原型应体现“加入图片 → 检查本次设置 → 开始上传 → 复制结果”，并能演示右键收集、来源授权、获取失败、服务器处理、重复、版本不可用和结果未知。它不读取真实 Token、不连接生产 Ariso，也不能证明浏览器扩展权限已经可用。

用户要求先看到原型。当前按已认可简约原型完成正式实现；本轮实际结果及未关闭项已记录。用户已授权首版开发，无需重新询问是否需要开发；本轮不将原型演示当作正式扩展实现或真实上传证据。

## 已核实的实现边界

1. `src/server/identity/tokens.ts` 的 `verifyUploadToken` 当前只接受 `POST /api/upload`。新增能力接口需要显式增加该 GET 路径，不能只移除路径限制。
2. `src/server/upload/public-contract.ts` 已有单文件上传、可见性、相册、标签和版本结果契约。新插件消费这些字段，不导入数据库或管理页面的 Cookie 上传控制器。
3. `src/server/upload/public-result.ts` 等待同一次媒体任务，处理预算为 900 秒。正式上传放在小窗内可持续打开的扩展页面，后台只处理入口和任务转交；具体窗口方式在正式阶段验证，不能假定 action popup 关闭后仍可长上传。
4. `src/server/upload/page-settings.ts` 会返回管理用相册、标签和存储列表，不能直接作为 Token 能力查询的响应。新接口只读上传限制、媒体默认值及默认存储可用状态。
5. 当前工作区存在重复检测改动。实现前核对目标 revision 与这些改动的合入状态；不得假定生产已具备工作区行为。
6. 根 TypeScript 配置目前覆盖仓库内所有 TS/TSX，ESLint 已列出部分独立原型生成目录。引入 WXT 后需要明确独立包和生成目录的检查边界，并让独立包自己的检查成为必需项。

## 方案与责任

| 位置         | 责任与约束                                                                               |
| ------------ | ---------------------------------------------------------------------------------------- |
| Ariso 后台   | 新增 `GET /api/upload/capabilities`；复用上传 Token 与现有设置，不新增表或登录系统       |
| 紧凑小窗     | 约 360px；上传与设置分视图，统一接纳两类输入；由可持续扩展页面运行实际上传               |
| 扩展后台     | 注册图片右键菜单，保存短期来源任务并打开／聚焦同一小窗，不承载长时间 fetch               |
| 上传适配     | 复用 `@uppy/core`／`@uppy/xhr-upload`，每请求一图，并发 3，禁用自动重试                  |
| 来源图片获取 | 从已授权图片域名取得文件，绝不携带 Ariso Token 或读取登录 Cookie；获取失败不记成上传失败 |
| 设置         | 单站点地址和 Token 使用扩展本机存储，仅扩展上下文可读；不上传到同步存储                  |
| 结果         | 依据真实 201／ready 和已存版本生成输出；未知、重复、私有及版本缺失有独立状态             |

独立包位于 `integrations/browser-extension/`，使用 WXT、TypeScript、React，声明自己的依赖，作为根 pnpm workspace 的成员共用根锁文件。2026-10-26 用户确认同仓库三个模块，具体边界见[模块组织](../../docs/guides/modules.md)。依赖版本在实施时依据项目 Node 24 与现有组件版本核对，不凭规划文档推定兼容。

## 接口约定

`GET /api/upload/capabilities` 是新增的受 Token 认证接口。成功响应只包含 `maxFileBytes`、`queueLimit`、`defaultVisibility`、`defaultLinkVersion`、`defaultStorageAvailable` 和 `requestId`。默认存储可用状态表示配置存在且启用，不发起存储写入探测。

错误保留现有公开接口的 `error.code`、`error.stage`、`error.message` 和 `requestId`。缺少、失效、撤销或停用 Token 返回 401，未初始化返回 409；有合法 Token 但没有可用默认存储时，返回真实能力状态。响应 `Cache-Control: no-store`，不返回管理列表、所有者信息和凭据。

`POST /api/upload` 继续接收一个文件，处理完成才返回成功。客户端不开放内部上传会话、公开轮询或新幂等协议。图片源下载、Ariso 上传、服务器处理、链接生成是不同阶段，分别报告结果。

## 验证约定

以下是未来实施要求，不是本轮已运行结果。

- Node 使用项目指定的 24.x，pnpm 使用项目锁定版本。独立扩展脚本尚未创建，任务中以“拟新增”标记。
- Ariso 后台采用现有 Vitest 单元／HTTP 集成夹具；实际完成后按项目指南执行适用的 lint、typecheck、单元、build 和集成检查。
- 扩展本机测试验证设置、来源请求、契约解析、状态转换和复制文本；真实扩展浏览器验收另行执行。
- 长处理用超过 30 秒的真实响应等待场景验证，覆盖小窗失焦、切换浏览器页面、最小化和关闭；不能假定 action popup 关闭后仍继续请求，也不能用后台保活轮询掩盖问题。
- Chrome 加载实际构建产物。只有普通网页或 WXT 构建成功，不足以声明真实扩展通过。
- 原型、正式浏览器界面及设计对照分别记录。以约 360px 小窗为主要设计宽度，补充窄视口、390/430/768、深浅主题和键盘操作的适用检查，不要求改回全页布局；扩展发行仍限桌面浏览器。
- 所有测试使用隔离数据库、文件目录和受控图片来源，不写生产图库。不得使用本机 Docker／Colima；容器检查只在 CI 或用户指定远端执行。
- 每个检查点记录实际命令、环境、revision、通过范围和未验证项，不因前一切片通过而替后续切片打勾。

## 风险与处理

| 情况                   | 用户可见处理与验收                                                         |
| ---------------------- | -------------------------------------------------------------------------- |
| 网页可见但不能直接下载 | 明确显示来源获取失败，保留选择本地文件／粘贴入口；不绕过登录、防盗链或限制 |
| 来源图片与网页不同域   | 根据实际图片域名申请可选权限，覆盖 CDN 与拒绝授权场景                      |
| Token 仅测试时有效     | 每次上传仍由后台验证；撤销后的新请求失败，不回溯取消已接收任务             |
| 上传进度达到 100%      | 改为等待 Ariso 处理；只有真实 ready 才显示完成                             |
| 断网、关闭小窗或取消   | 已接收后的结果可能未知；到图库核对，不自动重发、不声称已删除服务器图片     |
| 完全重复               | 按目标版本的 `UPLOAD_DUPLICATE` 契约显示未新增，不推测或读取旧图链接       |
| 所选版本不存在         | 显示图片已保存及已有版本，由用户显式选择，不静默回退、不重传               |
| 私有上传               | 明确需要登录访问，不提供可匿名使用的承诺                                   |
| 构建产物被根检查扫描   | 明确忽略生成物并接入独立包检查，不用排除源代码来降低质量门槛               |

## 范围纪律

首版不做截图、整页图片扫描、原图规则提取、多站点、图库管理、远端删除、自动编辑器替换、后台剪贴板监听、浏览器关闭后续传或服务器抓图。新增这些能力需要重新确定外部行为和接口范围。

可以在契约确定后分别处理独立扩展界面与后台文档；共享 `lib/ariso-client.ts`、队列状态或入口主页面的任务按依赖顺序串行。不锁整个仓库，不改其他未提交工作，不从当前授权推导生产部署、商店发布或推送授权。
