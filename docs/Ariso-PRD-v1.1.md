# Ariso vNext 产品需求文档（PRD）

- **文档状态**：需求已冻结，可进入 Spec 拆分
- **文档版本**：v1.1
- **日期**：2026-09-11
- **产品形态**：单用户、自托管图床
- **首版部署方式**：Docker

---

## 1. 项目背景

旧版 Ariso 以仿写 Lsky Pro 为起点，逐步加入了多用户、动态权限、用户审批、复杂系统设置等能力。随着功能增加，产品边界、前后端契约、图片处理规则和工程交付方式没有保持一致，导致后续开发成本不断上升。

新版不继续修补旧架构，也不以完整复刻 Lsky Pro 为目标。项目从核心使用场景重新设计：

> 用户在自己的服务器上部署 Ariso，通过网页或通用上传 API 上传图片，获得稳定外链，并在一个清晰的图库中整理、处理、分享和删除图片。

新版将放弃多用户平台思路，收敛为一个站点对应一个所有者的自托管图床。

---

## 2. 产品目标

### 2.1 核心目标

1. 提供简单、稳定的单用户自托管图床。
2. 支持网页上传和通用上传 API，供脚本、自动化工具和第三方客户端接入。
3. 支持本地存储和多个 S3 兼容存储。
4. 对外始终使用 Ariso 域名下的稳定图片链接。
5. 完整保留原图，并按配置生成压缩图、缩略图和水印图。
6. 支持真正的公开图片与私有图片访问控制。
7. 提供可用的图库、相册、标签、分享、回收站和访问统计。
8. 使用单容器完成部署，不要求 PostgreSQL、Redis、独立 Worker 或独立前端服务。

### 2.2 产品原则

- **单用户优先**：不为不存在的多租户场景增加角色、权限和组织结构。
- **原图不可破坏**：图片处理不能覆盖或修改上传原图。
- **链接保持稳定**：重命名、调整相册和重新处理不能改变已有图片地址。
- **行为显式**：版本缺失、处理失败、存储停用和上传中转等情况必须明确展示，不进行隐藏回退。
- **前后端规则一致**：网页上传和通用 API 使用同一套业务规则。
- **减少自研基础设施**：认证、上传队列、图表、拖拽和图片查看优先复用成熟依赖。
- **不做无关扩展**：首版不建设网盘、社区图库、AI 图片平台或复杂运维平台。

---

## 3. 用户与访问角色

### 3.1 站点所有者

Ariso 只有一个所有者。所有者可以：

- 登录管理后台；
- 上传、查看、编辑、下载和删除图片；
- 管理相册和标签；
- 配置本地存储与多个 S3 存储；
- 配置图片处理、SMTP、GitHub OAuth 和上传 API Token；
- 查看基础用量和公开图片访问统计。

### 3.2 匿名访客

匿名访客只能：

- 访问公开图片链接；
- 访问有效的相册分享链接；
- 输入相册分享密码；
- 浏览相册分享页中的公开图片。

匿名访客不能浏览站点全部公开图片，也不能访问私有图片或管理接口。

## 4. 明确不做

首版不包含：

- 多用户、公开注册、邀请注册和用户审批；
- 角色、动态权限和多租户；
- 公开图库或图片广场；
- AI 标签、AI 描述、以图搜图和内容识别；
- 站点备份与恢复功能；
- 操作审计和网页日志中心；
- 对外图库管理 API；
- 官方 PicGo 插件、PicGo 专用适配或可直接复制的 PicGo 配置承诺；
- 单张私有图片临时分享；
- 图片防盗链；
- 图片原图替换；
- 跨存储迁移；
- 旧版 Ariso 数据、账号、配置、相册、标签或图片迁移工具；
- 批量 ZIP 下载；
- 远程图片 URL 导入；
- PWA、离线图库和 Service Worker；
- 子路径部署；
- 非 Docker 部署；
- 多实例和分布式任务消费；
- 数据库自动降级或降级迁移。

## 5. 首次部署与初始化

### 5.1 Docker 部署

首版只提供 Docker 镜像，支持：

```text
linux/amd64
linux/arm64
```

部署时只需要一个 Ariso 容器和一个持久化数据目录，不要求额外部署数据库、Redis、Worker 或独立 Web 服务。

容器基础镜像暂定为 Debian slim 系列，以便统一提供 ImageMagick、ExifTool、字体和图片格式依赖。

### 5.2 数据目录

默认持久化目录：

```text
/data/
├── ariso.db
├── storage/
│   └── default/
└── assets/
    ├── watermarks/
    └── branding/
```

其中：

- `watermarks/` 保存图片水印素材；
- `branding/` 保存 Logo 和 Favicon 等站点品牌素材。

运行日志不写入数据目录，统一输出到 `stdout/stderr`。

### 5.3 初始化流程

首次启动时：

1. 创建数据目录与 SQLite 数据库。
2. 执行数据库迁移。
3. 自动创建默认本地存储 `/data/storage/default`。
4. 在容器终端与运行日志中输出一次性初始化码。
5. 用户打开 `/setup`，输入初始化码。
6. 使用邮箱和密码创建唯一所有者账号。
7. 配置站点公开地址。
8. 根据浏览器时区推荐站点时区，用户确认后保存。
9. 完成初始化，初始化码永久失效，`/setup` 关闭。

初始化未完成时，重启应用会生成新的初始化码，旧码失效。初始化码不能通过公开 HTTP 接口读取。

### 5.4 站点公开地址

初始化必须填写完整公开地址，例如：

```text
https://img.example.com
```

该地址用于生成：

- 图片外链；
- 相册分享链接；
- GitHub OAuth 回调地址；
- 密码重置邮件链接；
- 上传 API 返回地址。

Ariso 只支持部署在域名或子域名根路径，不支持：

```text
https://example.com/ariso/
```

Ariso 自身只监听 HTTP。HTTPS、证书和反向代理由 Nginx、Caddy、Traefik 等外部组件负责。

初始化后允许在后台修改站点公开地址。修改后：

- 图片 ID、图片路径和对象 Key 不改变；
- 新复制和新返回的链接使用新地址；
- Ariso 不自动维护或重定向旧域名；
- 用户需要自行保留旧域名或在反向代理、DNS 层配置跳转；
- 后台提示更新 GitHub OAuth 回调地址；
- 所有 S3 存储的 CORS 状态失效，需要重新检测。

### 5.5 站点时区

- 所有时间在数据库中统一保存为 UTC；
- 站点时区使用 IANA 时区名称，例如 `Asia/Singapore`；
- 初始化时根据浏览器时区提供推荐值；
- 所有者可以在后台修改站点时区；
- “今日”统计、每日趋势、分享有效期和界面时间显示按站点时区计算；
- 修改时区不重写数据库中的历史 UTC 时间。

## 6. 所有者认证

### 6.1 登录方式

支持：

- 本地邮箱和密码登录；
- GitHub OAuth 登录。

不提供公开注册。GitHub 登录必须先由已登录所有者主动绑定，未绑定的 GitHub 账号不能创建账号或进入后台。

本地密码登录始终保留，不能把 GitHub OAuth 作为唯一登录方式。

### 6.2 账号管理

所有者可以：

- 修改登录邮箱；
- 修改本地密码；
- 绑定 GitHub 账号；
- 解绑 GitHub 账号。

规则：

- 修改邮箱后，后续本地登录使用新邮箱；
- 解绑 GitHub 不影响本地邮箱和密码登录；
- GitHub OAuth 被关闭后，GitHub 登录入口不可用；
- 关闭 GitHub OAuth 不自动删除已有绑定关系，重新启用后可以继续使用。

### 6.3 密码找回

支持两种方式：

- 通过 SMTP 发送密码重置邮件；
- 通过容器内 CLI 命令重置密码。

SMTP 未配置或不可用时，CLI 重置仍然可用。

### 6.4 GitHub OAuth 配置

GitHub OAuth 的 `Client ID`、`Client Secret` 和启用状态通过 Web 后台管理。

规则：

- `Client Secret` 加密写入 SQLite；
- 后台不回显完整密钥；
- 保存后提示需要重启容器；
- 重启后新配置生效；
- Ariso 不获取 Docker 控制权限，也不自动重启自身。

### 6.5 上传 API Token

支持创建多个命名 Token，例如：

```text
Mac 上传脚本
Windows 上传工具
Blog CI
临时脚本
```

每个 Token：

- 只能调用通用上传 API；
- 不能登录后台；
- 不能查询、修改或删除图片；
- 创建时完整显示一次；
- 数据库只保存哈希；
- 支持可选有效期，默认永不过期；
- 支持单独启用、停用和撤销。

## 7. Web 上传

### 7.1 添加文件方式

支持：

- 点击选择文件；
- 拖拽文件；
- 粘贴剪贴板中的图片或截图；
- 选择或拖入整个文件夹。

文件夹上传规则：

- 递归扫描所有子目录；
- 只加入支持的图片格式；
- 不保留原目录结构；
- 不自动按照目录创建相册；
- 不支持的文件跳过并汇总提示；
- 同名文件允许上传，不会互相覆盖；
- 空目录不创建记录。

### 7.2 队列限制

默认规则：

| 项目 | 默认值 | 配置方式 |
|---|---:|---|
| 单文件最大尺寸 | 50 MiB | 后台可配置 |
| 单批最大文件数 | 20 | 后台可配置 |
| 队列最大图片数 | 500 | 后台可配置，范围建议 100～2000 |
| 浏览器同时上传数 | 3 | 首版固定 |

文件夹中图片超过单批上限时，全部加入队列，再自动拆分为多个批次上传。

图片解码尺寸、总像素、动画帧数、多页文件页数、处理时长和磁盘空间还受第 11.8 节的运行边界约束。

### 7.3 批次设置

同一批图片统一使用：

- 一个已启用的存储位置；
- 公开或私有状态；
- 一个或多个相册；
- 一个或多个标签。

上传队列不支持逐张设置。需要不同配置时，拆分为不同批次，或上传完成后在图库中修改。

上传页允许快速创建：

- 相册：只填写名称；
- 标签：只填写名称。

相册描述、封面、分享和排序等高级设置在相册管理页面完成。

没有任何已启用存储时：

- 上传按钮不可用；
- 页面显示“没有可用存储，请先启用或创建存储”；

### 7.4 上传启动与取消

- 文件加入队列后不自动上传；
- 用户检查队列并配置批次后，点击“开始上传”；
- 单张图片失败不暂停其他图片；
- 文件传输阶段可以取消；
- 进入服务端图片处理阶段后不能中途取消；
- 刷新或关闭页面后，未完成的浏览器队列不恢复；
- 已经提交到服务端的处理任务继续执行。

### 7.5 上传结果队列

上传结果队列保留成功项和失败项。

成功项提供：

- 复制 URL；
- 复制 Markdown；
- 复制 HTML；
- 打开图片；
- 进入图片详情。

失败项提供：

- 图片 ID；
- 失败步骤与可读错误；
- 查看已经保存成功的版本；
- 进入图片详情；
- 重新处理；
- 移入回收站。

上传成功或失败后立即释放浏览器中的原始 `File` 引用和 Blob URL。存在服务端缩略图时改用服务端缩略图，否则显示状态占位，降低大批量上传时的内存占用。

用户可以执行“清空已完成”。该操作只清除页面结果，不删除图库中的图片。

## 8. S3 Web 直传与通用上传 API

### 8.1 Ariso Web 上传到 S3

Ariso 自己的 Web 页面使用内部预签名直传流程：

```text
创建上传会话
→ 获取 15 分钟有效的预签名上传 URL
→ 浏览器直接上传原图到 S3 临时路径
→ 通知 Ariso 上传完成
→ Ariso 校验对象
→ 固定到正式路径
→ Ariso 读取原图并生成派生版本
→ 图片进入 ready
```

安全规则：

- S3 凭据不进入浏览器；
- 对象 Key 由 Ariso 生成；
- 预签名上传 URL 有效期固定为 15 分钟；
- 临时对象与正式对象使用不同路径；
- Ariso 必须检查对象存在性、文件大小、内容类型与真实图片格式；
- 未完成上传的临时对象由清理任务删除；
- 临时上传清理不影响回收站图片。

### 8.2 S3 CORS

Ariso 不自动修改 Bucket CORS。

后台提供：

- 根据站点公开地址生成 CORS 示例；
- 浏览器直传检测；
- “直传可用／不可用”状态；
- 失败原因；
- 重新检测按钮。

用户负责在 S3 服务商后台配置 CORS。

站点公开地址修改后，所有 S3 存储的浏览器直传检测结果失效，必须重新检测。

### 8.3 CORS 不可用时回退

若某个已启用 S3 存储未通过浏览器直传检测，Web 上传自动改为：

```text
浏览器 → Ariso → S3
```

页面必须明确提示文件正在通过 Ariso 服务器中转。已经开始的上传不会中途切换链路。

CORS 不可用只影响浏览器直传，不等于允许 Bucket 公开读取。S3 存储仍必须满足第 9.3 节的私有访问要求。

### 8.4 通用上传 API

对脚本、自动化工具和第三方客户端提供标准单文件上传 API：

```text
POST /api/upload
Authorization: Bearer <API_KEY>
Content-Type: multipart/form-data
```

支持参数：

- 文件；
- `storageId`；
- 一个或多个 `albumId`；
- 一个或多个标签名称；
- `visibility`。

相册和标签规则：

- 相册必须使用 ID 指定，因为相册名称允许重复；
- 标签使用名称传入；
- 标签名称不区分大小写；
- 已存在标签按名称匹配；
- 不存在的标签自动创建。

存储规则：

- 指定的 `storageId` 必须存在且处于启用状态；
- 未指定 `storageId` 时使用站点默认存储；
- 默认存储不存在、已停用或系统没有任何可用存储时，返回明确错误；
- 通用上传 API 即使目标是 S3，文件也通过 Ariso 服务器写入 S3，不要求调用方实现两阶段预签名协议。

完成语义：

- 每次请求只接受一个文件；
- 请求等待该图片本次应生成的版本处理完成；
- 图片进入 `ready` 后才返回 HTTP 2xx；
- 处理失败时返回非 2xx；
- 失败响应至少包含图片 ID、`failed` 状态、失败步骤和可读错误；
- 失败图片记录、原图和已经成功保存的版本继续保留；
- 不为上传调用方新增图片状态轮询 API。

成功响应包含：

- 图片 ID；
- `ready` 状态；
- 默认外链；
- 实际已生成版本的链接；
- 实际返回版本；
- 处理结果。

正式开放的上传 API 提供 OpenAPI 文档和 `curl` 示例。不开发官方 PicGo 插件，不承诺提供可直接复制的 PicGo 配置，也不开放图片查询、相册管理、删除和站点配置 API。

## 9. 存储管理

### 9.1 存储类型

支持配置多个：

- 本地存储；
- S3 兼容存储。

可以指定一个站点默认存储。Web 上传和通用 API 都可以选择存储；未指定时使用默认存储。

系统允许：

- 默认存储被停用；
- 暂时没有默认存储；
- 所有存储都处于停用状态。

系统不会在默认存储停用后自动切换到其他存储。没有可用存储时，新上传直接失败并显示明确提示。

一张图片的原图、压缩图、缩略图和水印图必须存放在同一个存储配置中。

### 9.2 本地存储

后台只允许配置 `/data/storage` 下的相对路径，例如：

```text
default
disk-2
archive/blog
```

实际路径：

```text
/data/storage/default
/data/storage/disk-2
/data/storage/archive/blog
```

禁止：

- 填写绝对路径；
- 使用 `../` 跳出 `/data/storage`；
- 将图片路径指向应用数据目录之外。

使用其他硬盘时，通过 Docker Volume 挂载到 `/data/storage/<relative-path>`。

### 9.3 S3 存储配置与连接测试

每个 S3 存储至少包含：

- 名称；
- Endpoint；
- Region；
- Bucket；
- Access Key；
- Secret Key；
- Path Prefix；
- Path Style；
- 启用状态。

S3 Bucket 和 Ariso 写入的对象必须默认不可匿名读取。

后台连接测试至少执行：

1. 使用配置凭据写入随机临时对象；
2. 使用配置凭据读取临时对象；
3. 不携带凭据匿名读取同一临时对象；
4. 删除临时对象。

结果规则：

- 写入、鉴权读取或删除失败时，连接测试失败；
- 匿名读取成功时，连接测试失败；
- 未通过连接测试的 S3 存储不能启用；
- 页面明确提示公开 Bucket 无法保证私有图片访问控制。

首版正式验证：

- AWS S3；
- Cloudflare R2；
- MinIO。

其他 S3 兼容服务标记为“可能兼容，未验证”。

### 9.4 存储引用与配置修改限制

只要存储仍被任意 Ariso 记录或任务引用，就视为“存在引用”。引用包括：

- 正常图片；
- 回收站图片；
- `pending`、`processing`、`ready`、`failed`、`deleting` 或 `cleanup_failed` 图片；
- 任意图片版本记录；
- 未完成上传会话；
- 排队中或待重试的图片处理任务；
- 尚未完成的删除或清理任务；
- 仍由 Ariso 管理、但尚未完成清理的存储对象。

存在引用时允许修改：

- 显示名称；
- 启用状态；
- Access Key；
- Secret Key。

存在引用时不允许修改：

- 存储类型；
- Endpoint；
- Region；
- Bucket；
- Path Prefix；
- Path Style；
- 本地相对路径。

需要更换位置时，创建新的存储配置。首版不提供跨存储迁移。

### 9.5 停用存储

任意存储都可以停用，包括当前默认存储。

停用后：

- 不能用于新上传；
- Web 上传的存储选择列表不允许选择该存储；
- 通用上传 API 指定该存储时返回明确错误；
- 该存储中的图片内容读取、预览、外链和下载返回“存储已停用”错误；
- 图片元数据、相册关系、标签、统计和处理记录继续保留；
- 所有者仍可以管理图片记录、移入回收站和执行永久删除；
- 永久删除仍会尝试删除实际存储对象，失败时进入 `cleanup_failed`；
- 重新启用后，原图片 ID 和原链接恢复可用，不生成新链接；
- 系统不会自动改用其他存储，也不会自动迁移图片。

### 9.6 删除存储

存在任何第 9.4 节所述引用时，禁止删除存储配置。

删除前，所有者必须：

1. 手动将该存储中的图片移入回收站；
2. 手动永久删除相关图片；
3. 处理所有 `cleanup_failed` 项；
4. 等待上传会话、处理任务和清理任务全部结束；
5. 确认不存在任何图片版本或存储对象引用。

只有所有引用和实际对象都完成清理后，才允许删除存储配置。若删除的是当前默认存储，默认存储设置同时清空。系统不得通过删除配置留下孤儿图片或孤儿对象。

## 10. 图片资产模型

### 10.1 图片实体

图库中的一条图片记录代表一次上传。内容完全相同的文件再次上传时，也创建新的图片 ID 和独立链接，不进行自动去重。

每张图片包含：

- 唯一图片 ID；
- `originalName`：上传时的完整原始文件名，只读；
- `displayName`：图库显示名称，可修改，初始值为去除最后一个扩展名后的原始文件名；
- 公开或私有状态；
- 存储位置；
- 图片格式、MIME、尺寸和文件大小；
- 动图、多页等类型信息；
- 版本记录；
- 相册关系；
- 标签关系；
- 完整元数据 JSON；
- 处理状态；
- 访问统计。

示例：

```text
originalName = IMG_001.PNG
displayName  = IMG_001
```

修改 `displayName` 不改变图片 ID、对象路径、图片链接、原始文件名、相册、标签或统计。

### 10.2 图片版本

同一张图片最多包含：

| 版本 | 规则 |
|---|---|
| 原图 `original` | 始终保存，保持上传字节不变 |
| 压缩图 `compressed` | 格式适用且压缩开启时生成 |
| 缩略图 `thumbnail` | 生成用于图库和相册预览的静态 WebP |
| 水印图 `watermark` | 格式适用且水印开启时生成 |

图库只展示一条图片记录，不将不同版本显示成多张图片。

### 10.3 原图不可替换

不允许上传新文件覆盖已有图片原图。需要更换内容时重新上传，生成新的图片 ID 和链接。

“重新处理”只能重新生成派生版本，不能修改原图。

## 11. 图片处理

### 11.1 上传成功条件

新上传图片只有在所有“本次应生成”的版本都成功保存后，才进入 `ready` 并视为上传成功。

状态流程：

```text
pending
→ processing
→ ready
```

处理失败：

```text
processing
→ failed
```

规则：

- `pending`、`processing`、`failed` 状态下，公开链接不可访问；
- 这些状态的图片仍显示在所有者图库中；
- 所有者可以查看状态、失败原因以及已经保存成功的版本；
- 原图和成功版本继续保留；
- 可以在原记录上重试处理，无需重新上传；
- 不适用压缩或水印的格式不会因为缺少这些版本被判定失败；
- 元数据读取失败不阻断图片上传完成。

### 11.2 任务队列与设置快照

采用应用内任务队列：

- 任务持久化到 SQLite；
- 与 Next.js 运行在同一个 Node.js 进程；
- 单实例消费；
- 应用重启后重新拾取未完成任务；
- 残留 `processing` 任务在启动后恢复为可重试状态；
- 不使用 Redis、BullMQ 或独立 Worker。

图片处理并发数可配置为 `1～4`，默认 `1`。

创建处理任务时保存本次图片处理配置快照：

- 已提交和已排队任务不受后续设置修改影响；
- 同一批上传使用提交时的配置；
- 自动重试继续使用原任务快照；
- 所有者手动执行“重新处理”时，使用执行当时的最新站点设置，并生成新的任务快照。

临时性错误自动重试一次，例如 S3 网络错误、临时文件错误。格式不支持、图片损坏、资源超限、参数无效等确定性错误不自动重试。

### 11.3 派生图编码与初始默认值

压缩图和水印图共用站点级派生图设置：

- 输出格式：JPEG、WebP 或 AVIF；
- 输出质量；
- 可选最长边限制；
- JPEG 背景色。

首次初始化后的默认值：

```text
压缩：开启
输出格式：WebP
质量：82
最长边限制：关闭
JPEG 背景色：白色
水印：关闭
默认外链版本：compressed
```

最长边限制开启后：

- 超过限制的图片等比例缩小；
- 较小图片不放大。

当输出 JPEG 且原图包含透明区域时，使用配置的背景色合成，严格生成 JPEG，不自动改为 WebP。设置页预览必须展示最终实际效果。

### 11.4 缩略图

缩略图固定规则：

```text
格式：WebP
最长边：640 px
质量：80
不放大小图
保持原始比例
```

等宽网格通过 CSS `object-fit: cover` 进行视觉裁切，瀑布流使用缩略图真实比例。两种布局不分别生成缩略图。

缩略图用于图库、相册分享和预览，不作为特殊格式的默认外链回退版本。

### 11.5 水印

全站只有一套水印配置，文字水印和图片水印二选一。

文字水印支持：

- 水印文字；
- 内置字体选择；
- 相对字号；
- 字体颜色；
- 描边颜色和宽度；
- 不透明度；
- 九宫格位置；
- 边距。

图片水印支持：

- PNG、WebP、SVG 静态素材；
- 最大 5 MiB；
- 保持素材比例；
- 相对图片宽度；
- 不透明度；
- 九宫格位置；
- 边距。

不支持：

- 平铺；
- 旋转；
- 任意 X/Y 坐标；
- 多个水印；
- 动态水印素材；
- 上传自定义字体。

Docker 镜像内置至少一套中文字体和一套拉丁字体。

水印生成顺序：

```text
压缩开启
→ 基于新生成的压缩图生成水印图

压缩关闭
→ 基于原图生成水印图
```

历史遗留的旧压缩图不能在压缩关闭时作为新水印图的来源。

### 11.6 设置预览

图片处理设置页允许上传临时测试图并预览：

- 派生图格式；
- 质量；
- 最长边；
- JPEG 背景色；
- 文字或图片水印。

预览和正式处理必须调用同一套服务端 ImageMagick 逻辑。临时图片和预览结果不进入图库，不长期保存。

### 11.7 重新处理

所有者可以选择：

- 全部派生版本；
- 仅压缩图；
- 仅缩略图；
- 仅水印图。

默认选择全部派生版本。

规则：

- 手动重新处理使用执行时的最新站点设置；
- 压缩关闭时，不能执行“仅压缩图”；
- 水印关闭时，不能执行“仅水印图”；
- 关闭开关只影响是否生成新版本，不删除已有版本；
- 已有压缩图或水印图继续允许访问；
- 新版本先写入临时对象；
- 生成成功后原子切换版本记录并删除旧文件；
- 生成失败时保留旧版本；
- 不保留历史版本，不提供版本回滚；
- 已有 `ready` 图片重新处理期间，旧版本继续提供访问。

### 11.8 图片处理运行边界

除文件大小限制外，首版必须设置不可由 Web 后台修改的运行硬限制，包括：

- 最大宽度；
- 最大高度；
- 最大总像素；
- 最大动画帧数；
- 最大多页文件页数；
- 单次 ImageMagick 处理超时；
- 单次 ExifTool 读取超时；
- 单任务临时文件和磁盘占用边界；
- 接收新上传所需的最低可用磁盘空间。

具体数值在图片处理技术 Spec 中定义。

行为规则：

- 原图保存后发现解码尺寸、帧数、页数或处理时长超限时，图片进入 `failed`；
- 页面显示明确失败原因；
- 不进行无限重试；
- 可用磁盘空间低于阈值时暂停接收新上传，并显示明确错误；
- 首版不在 Web 设置页开放这些高级资源参数。

## 12. 图片格式

### 12.1 支持处理的静态图片

首版目标支持：

- JPEG；
- PNG；
- 静态 WebP；
- 静态 AVIF；
- BMP；
- HEIC／HEIF；
- 单页 TIFF。

处理规则：

- 保留原图；
- 生成缩略图；
- 按设置生成压缩图和水印图。

### 12.2 动图

支持上传：

- 动态 GIF；
- APNG；
- 动态 WebP；
- 动态 AVIF。

处理规则：

- 保留完整动画原图；
- 生成静态预览缩略图；
- 首版不生成压缩图和水印图；
- 默认外链版本不适用时返回原始动画文件，不转换为静态缩略图。

### 12.3 矢量、图标和多页文件

支持：

- SVG；
- ICO；
- 多页 TIFF 或其他多页／多图文件。

处理规则：

- 保留原文件；
- 生成静态或首页预览；
- 不生成压缩图和水印图；
- 默认外链版本不适用时返回原文件，不使用 WebP 预览代替原文件；
- SVG 原图响应仍遵守第 14.9 节的附件下载规则。

### 12.4 格式识别

不能只相信扩展名和浏览器 MIME。服务端使用多层验证：

1. 文件大小限制；
2. 二进制签名识别；
3. XML／SVG 检测；
4. ImageMagick 实际解码；
5. ExifTool 格式、页数、动画和元数据读取。

同时应用第 11.8 节定义的尺寸、总像素、帧数、页数、超时和磁盘边界。

### 12.5 “不适用”与“失败”区分

- 格式按产品规则不生成某个版本：标记为“不适用”；
- 本应生成但处理失败：标记为“失败”；
- 明确请求不存在的版本时，返回“版本不可用”；
- 不用其他版本冒充失败版本；
- 只有在当前默认版本对该格式明确“不适用”时，默认链接才按第 14.6 节返回原文件，并明确实际版本为 `original`。

## 13. EXIF 与图片元数据

### 13.1 原图元数据

原图保持上传时的完整文件内容，包括可能存在的：

- EXIF；
- GPS；
- 相机型号；
- 镜头型号；
- 快门、光圈、ISO、焦距；
- MakerNotes；
- XMP；
- IPTC；
- ICC 等附加信息。

### 13.2 元数据提取

使用 ExifTool 将完整可解析元数据保存为结构化 JSON。保留分组名称，避免同名标签互相覆盖。

数据库不额外保存一份原始 EXIF 二进制，原图本身是完整数据的权威来源。

元数据读取失败时：

- 原图继续保留；
- 图片可以正常完成上传；
- 详情页显示读取失败；
- 支持单独重新读取元数据。

### 13.3 派生版本元数据

- 压缩图：先自动校正方向，再清除 EXIF 等附加信息；
- 缩略图：自动校正方向并清除附加信息；
- 水印图：不保留附加信息。

### 13.4 展示规则

所有者在图片详情页可以查看常用摄影参数和完整元数据列表。

首版不支持按相机、镜头、ISO、GPS 等元数据搜索或筛选。

相册分享页不主动展示 EXIF 或 GPS。

公开图片的原图允许访问，因此明确访问原图的访客可能读取其中的 GPS 和拍摄信息。界面在复制或下载公开原图时应显示提示，但不阻止操作。

## 14. 公开、私有与图片访问

### 14.1 可见性

每张图片支持：

- 公开；
- 私有。

站点初始默认值为公开。Web 和通用 API：

```text
本次上传明确指定
→ 使用本次值

本次上传未指定
→ 使用站点默认值
```

修改站点默认值只影响后续上传，不自动修改已有图片。

### 14.2 私有图片

私有图片的所有版本都必须鉴权，包括：

- 原图；
- 压缩图；
- 缩略图；
- 水印图。

私有图片只能由已登录所有者访问。首版不提供私有图片临时分享，也不允许通过相册分享访问私有图片。

S3 存储必须使用不可匿名读取的 Bucket 和对象，防止访客绕过 Ariso 权限直接访问底层对象。

### 14.3 稳定图片地址

对外始终使用 Ariso 域名：

```text
/i/{imageId}?type=original
/i/{imageId}?type=compressed
/i/{imageId}?type=thumbnail
/i/{imageId}?type=watermark
```

不把本地文件路径、Bucket 地址或永久 S3 对象 URL 作为正式外链。

### 14.4 默认版本

站点默认外链版本只能选择：

- `original`；
- `compressed`；
- `watermark`。

`thumbnail` 不能设置为默认外链，但允许手动访问和复制。

站点初始默认外链版本为 `compressed`。

关闭压缩或水印前，如果该版本当前是默认外链，必须先选择其他有效默认版本。系统不能静默回退。

### 14.5 无 `type` 参数

以下地址合法：

```text
/i/{imageId}
```

它在每次访问时读取当前站点默认版本，并直接返回对应图片，不先重定向到显式版本 URL。

Ariso 自己生成、复制和 API 返回的链接默认显式带 `type`，确保已经发布的内容不会随站点默认设置改变。

### 14.6 默认版本缺失

- 图片格式按产品规则不适用默认版本：返回原文件，并明确实际版本为 `original`；
- 原文件按上传字节返回，不转换为缩略图、WebP 或其他格式；
- 动图返回完整动画原图；
- SVG、ICO 和多页文件返回各自原文件；
- SVG 仍按第 14.9 节作为附件下载；
- 图片本应生成默认版本但处理失败或历史缺失：返回版本不可用，不自动回退；
- 明确指定 `type` 时，目标版本不存在则返回版本不可用，不回退；
- 图片在回收站或未 `ready`：拒绝公开访问；
- 图片为私有：要求所有者登录；
- 图片所属存储已停用：返回存储已停用错误，不回退到其他存储。

### 14.7 本地与 S3 文件传输

本地存储：

```text
访问 Ariso URL
→ 检查图片状态、存储状态与权限
→ 记录统计
→ Node.js 返回本地文件
```

S3 存储：

```text
访问 Ariso URL
→ 检查图片状态、存储状态与权限
→ 记录统计
→ 302 跳转到 5 分钟有效的预签名 S3 URL
→ S3 传输文件
```

S3 文件流量不经过 Ariso 服务器，但浏览器可能看到有效期不超过 5 分钟的 S3 地址。

图片被改为私有、移入回收站或所属存储被停用后，Ariso 不再签发新地址。已经签发的 S3 预签名地址可能在剩余有效期内继续使用，这是 S3 跳转传输模式的明确边界。

### 14.8 缓存

Ariso 图片入口与 S3 跳转响应不做长期缓存。每次新请求都经过 Ariso 状态、存储与权限检查，以确保：

- 公开改私有后，新请求立即生效；
- 移入回收站后，新请求立即停止访问；
- 存储停用后，新请求返回明确错误；
- 重新处理后原链接可以访问新版本；
- 访问统计口径一致。

### 14.9 SVG 原图

SVG 原图只能作为附件下载，不允许作为 Ariso 同源文档直接打开。响应需要包含附件下载和 `nosniff` 等安全头。

图库、相册分享页和大图查看器统一展示生成的 WebP 预览。该预览不作为默认外链版本缺失时的自动回退。

### 14.10 下载

通过：

```text
/i/{imageId}?type=original&download=1
```

下载指定版本。

规则：

- 本地存储返回附件响应；
- S3 使用 5 分钟有效、带下载响应参数的预签名地址；
- 文件名使用安全处理后的 `displayName`；
- 扩展名根据该版本的实际格式生成；
- `displayName` 本身不包含初始扩展名，因此不生成双扩展名；
- 所有者可以逐个下载已有版本；
- 存储停用时下载返回明确错误；
- 首版不提供批量 ZIP 下载。

## 15. 图库

### 15.1 展示方式

支持用户切换：

- 等宽网格；
- 瀑布流。

支持用户切换：

- 分页；
- 加载更多。

两类设置可以任意组合。首次默认：

```text
等宽网格 + 加载更多
```

切换展示方式时不重新请求当前已有数据，不丢失筛选、排序和选择状态。切换加载方式时保留筛选和排序，从第一页重新加载。

展示方式与加载方式作为浏览器本地偏好保存。

### 15.2 每页数量

默认每页／每批加载 40 张，可选：

```text
20
40
80
```

### 15.3 搜索、筛选和排序

支持：

- 搜索 `displayName` 和 `originalName`；
- 按相册筛选；
- 按一个或多个标签筛选；
- 按上传时间范围筛选；
- 按格式筛选；
- 按存储位置筛选；
- 按公开／私有状态筛选；
- 按处理状态筛选；
- 按上传时间排序；
- 按文件大小排序。

筛选条件同步到 URL，刷新、前进、后退和复制链接后可以恢复当前查询。

### 15.4 处理状态与不可用状态

`pending`、`processing`、`failed` 图片仍显示在所有者图库中。

图片卡片和详情页需要明确显示：

- 当前处理状态；
- 失败步骤和可读错误；
- 已经成功保存的版本；
- 存储是否已停用。

失败图片支持：

- 查看错误；
- 查看或下载已经成功保存的版本；
- 重新处理；
- 移入回收站。

存储已停用时，卡片使用“存储已停用”占位，不将无法读取的图片误显示为处理失败。

### 15.5 大图查看

支持：

- 前后切换；
- 缩放和平移；
- 全屏；
- 键盘、鼠标和触摸操作。

下载仍从图片详情页执行，不在大图查看器中增加 Download、Share 或 Slideshow 功能。

### 15.6 选择范围

“全选”只选择当前页或当前已经加载的图片：

- 分页模式：只选中当前页；
- 加载更多模式：只选中当前已经加载的图片；
- 后续新加载的图片默认不自动加入选择；
- 页面明确显示当前选中数量；
- 首版不提供“一次选择全部筛选结果”。

例如：

```text
筛选结果：3000 张
当前已加载：40 张
点击全选：选中 40 张
```

### 15.7 批量操作

支持：

- 加入一个或多个相册；
- 从相册移除；
- 添加、移除标签；
- 设置公开；
- 设置私有；
- 移入回收站；
- 永久删除回收站中的选中图片；
- 批量重新处理。

批量重新处理按图片分别创建任务。某张图片失败不影响其他图片。

### 15.8 批量复制

多选图片后支持批量复制：

- URL；
- Markdown；
- HTML。

规则：

- 按当前图库或相册展示顺序输出；
- 每张图片占一行；
- 一次统一选择一个版本；
- 缺少该版本的图片不自动回退；
- 存储已停用的图片不能复制有效链接；
- 页面列出不可复制项，其余有效项继续复制；
- Markdown 和 HTML 使用各图片 `displayName` 作为默认 `alt`。

## 16. 相册与标签

### 16.1 相册

Ariso 使用相册，不提供文件夹体系。

- 一张图片可以加入多个相册；
- 加入多个相册不会复制图片文件；
- 相册名称允许重复，通过 ID 区分；
- 将图片移出相册不会删除图片。

相册支持排序：

- 加入相册时间，最新／最早；
- 图片上传时间，最新／最早；
- 图片显示名称；
- 手动排序。

手动排序规则：

- 支持鼠标、触摸和键盘拖拽；
- 新图片追加到末尾；
- 同一图片在不同相册中分别保存排序位置；
- 切换其他排序模式不删除手动顺序。

相册封面：

- 可以手动选择相册内图片；
- 未指定时使用当前排序下第一张公开图片；
- 封面变私有、移出相册或进入回收站时，自动回退；
- 没有公开图片时显示默认占位封面；
- 不额外生成封面文件。

### 16.2 标签

- 一张图片可以有多个标签；
- 标签名称不区分大小写；
- `Go`、`go`、`GO` 视为同一个标签；
- 保留首次创建时的显示形式；
- 标签名称不可重复；
- 支持批量添加和移除。

### 16.3 删除相册和标签

删除相册：

- 立即删除，不进入回收站；
- 分享链接立即失效；
- 删除封面、排序和图片关联；
- 不删除图片；
- 不影响图片在其他相册中的关系。

删除标签：

- 立即删除，不进入回收站；
- 从所有图片移除该标签；
- 不删除图片；
- 之后可以重新创建同名标签。

## 17. 相册分享

### 17.1 分享能力

每个相册最多有一个分享链接。

支持：

- 启用和关闭分享；
- 可选密码；
- 可选有效期；
- 延长有效期并重新启用原链接；
- 重新生成 Token，使旧链接永久失效。

修改密码、有效期和启用状态不会改变分享地址。

分享有效期在数据库中保存为 UTC，界面按站点时区设置和显示。

### 17.2 分享内容

分享页只展示相册中的公开图片：

- 私有图片不显示；
- 私有缩略图不显示；
- 图片改为私有后立即从分享页消失；
- 图片进入回收站后立即从分享页消失。

相册分享不会改变图片本身的公开／私有状态。

图片所属存储已停用时，其内容请求按第 9.5 节返回“存储已停用”，不回退到其他存储或版本。

### 17.3 密码授权

密码验证成功后，当前浏览器记住授权 24 小时。

以下情况会使已有授权立即失效：

- 分享关闭；
- 分享过期；
- 修改分享密码；
- 重新生成分享链接。

### 17.4 分享页展示

每个相册可以单独选择：

- 等宽网格；
- 瀑布流。

每个相册可以单独选择：

- 不显示图片信息；
- 显示 `displayName`。

分享页不展示：

- 原始文件名；
- 标签；
- 上传时间；
- 存储位置；
- EXIF 或 GPS；
- 文件大小和技术参数。

分享页不提供“下载原图”按钮。该限制不是额外权限边界：公开图片的原图链接本身仍可能被访问。

## 18. 回收站与永久删除

### 18.1 移入回收站

图片进入回收站后：

- 所有版本链接停止访问；
- 从正常图库和相册分享页移除；
- 文件继续保留并占用空间；
- 不自动清理。

继续保留：

- 相册关系；
- 相册手动排序位置；
- 标签；
- `displayName`；
- 公开／私有状态；
- 图片版本与处理状态；
- 历史访问统计。

即使图片所属存储已停用，所有者仍可以将图片记录移入回收站。

### 18.2 恢复

恢复后：

- 原有图片链接重新使用同一个图片 ID；
- 恢复删除前的公开／私有状态；
- 恢复原相册、标签和排序位置。

若图片所属存储处于启用状态，原链接恢复可用；若存储仍处于停用状态，图片记录恢复，但文件访问继续返回“存储已停用”。

若图片在回收站期间，其相册或标签已被删除，恢复时跳过不存在的关系，不重新创建。

### 18.3 永久删除

永久删除流程：

```text
回收站
→ deleting
→ 删除所有实际存在的版本
→ 全部成功
→ 删除数据库记录与关联
```

存储处于停用状态不阻止永久删除。Ariso 仍使用该存储配置执行对象清理。

若部分存储对象删除失败：

- 图片继续留在回收站；
- 状态变为 `cleanup_failed`；
- 图片链接继续不可访问；
- 已删除成功的版本不恢复；
- 记录仍未清理的对象；
- 临时错误自动重试一次；
- 再失败后允许手动重试；
- 重试必须幂等；
- 只有所有存储对象清理成功后，才删除数据库记录。

存在图片、版本或未完成清理引用时，对应存储配置不能删除。

## 19. 访问统计与基础用量

### 19.1 基础用量

后台展示：

- 图片数量；
- 相册数量；
- 各存储位置中 Ariso 文件占用空间；
- 原图、派生版本和回收站文件占用。

### 19.2 访问统计口径

一次访问计入统计，需要满足：

- 访问的是公开图片；
- 图片状态为 `ready`；
- 图片所属存储处于启用状态；
- 版本存在；
- 请求通过 Ariso 检查；
- Ariso 开始返回本地文件，或成功签发 S3 跳转地址。

计入：

- 原图、压缩图、水印图访问；
- 普通展示；
- `download=1` 下载请求。

不计入：

- 缩略图请求；
- 所有者已登录后的访问；
- 私有图片；
- 处理预览；
- 图片不存在、版本不存在、回收站、存储停用和权限失败请求。

下载不单独统计，与普通访问共用一个访问指标。

S3 统计表示 Ariso 已签发有效访问地址，不表示访客已经完整下载文件。

### 19.3 展示内容

后台展示：

- 今日访问量；
- 累计访问量；
- 最近 7／30／90 天趋势；
- 热门图片排行；
- 各版本访问量；
- 各存储空间占用图表。

不统计地区、设备、独立访客或来源站点。

“今日”和每日趋势按照站点时区分组和展示。

### 19.4 写入与保留

公开图片访问先在内存聚合，再定时批量写入 SQLite，降低高频写入压力。进程异常退出时允许损失少量尚未刷新的统计。

每日明细按站点时区划分日期，并保留 365 天。更早数据合并为累计值，不继续保留逐日明细。

修改站点时区不重写已经保存的历史每日统计记录，修改后的新统计按新时区归档。

| 部分 | 选型 |
|---|---|

### 23.4 API 契约

- Next.js Route Handler 与业务模块共用 Zod Schema；
- 不引入 Fastify、tRPC 或 GraphQL；
- 通用上传 API 从 Zod Schema 生成 OpenAPI；

- 不使用自定义 Next.js Server；
- 不使用 Redis 和独立 Worker；

- 任务创建时保存处理设置快照；
- 容器启动时自动执行版本化 SQL 迁移；
- 迁移失败时容器退出，不启动 Web 服务；
- 只支持数据库向前迁移，不提供自动数据库降级。

## 24. Docker 与发布

### 24.1 镜像

发布到：

```text
ghcr.io/dnslin/ariso-next
```

多架构：

```text
linux/amd64
linux/arm64
```

镜像包含：

- Next.js Standalone 应用；
- Node.js 运行时；
- ImageMagick 7；
- ExifTool；
- 图片格式解码依赖；
- 中文与拉丁水印字体；
- SQLite 迁移文件。

### 24.2 启动配置

环境变量只保存应用启动级配置，例如：

```env
HOST=0.0.0.0
PORT=3000
DATA_DIR=/data
LOG_LEVEL=info
BETTER_AUTH_SECRET=...
ARISO_ENCRYPTION_KEY=...
```

S3、SMTP 和 GitHub OAuth 密钥由 Web 后台管理，并使用 `ARISO_ENCRYPTION_KEY` 加密后写入 SQLite。

`ARISO_ENCRYPTION_KEY` 规则：

- 必须由部署者提供并长期固定保存；
- 缺失、格式无效或无法解密已有敏感配置时，应用启动失败；
- 应用不得自动生成新密钥；
- 应用不得自动清空无法解密的字段；
- 启动日志必须明确提示恢复原密钥或数据备份。

`BETTER_AUTH_SECRET` 改变时：

- 现有登录会话失效；
- 所有者需要重新登录；
- 账号、图片和业务数据不删除。

### 24.3 版本规则

使用语义化版本：

```text
0.x    开发阶段
1.0.0  首个稳定版本
1.0.x  修复
1.x.0  向后兼容功能
```

### 24.4 升级与回滚

- 数据库迁移只支持向前；
- 升级前由部署者停止写入并备份整个 `/data` 目录；
- 数据库完成迁移后，不能只切换回旧镜像继续使用新数据库；
- 回滚必须恢复升级前的 `/data` 备份，再使用旧镜像启动；
- 首版不自动创建升级备份；
- 首版不提供网页备份、自动回滚或数据库降级迁移；
- 迁移失败时容器退出，不启动 Web 服务，并保留明确日志。

### 24.5 仓库与旧版关系

- 新版合并为一个 `dnslin/ariso-next` 仓库；
- `ariso-front` 归档，不继续分别维护；
- 旧代码保留分支或 Tag，仅作为参考；
- 新版从新的工程结构开始，不在旧代码中逐层删除重写；
- vNext 作为全新安装发布；
- 不提供旧版 Ariso 数据、账号、相册、标签、配置或图片迁移工具；
- 旧站点需要保留时，由用户继续独立运行或自行处理数据。

## 26. 首版验收场景

### 26.1 初始化、账号与站点设置

1. 空数据目录启动容器后生成一次性初始化码。
2. 未提供正确初始化码时不能创建所有者。
3. 使用邮箱和密码创建唯一所有者后，不能再次创建用户。
4. 本地邮箱和密码可以登录，并始终保留为可用登录方式。
5. 所有者可以修改邮箱和密码。
6. GitHub OAuth 配置、重启和绑定后可以登录。
7. 未绑定的 GitHub 账号不能进入后台。
8. GitHub OAuth 关闭后入口不可用，但已有绑定关系保留，本地登录不受影响。
9. SMTP 可用时能够发送密码重置邮件。
10. SMTP 不可用时可以通过容器 CLI 重置密码。
11. 初始化时保存公开地址和 IANA 站点时区。
12. 修改公开地址后图片 ID 不变，新链接使用新地址，并提示更新 OAuth 回调与 S3 CORS。

### 26.2 默认本地上传

1. 初始化完成后默认本地存储处于启用状态，无需额外配置即可上传。
2. 初始图片处理配置为压缩开启、WebP、质量 82、最长边关闭、水印关闭。
3. 上传原图保存不变。
4. 根据当前设置生成适用派生版本。
5. 所有应生成版本成功后图片进入 `ready`。
6. 上传结果可复制 URL、Markdown 和 HTML。
7. `displayName` 初始值为不带最后一个扩展名的原始文件名。

### 26.3 通用上传 API

1. Token 只能调用单文件上传 API，不能查询、修改或删除图片。
2. 相册通过 `albumId` 指定。
3. 标签通过名称指定，不区分大小写，不存在时自动创建。
4. API 请求等待本次图片处理完成。
5. 图片进入 `ready` 后返回 HTTP 2xx、图片 ID、实际版本和链接。
6. 处理失败时返回非 2xx，并包含图片 ID、`failed` 状态、失败步骤和错误。
7. 失败记录、原图和成功版本继续保留。
8. 提供 OpenAPI 和 `curl` 示例，不依赖官方 PicGo 插件。

### 26.4 S3 上传、私有性与访问

1. 可以创建多个 S3 存储并测试写入、鉴权读取、匿名读取和删除。
2. 临时对象能够匿名读取时，连接测试失败，存储不能启用。
3. CORS 可用时，Ariso Web 使用 15 分钟有效的预签名地址直传原图。
4. CORS 不可用时，页面明确提示并通过 Ariso 中转。
5. 通用上传 API 始终使用单次 multipart 请求。
6. 对外返回 Ariso 域名链接。
7. 访问 S3 图片时，Ariso 完成检查和统计后跳转到 5 分钟有效的签名 URL。

### 26.5 存储停用与删除

1. 当前默认存储可以停用，系统不自动选择其他存储。
2. 所有存储都停用时，Web 上传显示“没有可用存储”，通用 API 返回明确错误。
3. 停用存储中的图片内容、外链和下载返回“存储已停用”。
4. 重新启用后，原图片 ID 和原链接恢复可用。
5. 停用状态下仍可管理图片记录、移入回收站和永久删除。
6. 存在任何图片、版本、上传会话、处理任务或清理任务引用时，不能删除存储。
7. 存在引用时不能修改 Bucket、Endpoint、Region、Path Prefix、Path Style、本地路径或存储类型。
8. 完成所有图片和对象清理后才能删除存储配置，不产生孤儿图片或孤儿对象。

### 26.6 私有图片

1. 私有图片的原图、压缩图、缩略图和水印图均要求所有者登录。
2. 切换版本参数不能绕过权限。
3. 相册分享不能显示私有图片。
4. 图片由公开改为私有后，Ariso 对新请求立即拒绝。
5. S3 对象不能匿名读取。

### 26.7 图片处理、失败与设置快照

1. 原图保存成功但派生版本失败时，保留原图和成功版本。
2. 图片保持 `failed` 状态，公开链接不可访问。
3. `pending`、`processing`、`failed` 图片在所有者图库可见。
4. 所有者可以查看失败步骤、成功版本并重试。
5. 重试不创建新图片 ID。
6. 自动重试使用原任务设置快照。
7. 排队期间修改设置不影响已经提交的任务。
8. 手动重新处理使用执行时的最新设置。
9. 已有 `ready` 图片重新处理失败时，旧版本继续可用。
10. 超过像素、尺寸、帧数、页数或处理时限时进入 `failed` 并显示明确错误。
11. 磁盘空间低于阈值时停止接收新上传。

### 26.8 特殊格式与版本回退

1. 动图保留完整动画原图，只生成静态预览，不生成压缩图和水印图。
2. SVG、ICO 和多页文件保留原文件，只生成预览，不生成压缩图和水印图。
3. 默认版本对格式不适用时返回原文件字节，并明确实际版本为 `original`。
4. 不使用缩略图或 WebP 预览替代原文件。
5. 明确请求不存在的 `type` 时返回版本不可用，不回退。
6. SVG 原图作为附件下载，不作为同源文档直接打开。

### 26.9 图库与批量操作

1. 图库可以按处理状态筛选。
2. 失败图片可以查看错误、查看成功版本、重试和移入回收站。
3. 存储停用与处理失败使用不同状态提示。
4. 分页模式“全选”只选择当前页。
5. 加载更多模式“全选”只选择当前已加载图片。
6. 后续新加载图片不自动加入选择。
7. 批量重新处理时，单张失败不影响其他图片。

### 26.10 相册分享

1. 一个相册只能存在一个有效分享地址。
2. 密码和有效期可以单独修改。
3. 24 小时验证授权在密码修改、关闭、过期或重新生成链接后失效。
4. 分享页只展示公开图片。
5. 手动排序和封面在分享页正确生效。
6. 分享有效期和界面时间按站点时区显示。

### 26.11 回收站

1. 图片移入回收站后所有链接停止访问。
2. 恢复后继续使用原图片 ID 和原链接。
3. 相册、标签和排序关系恢复。
4. 存储停用时可以恢复记录，但文件访问保持不可用，直到重新启用存储。
5. 回收站不自动清理。
6. 永久删除部分失败时保留数据库记录并允许重试。
7. 存储停用不阻止永久删除对象。

### 26.12 升级与密钥

1. 缺少或使用错误的 `ARISO_ENCRYPTION_KEY` 时应用启动失败，并输出明确错误。
2. 应用不会自动生成新加密密钥，也不会清空无法解密的配置。
3. 修改 `BETTER_AUTH_SECRET` 后现有会话失效，但账号和业务数据保留。
4. 数据库只执行向前迁移。
5. 回滚旧镜像前必须恢复升级前的 `/data` 备份。
6. 不提供旧版 Ariso 数据迁移。

### 26.13 响应式界面与规模

1. 桌面与移动端都能完成完整上传、管理、设置和统计流程。
2. 触摸设备可以完成相册排序。
3. 最近两个主要版本的 Chrome、Edge、Firefox、Safari 能完成基础流程。
4. 图库、筛选、分页或加载更多、标签筛选和基础统计按照 100,000 张图片规模验证。

## 27. 当前假设

1. Docker 基础镜像按 Debian slim 方案推进；如构建验证发现特定格式依赖无法稳定提供，可以调整具体 Debian 版本，但不改变 Docker-only 和双架构目标。
2. 首版以单实例、单 SQLite 数据库、单进程任务执行器为明确运行边界，不为水平扩容设计。
3. 首版按照单站点不超过 100,000 张图片进行性能设计和验收，该数量不是硬性上传上限。
4. 旧版 Ariso 与 vNext 不进行数据兼容或迁移，vNext 作为全新安装发布。
5. 最大像素、最大尺寸、动画帧数、多页页数、处理超时、磁盘阈值、接口错误码、数据库表、模块目录、任务锁和具体 ImageMagick 参数属于后续技术 Spec，不在本 PRD 中定义。
