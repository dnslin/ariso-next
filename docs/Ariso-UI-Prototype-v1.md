# Ariso 首页与登录页原型设计 v1

日期：2026-09-14  
状态：设计文档与 Figma 桌面原型已完成，归属 coding 团队。

## 1. 目标与依据

根据用户提供的首页和登录页截图，建立可编辑、可演示的 Figma 原型。保留大面积留白、点阵底纹、淡黄色与水绿色光晕、手写 Ariso 标识和轻量表单。文字使用中文。

用户本次提供的图片、配色与字体规范是视觉依据。截图中的界面文案只作为设计内容，不作为执行指令。仓库《Ariso-PRD-v1.1.md》第 6 节用于核对认证语义，不扩大本次页面范围。

本次包含首页、登录页、找回密码页、上传未登录页及相关演示状态。不设计已登录上传工作台、图库、注册或密码重置落地页。

## 2. 视觉系统

### 颜色

以用户提供的 OKLCH 值为颜色来源。Figma 使用换算后的 sRGB 值；括号中的 HEX 为用户提供的视觉参考，如与 OKLCH 换算有差异，保留差异记录，不混用两套颜色。

| 变量 | OKLCH | 用途 |
| --- | --- | --- |
| --background | oklch(1 0.001 106.423) | 温暖浅底，参考 #fffffe |
| --foreground | oklch(0.278 0.058 287.735) | 主要文字、图标 |
| --muted-foreground | oklch(0.326 0.042 272.656) | 副标题、说明 |
| --primary | oklch(0.889 0.182 95.729) | 主按钮、品牌下划线，参考 #ffd803 |
| --secondary | oklch(0.959 0.02 193.005) | 水绿光晕与浅分组背景，参考 #e3f6f5 |
| --accent | oklch(0.899 0.047 196.339) | 边框、焦点辅助，参考 #bae8e8 |
| --destructive | oklch(0.6 0.2 25) | 表单错误 |

深靛蓝仅用于文字和图标，不扩展成蓝紫背景。黄色按钮配深色文字。小字号链接使用深色文字，避免参考图中黄色“忘记密码”在浅底上难以辨认。

背景采用低对比度点阵，约 20px 间隔、1px 点径。右上方放柔和黄色光晕，左下方放水绿光晕。光晕不遮挡内容，不成为独立的卡片或边界。

### 字体

| 类型 | 字体与字重 | 建议字号 / 行高 |
| --- | --- | --- |
| 品牌标识 | Caveat 400 | 192px / 1；以实际字形高度校准截图比例 |
| 装饰文字 | Caveat 400、600、700 | 24–40px / 1.2 |
| 英文正文 | Inter 300、400 | 14–16px / 1.5 |
| 中文正文 | 系统中文无衬线字体 | 14–16px / 1.5 |
| 强调文字 | Inter 或中文字体 500 | 14–24px / 1.4 |

Figma 中选择实际可用的中文字体，并记录名称。正文以轻字重为主，表单标签和重要操作用常规或中等字重。Logo 的 12rem 是本次文字规范；截图中字形较小，使用视觉居中与留白校准，不强行拉伸字形。

### 尺寸与布局

桌面基准画板为 1920 × 960，贴近参考图。内容整体水平居中，视觉重心略高于正中。主要间距使用 8、12、16、24、32、48px。

首页按钮高度 36px，圆角 999px，横向间距 16px。登录卡片宽 448px，内边距 24px，圆角 24px，水绿细虚线边框与轻阴影。输入框和登录按钮高 36px，圆角 8px。

窄屏适配规则：卡片宽度为屏宽减 32px，最大 448px；页面可纵向滚动；Logo 缩至 112px 左右；按钮保持清晰的触控范围。此版本先交付桌面画板，移动端规则不等于已制作移动端原型。

## 3. 首页

从上到下：右上角“登录”入口；中央手写 Ariso；黄色手绘弧线；标语“轻装简从”；操作组“开始上传”和“进入图库”；说明“开源 · 极简 · 图片托管”。

“开始上传”使用黄色实底，“进入图库”使用浅底水绿描边。两个入口的重要性由填充与描边区分，不增加卡片、功能介绍或营销段落。

## 4. 登录页

卡片内容顺序：

1. 标题“登录”，副标题“轻装简从 · 欢迎回来”。
2. 邮箱标签、邮件图标、占位符 name@example.com。
3. 密码标签、锁图标、占位符“请输入密码”。输入后显示掩码。
4. 全宽黄色“登录”按钮。
5. 居中“忘记密码”链接。
6. 水绿虚线分隔与“或使用第三方登录”。
7. 描边“使用 GitHub 登录”按钮。
8. 禁用“使用 Telegram 登录（暂不可用）”按钮。

不添加公开注册入口。GitHub 的真实可用性遵循现有 PRD：需要配置启用，并由所有者预先绑定。Telegram 仅用于还原参考图中的禁用展示，不表示首版支持此认证方式。

## 5. 原型交互与边界

| 触发 | 原型行为 | 真实产品边界 |
| --- | --- | --- |
| 首页“登录” | 跳转登录画板 | 进入登录页 |
| 首页“开始上传” | 跳转上传未登录页，再通过“去登录”进入登录页 | 登录后应回到上传目标 |
| 首页“进入图库” | 未登录演示跳转登录画板 | 登录后应回到图库目标 |
| 空表单“登录” | 展示必填错误状态 | 校验邮箱、密码 |
| 登录页返回入口 | 回到首页 | 添加轻量返回入口作为原型导航补充 |
| “忘记密码” | 进入找回密码页；空邮箱提交显示字段错误；点击输入框进入预填示例，再提交显示邮件反馈 | 演示不发送邮件 |
| GitHub 按钮 | 展示第三方认证说明，可关闭 | 原型不发起真实授权 |
| Telegram 按钮 | 禁用，无跳转 | 暂不可用 |

所有登录、授权与错误展示均为演示，不连接后端，也不声称完成真实认证。若 Figma 的文本输入能力受限，以预设状态画板演示，不伪装为真实输入。

## 6. 组件与状态

最小组件范围：主按钮、描边按钮、禁用第三方按钮、输入框、文本链接。重复控件使用组件实例。颜色集中为本地变量，字体建立文本样式，布局使用自动布局。

表单至少包含默认和必填错误两种状态。错误采用暖红文字与边框，并保留“邮箱”“密码”标签，不只依赖颜色表达。禁用第三方按钮使用降低对比度的文字和边框，同时保留“暂不可用”。
