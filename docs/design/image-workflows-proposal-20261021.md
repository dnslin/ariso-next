## 1. 建议结论

四项都可行，不需要拆出图片微服务或重做图库。建议使用现有图片身份、候选版本发布、Local/S3 读写和公共界面组件。新增 ZIP 能力、私有单图授权和尺寸产物索引。

| 需求                 | 推荐首版                                      | 可行性 / 成本     | 主要难点                                         |
| -------------------- | --------------------------------------------- | ----------------- | ------------------------------------------------ |
| 批量打包下载         | 所有者选图，固定版本，服务端流式 ZIP          | 中等，约 3–5 人日 | 原生浏览器下载衔接、读取失败、取消和大文件       |
| 替换图片并保留外链   | 保留 imageId，新原图及派生一起发布            | 中高，约 5–8 人日 | 新旧对象原子切换、已有版本可重建、失败不改变旧图 |
| 单张私有图片临时分享 | 独立有期限查看页，图片保持私有                | 中等，约 4–6 人日 | 页内文件权限、S3 撤销时效、回收与替换            |
| 多尺寸图片预设       | 固定 640 / 1280 / 1920 最长边，按需生成后复制 | 中等，约 4–6 人日 | 新尺寸索引、生成队列、版本变化后保留尺寸链接     |

估算包括相关自动检查和本地浏览器验证，不含用户评审等待、发布部署及额外需求。合计约 16–25 人日，只是规划估算。可以分项交付，不必等四项一起上线。

## 2. 能力边界与顺序建议

沿用现有模块 ID，不为这四项另建一套模块体系。

| 需求标识            | 主要责任                                          | 使用的既有模块                              |
| ------------------- | ------------------------------------------------- | ------------------------------------------- |
| archive-download    | `library` 管理选图与反馈，`delivery` 生成下载响应 | `identity`、`media`、`storage`              |
| image-replacement   | `upload` 接收新文件，`media` 准备并发布内容       | `library`、`delivery`、`sharing`、`storage` |
| private-image-share | `sharing` 管理期限与授权，`delivery` 提供受限文件 | `identity`、`media`、`storage`、`library`   |
| image-size-presets  | `media` 生成尺寸产物，`delivery` 解析并读取       | `library`、`storage`                        |

先验证两个具体技术问题：ZIP 的原生下载与中断；替换是否能重建全部已有固定版本。建议交付顺序：**批量下载 → 私有单图分享 → 替换图片 → 尺寸外链**。前两项可独立交付；尺寸外链应建立在明确的内容发布与失效规则上。

用户已批准四项一并实施。以上顺序用于内部交付，适用规则同步到对应 SPEC；不表示已发布或已完成人工验收。

## 4. 批量打包下载

### 用户流程

用户后续批准A方案，覆盖首轮预检查弹窗：图库或相册跨页选图 → 点击操作栏“打包下载”图标展开版本菜单，或右键“打包下载”展开版本子菜单 → 选择原图 / 压缩图 / 缩略图 / 水印图 → 自动准备并发起原生ZIP下载。

- 选中图片后，既有批量快捷操作栏增加“打包下载”纯图标按钮，保留可访问名称。手机提供至少44px点击区，不依赖右键。
- 两个入口复用同一版本菜单与下载动作；保留其他已有菜单项。菜单关闭后焦点沿用HeroUI及现有右键来源恢复。
- 沿用现有图库右键选择约定：右键已选图片或图库空白时操作当前选集；右键未选图片时先仅选中该图再打开菜单；没有选集时在空白处右键保留系统菜单。菜单键和 Shift+F10 沿用相同规则，不为下载另设选择行为。
- 首版仅所有者使用，允许下载自己的公开和私有图片。匿名分享的批量下载不在本需求中。
- 菜单列出四个固定版本，不提供随站点设置变化的“默认版本”，不生成缺失版本。点选时固定选集与版本。
- 正常界面只有版本选项，不显示文件列表、大小/数量摘要或二次确认。准备中使用既有按钮pending，不展示虚构百分比。
- 发现未生成版本、已回收、存储停用或不可读文件时，本次不启动下载，以简短Toast保留实际原因。用户可换版本或调整图库选择，不静默漏图，不再提供弹窗内排除步骤。
- ZIP 文件名建议 `Ariso-20261021-143000.zip`。包内使用显示名称和真实格式扩展名，同名追加 ` (2)` 等序号，保留中文，不生成目录穿越路径。
- 私有性不变；正常下载菜单不增加私有、GPS或同名处理说明。

### 技术方案

复用选图核对和对象读取，使用成熟 ZIP 库逐个向响应写入；图片用 STORE 模式，即只打包、不重复压缩已压缩的媒体。设计时依赖没有 ZIP 库，正式实施采用 `zip-stream@7.0.5`，沿用 Archiver 的底层 ZIP 流库，使用 STORE、逐项输入与主动取消。直接依赖该库避免引入未使用的 glob 依赖。

为避免长 ID 列表塞入 URL、或浏览器缓冲整个 ZIP，建议两步协议：

1. 所有者 POST 创建短期下载清单，提交 ID 和固定版本；全部可读时仅返回本次下载地址，不可用时返回错误，不创建部分清单。
2. 浏览器 GET 该地址，重新验证登录与当前可读状态后开始 ZIP 流。

清单只保存输入，不保存 ZIP 文件。单进程内存记录即可，建议 10 分钟过期，重启后提示重新准备。下载地址本身不授予匿名权限。清单不会锁定内容快照；点击开始时解析当时已发布的版本。若流中源对象随后被替换清理而读取失败，整次下载失败，不混称成功。

首版建议单次至多 200 张，沿用现有单次检查规模；这是新下载动作的建议范围，不是图库已有选择限制。字节上限、超时和并发值先做真实文件基准，再确定是否有必要设限，不把猜测写成容量保证。

- 接收由浏览器下载列表呈现，不增加成功确认页，不宣称已经下载完成。
- 选版本前关闭菜单不发请求；选定后的准备随来源查询改变或页面卸载取消。开始后在浏览器下载列表取消，服务器随连接取消停止ZIP与当前对象流。
- 中途读取失败要中断响应并保留诊断，不能追加一个缺图但成功的 ZIP。原生下载失败信息可能只由浏览器呈现，这是本方案的明确限制。
- 不计入公开外链访问量。不建立导出历史、后台任务中心、断点续传或临时 ZIP 文件库。

### 可观察的验收

- 公开/私有、Local/S3 混合下载，解包文件数、内容与清单一致；中文、同名、特殊字符不冲突。
- 跨页选择正确；存在失败项时无下载，改版本或在图库调整选择后可重新发起。
- 操作栏图标展开版本菜单，右键文字项展开同一组版本子菜单；右键和键盘菜单遵守既有选择约定。手机可通过至少44px的图标按钮进入，可访问名称与关闭回焦正确。
- 200 项及代表性大文件测 CPU、峰值内存、首字节、总时间和取消释放；结果包含硬件与输入规模。
- 获取地址后退出登录、回收图片、停用存储、源文件丢失，都正确拒绝或中断。
- 移动浏览器实际承接下载；页面不把发起响应当作完成。

## 5. 替换图片并保留外链

### 保留与更新

保留 `imageId`、外链地址、显示名称、公开性、相册、标签、创建时间和统计身份。更新原文件名、真实格式、尺寸、字节数、拍摄元数据及处理结果；补充内容更新时间。同一统计身份继续累计，不另做历史内容统计拆分。

“保留外链”覆盖默认链接、已经存在的固定版本链接，以及未来已发布的尺寸链接。其访问权限沿用图片当前公开性。

### 用户流程

详情“更多 → 替换图片” → 系统选择一张新图片 → 立即上传并准备已有派生版本及尺寸 → 全部成功后一起切换。取消文件选择不发请求。

全程保留原详情，不建立独立替换页，不提供新旧对比、再次确认或大段正常说明。上传和处理只显示简短真实状态；关闭详情不取消已选定上传，图库沿用既有活动任务。实际失败在原详情显示原因并允许重新选图。来源筛选、选择、滚动与队列保持。

所有准备完成前，原详情与已有链接仍读取完整旧图；任一失败保持全部旧内容。成功后不提供历史恢复，不建立版本历史或回滚界面。该后续指令覆盖首轮复杂替换原型。

### 发布与格式规则

1. 使用原图片所属存储。写入新对象 Key，不覆盖已在读取的旧文件，也不顺带迁移存储。
2. 复用现有接收、真实格式识别、处理快照和任务资源约束。一个图片有内容任务时，不再受理第二个替换/重处理；不同图片继续独立运行。
3. 先准备新原图、缩略图、全部已存在固定派生、已发布尺寸和新元数据。在准备期间，外链和详情仍读取完整旧内容。
4. 一次短数据库事务发布所有新引用和图片事实，同时撤销旧临时分享。成功后沿现有清理责任回收旧对象；失败维持全部旧引用。
5. 不能照搬“关闭某版本就保留旧文件”的重处理行为，否则原图已变而水印图仍是旧内容。
6. 已公布的压缩/水印版本使用其可追溯处理快照重新生成，不因站点现在关闭该功能而丢失。若现记录不能恢复必要水印资产或参数，提交前阻止替换，解释具体版本；不猜配置、不加原图回退。
7. 首版只接受能够生成全部已有版本的新文件。静态换静态是主要路径。若静态换动画/SVG 不能产生旧 compressed/watermark，提示改用静态文件，或上传为新图片。仅有原图/缩略图的图片可按实际格式能力判断，不一概拒绝所有动画。
8. 发布前再核对回收、删除、存储与任务状态，防止内容写入已结束生命周期的图片。复用现有对象引用与清理规则，不增加全库锁。

当前处理流程会较早更新图片事实与元数据，因此必须把替换的这些写入移至候选结果及最终发布阶段。

已核实，历史参数可沿 `media_versions → media_objects.jobId → media_jobs.snapshot` 追溯；但现有水印素材只保留设置、活动任务、预览和上传引用，成功的历史任务不会永久保留素材。替换需要增加“当前已发布水印版本对其所需素材的引用保留”，这是为了能重建当前公开内容的具体改造。历史素材已经缺失时，按前述规则阻止该图替换。证据：[`watermark-assets.ts:192`](../../src/server/media/watermark-assets.ts#L192)、[`watermark-assets.test.ts:268`](../../tests/integration/media/watermark-assets.test.ts#L268)。

### 缓存边界

现有 `/i` 使用 `private, no-store, no-transform`，ETag 随对象 ID 变化。通过 Ariso 正常新请求可取得替换后的内容，不需要先新建 CDN 清理模块。

已经发出的 S3 签名可在原有 300 秒窗口内使用；旧对象清理后该对象不再可取。第三方自行缓存、已经显示或下载的字节不能被 Ariso 追回。方案不承诺所有外站的旧画面瞬时消失。

### 可观察的验收

- 准备中逐个读取原图、固定版和尺寸版，始终是旧内容；成功后全部为新内容，URL 不变。
- 上传、解码、某一派生、元数据、发布事务和存储写入分别失败，旧图完整可读且无新旧混搭。
- 已存在版本在当前开关关闭后仍正确处理；无法重建时阻止提交。
- 替换与重处理、回收、清理、存储停用竞争时无引用错乱或对象泄漏；有内容任务时给出可理解原因。
- 相册、标签、公开性、创建时间及统计连续；旧临时分享在成功发布时失效，失败时保持有效。

## 6. 单张私有图片临时分享

### 用户流程与内容

私有图片详情“临时分享” → 核对实际分享版本 → 选择有效期 → 创建地址 → 复制或预览访客页面 → 可随时撤销。

- 建议期限 1 小时 / 24 小时 / 7 天，默认 24 小时，不提供永久。
- 每图至多一条当前分享；已有有效分享时展示现有地址、剩余时间和撤销入口，不因反复打开界面而创建多条。
- 首版分享一个明确的浏览器可看版本。优先已生成压缩图；若格式只能使用原图或缩略图，创建前明确展示实际版本，沿现有预览规则决定。没有可读预览时不能创建。
- 创建时保存所选版本角色，后续不能被访客改参数切为原图。普通重处理若改变了画面，分享会读取该角色的新发布内容；此点在管理界面说明。原图替换则撤销分享。
- 使用原图时明确原文件可能包含 GPS / 拍摄信息。匿名页面不展示名称、相册、标签、拍摄参数或后台地址；页内文件可能保留的元数据不能靠隐藏界面消除。
- 图片继续私有，普通 `/i/{id}` 仍拒绝匿名访问。临时查看页不等于防保存：访客能保存已经到达浏览器的图片。
- 当前分享可在图片详情管理；现有分享管理页增加图片类型的精简列表，使用相同创建/撤销能力，不建第二套管理系统。原型重点演示详情入口与访客页，管理列表是正式实施补充范围。

### 最小授权方案

增加单图分享记录 `image_shares`：imageId、随机 token、分享版本、expiresAt、revokedAt、createdAt。每图一条当前记录；重新创建更换 token，旧地址永久无效。现有相册分享表不改成泛型资源平台。

以下路由均是拟议的新协议，当前不存在：

- 所有者 `GET/POST/DELETE /api/images/{imageId}/share`：读取当前、创建、撤销。
- 匿名 `/s/image/{token}`：单张查看页。
- 匿名 `/s/image/{token}/media`：只读取该 token 选定的图片与版本，不接受任意 imageId 或版本升级。

本地与 S3 都由 Ariso 流式转发页内图片，每次 GET/HEAD 检查 token、到期、撤销、回收、删除、存储状态及可读版本。复用现有取消与背压。不能向访客跳转到能独立继续访问 300 秒的 S3 签名地址。

页与资源统一 `private, no-store`，复用现有分享的 noindex / no-referrer。到期判断不依赖定时清理；已经开始的请求和已发出字节无法追回。若有异步存储准备，在准备结束、发送响应前复核授权。

不增加密码、限次访问、禁右键、防截图、访客统计或“禁止下载”开关。私有分享不混入现有公开外链统计。

### 生命周期

| 事件                         | 旧临时地址                                                 |
| ---------------------------- | ---------------------------------------------------------- |
| 到期、主动撤销               | 永久失效                                                   |
| 重新创建分享                 | 生成新 token，旧地址不恢复                                 |
| 替换图片成功                 | 同次发布撤销，失败不撤销                                   |
| 普通重处理                   | 继续有效，读取创建时所选角色的新版本；若角色不可读则不可用 |
| 回收、永久删除、图片改为公开 | 撤销；恢复或再次改私有不复活                               |
| 存储停用                     | 暂不可读；恢复后仅在仍有效且未撤销时继续                   |
| 分享已到期时存储恢复         | 仍然失效                                                   |

“改为公开时撤销”避免临时入口在随后再次改私有后意外恢复；公开期间普通外链按既有公开规则访问。

### 可观察的验收

- 独立匿名会话可看有效分享，普通私有 `/i`、其他图片、管理 API 仍拒绝。
- GET/HEAD 在恰好到期时拒绝；撤销后重新请求立即失败，S3 无可绕过的签名跳转。
- 重新创建、替换、回收/恢复、公开/私有变化及存储停用/恢复遵守上表。
- 页面、RSC、无效页和错误响应不夹带后台字段；原图元数据风险按实际字节说明。
- 复制失败提供完整手动文本；创建或撤销响应不明时先读取当前记录，不盲目重发。

## 7. 多尺寸图片预设

### 用户流程

保留现有默认、原图、压缩图、缩略图、水印图复制入口，仅对压缩图和水印图增加尺寸选择。已有“复制图片链接”增加尺寸选择。选择压缩图或水印图 → 选择尺寸 → 查看实际输出宽高 → 首次点击“生成尺寸图片” → 完成后复制 URL / Markdown / HTML。已生成的尺寸直接复制。

建议首版只提供“当前版本尺寸 / 小图 640 / 中图 1280 / 大图 1920”。后三项指最长边，不保证宽度等于该数字。等比缩小、不裁剪、不放大。

- 例如 900×600 选大图，实际仍为 900×600；竖图按最长边处理。
- 基于已发布的选定版本派生，最大不超过该版本的尺寸。若压缩图已限制为 1024，1920 预设最多仍是 1024。
- 原图保持原字节，尺寸固定为原始尺寸；提示选择压缩图/水印图以指定尺寸。不能把缩放后文件继续称作原图。
- 水印尺寸由已经加水印的版本缩小，不能换用无水印原图；透明度、方向和已有颜色处理应保持正确。
- 未生成、处理中、失败、已就绪分开表达；生成失败不改变剪贴板，不复制一个尚不存在的链接。
- 私有图片的尺寸链接仍需所有者登录，不顺带获得临时分享权限。
- 首版只在单张详情复制提供，批量复制多尺寸、尺寸 ZIP、srcset、任意裁剪、任意宽高及全站自定义预设管理不纳入。

### 数据与交付

现有 `media_versions` 每图每类一条，不能塞下多套尺寸；`mediaPreviews` 会过期，也不适合作为长期外链文件。

新增专用尺寸索引，至少保存 imageId、sourceVersion、preset、sourceObjectId、objectId、实际格式/宽高/字节及状态。对象继续纳入现有存储引用、占用统计和清理，不另建对象仓库。必须把尺寸索引接入对象发布引用判定、存储引用查询、占用统计和永久删除：当前 [`objects.ts:96`](../../src/server/media/objects.ts#L96) 的 `markUnpublishedMediaObjects()` 只检查 `media_versions`，仅新增尺寸表会让已发布尺寸误入清理。相同源对象和预设重复请求复用同一个生成结果；对不同预设恰好产生相同实际尺寸，可以先允许独立结果，不为此设计跨图内容去重系统。

拟议地址：`/i/{imageId}?type=compressed&preset=medium`。`preset` 为新的受支持参数，当前实现忽略未知参数，不会缩图。`preset` 仅允许搭配显式 `type=compressed|watermark`；省略 type、与 original/thumbnail 组合或重复 preset 都返回 400。未知 preset 应返回明确参数错误，不能假装生效；不存在的已知尺寸返回明确未就绪结果，不回落原图。

由所有者触发生成，复用现有处理工作器及 Local/S3 临时下载、产物上传和任务资源管理。现有 job kind 只有 process/metadata，正式实施需增加尺寸任务种类和参数，不是只加前端下拉框。匿名 GET/HEAD 只读已发布产物，不运行任意实时变换。

### 与替换、重处理的组合

已发布尺寸链接也属于稳定外链。替换或源版本重处理后，先重建该源角色已公布的尺寸，再与新基础版本一起发布，旧尺寸随旧对象清理。未公布的尺寸不要求提前生成。

首次尺寸生成与源版本发布并发时，以预期 sourceObjectId 判断结果是否仍对应当前源；过时结果不覆盖新源，用户重新准备即可。使用现有对象/任务约束，不增加全库锁。

动画 GIF/APNG/WebP/AVIF、SVG、ICO、多页容器沿现有 static 分类边界禁用尺寸功能并说明原因，不静默取第一帧。HEIC/TIFF 仅在当前链识别为 static 且已有工具能处理时开放，真实样本仍需验证。

成本是额外长期存储、首次解码和 S3 读取/写入。按需生成避免每次上传固定生成三套。既有缓存策略继续使用，不额外引入 CDN。

### 可观察的验收

- 横竖、小图、透明 PNG、方向照片的实际尺寸、比例、方向和透明度正确；无放大或裁剪。
- 水印仍在、原图仍为原字节；特殊格式准确禁用，不能丢动画。
- 重复请求复用、失败重试、复制三种格式与手动复制均正确。
- Local/S3 生成、访问、存储用量、回收、删除清理完整；HEAD 不触发处理或计数。
- 重处理/替换后旧尺寸 URL 指向新内容，不悬空、不持续返回旧图片。

## 11. 官方参考与采用理由

查阅日期：2026-10-21。参考产品的交互与底层库能力，不移植其整套产品范围。

- [Immich 公共分享](https://docs.immich.app/features/sharing/)：所选照片可创建随机分享地址并配置期限。用于支持单张内容也可独立分享的产品方向。
- [Cloudflare 预定义尺寸](https://developers.cloudflare.com/images/optimization/hosted-images/create-variants/)：使用命名尺寸、按比例缩放且可选择不放大。用于支持固定少量预设，而非任意变换编辑器。
- [Cloudinary 命名变换](https://cloudinary.com/documentation/named_transformations)：可复用已命名参数。用于明确可读尺寸标识，不要求引入其服务。
- [Cloudinary 资产替换](https://cloudinary.com/documentation/upload_parameters#replacing_existing_assets)：资产覆盖与已缓存内容需要分别考虑。用于明确稳定身份与外部缓存的边界。
- [Archiver API](https://www.archiverjs.com/docs/archiver/)：可追加输入流、使用 STORE 和终止打包。其 abort 不会自行排空所有输入流，因此实现仍需主动取消当前对象读取。

这些资料支持方案模式，不证明 Ariso 新功能已实现或已通过测试。
