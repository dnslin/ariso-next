# 设计交付规范

本文件汇总仍有效的设计约定。业务规则以 [PRD](../product/Ariso-PRD-v1.1.md) 和 [SPEC](../product/CAPABILITY-MAP.md) 为准；原型中的照片、名称、数量、预填值、计时跳转及成功反馈是示例。主页面和补充状态均需按真实数据实现。

## 前端实现约束

1. **图标来源固定。** 界面图标必须使用 Lucide（`lucide-react`）或 `@gravity-ui/icons`，优先复用项目已安装的图标库，不自行绘制或复制 SVG 来替代库中图标。
2. **能用 Tailwind CSS 就必须使用。** 布局、间距、尺寸、颜色、圆角、响应式和状态样式优先直接使用 Tailwind CSS，尽量避免新增页面或组件 CSS 文件。确有 Tailwind 无法满足的场景时，说明原因后使用必要的局部 CSS。全局 CSS 不受此文件限制，可维护主题变量、字体、基础样式和全局规则。
3. **尽量复用 HeroUI。** 通用控件优先使用 HeroUI，业务界面优先组合现有组件。只有核对现有组件的 API、类型和组合能力后，确认无法满足必要场景，才自定义组件，并记录具体缺口与原因。具体复用边界见下节。

## HeroUI 组件复用规则

前端实现必须优先使用 HeroUI React。保留现有原型作为页面布局、信息层级、业务流程和状态的依据，不为匹配组件库而批量重画原型。组件选型查阅用户指定的 [HeroUI React 官方文档索引](https://heroui.com/react/llms.txt)；本次盘点基于 v3，实施时核对并固定实际依赖版本，使用对应版本的文档和类型，不能混用 v2/v3 API。

1. **通用控件优先直接复用。** HeroUI 已有且能满足要求的按钮、表单、选择器、开关、弹窗、提示、表格和分页等，必须采用现成组件。先检查其组合方式、状态、样式能力和类型定义，不能因为原型是手绘控件就重新实现一套。
2. **业务组件优先组合。** 上传队列、相册搜索选择、批量操作栏等由 HeroUI 基础组件与业务数据组合。跨页选择、权限、上传取消、时间转换和服务端校验仍按 SPEC 实现，不能把组件默认行为当成业务规则。只为实际重复需求提取组件，不另建通用 UI 框架。
3. **缺少对应能力时允许专门实现。** 瀑布流、大图查看器、水印九宫格、统计图表等可使用项目已选的专门库或业务组件；其中按钮、选择和提示仍优先复用 HeroUI。任务中说明具体缺口、已核对的官方能力及采用方式，无须为已满足规则的常规选型逐项请求批准。
4. **以设计稿为交付目标。** 使用 HeroUI 的组合、主题和样式能力还原指定 Figma 节点的结构与视觉，包括区域顺序、尺寸、间距、字体层级、颜色、圆角、图标及操作位置。品牌黄、水绿、双柔光、固定底栏、手机全屏导航和字段外标签等已确认设计继续执行。组件默认样式不是设计依据，复用 HeroUI 不能作为偏离页面结构或视觉的理由。
5. **差异必须明确处理。** 发现业务表达不清、状态遗漏或无法按设计实现时，列出具体节点、差异、原因和影响，先修正实现；确需改变既有设计的部分交由用户确认，不自行修改 Figma 或以记录原因代替批准。交付证据与未解决差异的完成条件统一见[前端共用验收](../tasks/execution.md#前端共用验收)。
6. **按真实页面验收。** 每项前端任务列出采用的 HeroUI 组件、业务组合及自定义理由，并记录相对原型的必要差异。评审检查是否存在无理由重复自制，以及桌面/手机、浅深色、键盘焦点、触控和适用的加载、错误、禁用状态。组件库提供基础能力，不替代整页布局、可访问性与业务流程验证。

## 视觉基础

沿用暖白、品牌黄、水绿与深靛蓝文字。深靛蓝不扩展为整页蓝紫背景，黄色不用于浅底小字号链接。品牌使用 Caveat，英文使用 Inter，中文使用 Noto Sans SC；常用间距为 8、12、16、24、32、48px。HeroUI 的结构与状态用于设计映射，不能据此声称已采用官方 Figma 组件库。

浅色颜色以用户确认的 OKLCH 为来源，Figma 使用换算后的 sRGB；参考 HEX 不覆盖换算值。深色使用当前 Ariso / Dark 语义颜色。

## 公共界面复用与占位退出

后台导航、品牌区、当前项表现、用户区和手机菜单由共享组件及其统一配置维护。页面只传入业务内容和必要上下文，不各自复制导航清单、遗漏图标或重排公共区域。一级后台页面直接呈现标题，不再显示没有实际导航目标的“工作空间”面包屑；详情以返回操作表达层级。同一视口下，公共外壳统一正文起点与内边距，不因路由、加载或业务状态变化而跳动。新增入口时更新公共来源，并检查已有消费页面；只复用外壳容器、不统一其中的公共内容，不算完成复用。不为此另建通用 UI 框架。

临时占位和部分交付必须在当前任务证据中写明未实现范围、承接任务和替换条件。后台导航按 2026-09-26 用户确认保留完整设计菜单；未实现入口禁用并标注“尚未开放”，不提供虚假路由，不把占位视为已交付。后续任务消费该区域时复核替换条件，条件满足即移除对应占位；不能因早期夹具或占位曾通过检查而一直沿用。

## 公共页面、导航与布局

- 非后台完整页面及其错误、处理中、成功状态保留右上淡黄、左下水绿两处柔光和低对比度点阵。柔光位于内容底层，不拦截点击、焦点或辅助阅读。浮层沿用所在页面背景；深色降低柔光强度。
- 除首页外，公共页面左上角提供明确“返回首页”；流程内另保留“返回登录”“上一步”等目的地。外部邮件直接打开页面也应有出口。全屏查看器可收起品牌和首页入口，但保留退出全屏。
- 桌面后台基准 1440×1080，常驻侧栏 232px，主区左右 32px。侧栏可收起；当前设计只提供展开画板及收起图标，实施补充 72px 图标栏，保留名称提示、当前项、禁用原因和展开入口，浏览器记住选择。手机和平板仍使用全屏菜单，不压缩为图标栏。手机基准 390×844、左右 16px；小于 768px 使用顶部入口与全屏导航，768–1199px 使用顶部菜单并按可用宽度排列，至少 1200px 使用桌面侧栏。
- 手机图库通常双列；360px 代表为两列 158px、间隔 12px。不能缩小整张桌面页面来适配，也不能靠随机换行堆叠控件。标题与短操作、相关短字段优先并排，长名称、地址与凭据独占一行。
- 手机全屏导航按当前路由高亮当前项，关闭后恢复来源与焦点。它不是侧边遮罩抽屉。设置分类使用当前分类选择器；桌面保留设置标签。用户信息位于侧栏或菜单底部。
- 数量、分页及设置页操作栏与正文滚动区分离，固定在页面底部；正文留足操作栏空间。不要让底栏跟随上方图片、列表长度或卡片位置移动。短视口和固定操作栏在真实网页验证；设备实测范围按[任务执行约定](../tasks/execution.md#前端共用验收)。
- 空状态采用居中图标、标题和说明，行动按钮放在说明下方，属于内容而非全页固定底栏。弹窗操作区在弹窗底部，也不按全页底栏处理。
- 列表保持一致列宽和操作位置，无按钮行也保留操作列。正常可读图片在队列、已选清单和结果中提供对应缩略图；不可预览用格式占位，回收内容按下述所有者管理预览规则展示；存储停用或无可读版本时用记录占位。

## 表单、提示与操作

短对话框区分标题、正文、操作区，关闭在右上。确认框通常左侧取消、右侧主要操作；结果反馈只保留一个确认按钮。手机宽度为屏宽减 32px，正文过长时滚动，不能裁掉底部操作。图片详情、本地存储、S3 配置和长处理预览采用独立页面；桌面可按对应原型采用详情弹层。S3 页面中的测试、取消、保存是三个独立步骤，不套用确认框的两按钮限制。

表单标签在控件外，字段和标签左对齐。错误紧跟字段，以文字和边框共同表达，保留其他输入；提交中禁止重复提交。开关标签在左、控件在右，下拉箭头固定右侧。水印九宫格有九个明确位置与当前文字，关闭时有禁用原因；静态预览不等于实时处理。

次要说明可以使用 Tips，实际动作仍使用可识别、有底色或边框的短按钮。SMTP 清除入口采用短按钮与独立提示图标，并保留二次确认；桌面键盘聚焦可读提示、Esc 关闭，手机点击展开并可关闭，关闭后归还焦点。关键错误、禁用原因或必要操作后果不能仅靠鼠标悬停获取。

手机按钮和独立图标按钮点击区至少 44×44px，视觉图标可更小。焦点使用清楚的 2px 描边；Tab 顺序遵循阅读顺序，展开控件同步状态，浮层关闭恢复焦点。状态不只靠颜色区分。减少动态效果时省略非必要过渡。桌面点击区按实际输入方式核验，不强制所有桌面控件变成 44px 高。

长地址必须完整换行或展开查看，复制内容不含视觉换行；自动复制失败提供完整可选文本。图表提供等价数值表、范围、单位和图例，不能只依赖颜色或悬停。
