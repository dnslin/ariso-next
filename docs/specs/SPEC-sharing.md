## 1. 目标与边界

所有者为一个相册维护一个分享地址，独立设置启停、密码、截止时间、布局和显示名称。访客通过有效链接及必要的密码验证，浏览该相册当前的公开图片。分享不创建文件副本，不改变图片可见性，也不授予管理权限。

sharing 拥有分享记录、链接 Token、浏览器密码授权和匿名页面。相册成员、名称、描述、固定展示规则及封面身份由 collections 提供；图片能否读取、实际版本与内容 URL 由 delivery 决定；品牌和时间来自 site。所有者管理入口由 identity 鉴权。

不增加访客账号、评论、协作上传、私有图片临时分享、全站公开相册目录、ZIP 下载、访客统计或新图片版本。管理列表与匿名页面分开，不能把后台相册响应直接传给匿名组件。

## 2. 工程与成熟能力依据

沿用现有单进程 Node、Next、SQLite/Drizzle、Zod 和 Pino。业务代码尚未实现；数据库复用 runtime 连接及迁移入口，不创建分享专用连接或服务。

- 随机链接沿用成熟产品的不可预测地址模式；[Google Photos 的链接分享说明](https://support.google.com/photos/answer/9789702?hl=en-GB)可作交互参考，但 Ariso 的启停和重生成语义以 PRD 为准。使用 [Node crypto.randomBytes](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptorandombytessize-callback)生成 32 字节随机值，再编码为 base64url；不把相册 ID 或时间戳当秘密。
- identity 以 Better Auth 1.7.5 为调研基线，实施时固定并验证实际依赖组合。本轮核对该版本发布包的 `better-auth/crypto` 导出和类型，提供异步 `hashPassword(password)` 与 `verifyPassword({ hash, password })`，复用其 scrypt 能力；[官方密码说明](https://better-auth.com/docs/authentication/email-password)解释默认存储方式。该库尚未安装，本轮未执行真实哈希测试。
- 分享授权使用独立随机 Cookie 和 SQLite 记录；[Next cookies 文档](https://nextjs.org/docs/app/api-reference/functions/cookies)提供 Route Handler 设置 HttpOnly、SameSite、Secure 和 Path 的能力。分享授权不是 Better Auth 所有者会话，不创建伪所有者或复用上传 Token。
- 按第 12 节已确认的大图行为，复用 library 已选的 Lightbox 展示能力和预览规则；只共享展示组件，不调用管理查询、详情或元数据接口。

## 3. 数据与输入

| 表             | 字段与约束                                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `album_shares` | id、album_id（唯一，关联 albums，ON DELETE CASCADE）、token（唯一）、enabled、password_hash（可空）、expires_at（可空）、layout、show_name、auth_revision、created_at、updated_at |
| `share_grants` | share_id、grant_secret_hash、auth_revision、verified_at、expires_at；主键为 share_id + grant_secret_hash，分享外键 ON DELETE CASCADE；过期时间索引用于清理                        |

一个相册最多一行分享记录。重复创建返回现有记录，不重新生成链接或覆盖设置。首次明确“创建并启用”时，默认网格、隐藏图片名称、无密码、无期限；可在同一次提交填写密码和期限。没有创建过分享的相册不自动出现在匿名入口。

Token 必须由服务端生成，并持久保存以便所有者以后重新复制地址；不能采用只显示一次的 API 密钥交互。原始密码不保存、不回显；管理响应只返回 hasPassword。每个分享的浏览器授权密钥只保存在对应路径的 HttpOnly Cookie，数据库存其 SHA-256 摘要；高熵随机密钥与用户设置的密码使用不同的存储方式。

layout 仅 grid/masonry，showName 为布尔。密码设置操作显式区分 keep/set/clear：未修改或空输入不能被误解为清除密码；set 接受 1–128 个 Unicode 码点，不强制所有者密码复杂度，保留大小写与首尾空格，Unicode 按所选库的 NFKC 规范化（本轮已核对 utils 0.4.2 源码），实施测试覆盖等价字符。clear 为独立的“移除密码”操作。

截止时间保存为 UTC，界面按 site 的 IANA 时区输入和显示。新设或修改期限必须晚于保存时刻；清除期限表示不过期。编辑已过期分享的布局时可以保留原期限，不偷偷延期。启用已过期分享必须同时延期或清除期限，提示在原地址恢复访问。修改站点时区只改变显示，不改已保存的绝对时刻。

分享地址为当前 publicUrl + `/s/{token}`，不从请求 Host 拼接。站点改域名后新复制地址使用新域名，Token 不变；旧域名可用性沿用 site 的部署边界。密码、期限、启停、布局和名称显示设置不改变 Token。

## 4. 链接生命周期

可访问条件始终为：相册存在、当前 Token 匹配、enabled=true、expires_at 为空或当前时间严格早于它。恰好到期即不可访问，不依赖定时任务先把状态改成“已过期”。界面计算未创建/关闭/过期/开启，以及是否需要密码；不持久维护一套容易过时的状态字符串。

| 所有者操作               | 地址       | 密码授权结果                                     |
| ------------------------ | ---------- | ------------------------------------------------ |
| 关闭后重新开启           | 不变       | 关闭时撤销；再次开启后，有密码则必须重新验证     |
| 添加、替换或移除密码     | 不变       | 原授权全部撤销；移除后按无密码方式访问           |
| 到期前延长或缩短未来期限 | 不变       | 保留尚在 24 小时内的授权，但每次请求仍检查新期限 |
| 已到期后延期或取消期限   | 不变       | 不恢复旧授权，有密码必须重新验证                 |
| 仅修改布局/名称显示      | 不变       | 保留有效授权                                     |
| 重新生成链接             | 换新 Token | 旧链接永久失效，原授权全部撤销；保留其他分享设置 |
| 删除相册                 | 地址失效   | 分享记录和授权外键级联删除，图片不删除           |

auth_revision 用于撤销：关闭、密码变化、重生成以及“保存时旧期限已到期”的编辑，在同一短事务中递增。旧期限是否已过不依赖访客曾访问或后台清理曾运行。授权行的 revision 必须等于当前值；撤销时可同时删除旧行，但校验 revision 仍是正确性依据。

管理 PATCH 只修改明确提交的字段，不把页面打开时的整行旧值写回。密码哈希在事务外异步计算，随后短事务重读当前分享并应用操作。重生成同样在事务内换 Token/撤销，成功后界面才展示新地址；网络结果不明先重取当前记录，不自动再生成一次。

## 5. 密码验证与 24 小时授权

访客访问有效的带密码分享，未持有该分享的有效授权时，仅返回品牌和密码表单。提交密码后先读取当前 Token/哈希/revision，事务外验证哈希，成功后在短事务重读并检查相册、Token、启停、期限及 revision 均仍有效，再写入授权。验证期间发生关闭、改密码、到期、重生成或删除，不能用旧验证结果发放新授权。

授权 expires_at 为本次验证成功时刻 + 24 小时，固定有效期，不因浏览或刷新续期。它还受分享本身的当前期限约束。关闭浏览器或重启服务不主动撤销未到期授权；浏览器清除 Cookie 后需要重新验证。

Cookie 提议名 `ariso_share_grant`，每次成功验证生成随机 32 字节，HttpOnly、SameSite=Lax、Path=/s/{当前 token}、无 Domain；HTTPS 设置 Secure，本地 HTTP 沿用 site 已允许的部署方式。Cookie 持久期与该授权一致为 24 小时。设置 Cookie 只能在响应可写的 Route Handler 中进行，不在已开始流式渲染的页面中写。

不同分享用不同 Cookie Path，同名 Cookie 不相互覆盖；A 相册验证不刷新 B 的授权或 Cookie 期限。数据库凭 share_id + 密钥摘要精确查授权，不接受其他相册的 Cookie。重生成后新路径需要重新验证，旧路径 Cookie 即使尚未过期也因 Token/revision 校验而无效；无需跨路径主动清除所有 Cookie。

同一相册在多个标签页同时正确验证时，两次成功各写入独立授权，浏览器最后保存哪一个 Cookie 都能验证；较早授权按自身期限清理。不同相册并发验证应都保留成功结果，不接受相互覆盖后要求再输一次密码作为正常行为。管理会话有效也不跳过分享页密码，便于所有者看到访客实际效果；所有者管理页面另走自己的入口。

密码错误返回统一错误，不显示哈希、密码长度或部分匹配信息。匿名密码端点有真实的猜测和昂贵哈希计算边界：工程起始值为每分享每分钟最多 20 次验证、全进程最多 2 个并发哈希验证，超出返回 429 和 Retry-After，不新增验证码或永久锁定。计数内存有界、清理闲置项；不信任任意 X-Forwarded-For 为真实来源。实施压测后可调整技术参数，不把它写成用户配置。

过期授权在启动和运行中的小批清理删除；每次校验仍直接比较期限，清理延迟不延长访问。日志记录分享 ID、结果与耗时，不记录密码、完整 Token 路径、Cookie 或授权密钥；沿用运行日志，不另建产品审计中心。

## 6. 匿名数据与图片权限

每次 HTML、列表、刷新和大图邻居请求都先执行同一分享校验。无效 Token/已删除返回 404；关闭/过期返回 410 和通用状态页；密码缺失/授权过期返回 401 和密码表单。状态页不带相册名称、描述、封面、图片数量或图片清单。页面框架可使用站点品牌，不把相册数据放进未解锁 HTML、RSC 数据、结构化数据或社交预览。

通过校验后只查询**当前属于该相册、public、未回收且未开始永久删除**的图片。已移出/变私有/回收的图片在后续响应中立即排除；不能先分页所有图片再在浏览器隐藏，否则会泄露私有条目与数量。即使当前浏览器另有所有者 Cookie，也固定使用匿名可见集合与可读状态，不借所有者权限展示私有或首次处理失败的内容。

匿名响应只包含：相册名称/描述、布局/名称设置、公开成员数量、裁剪后的封面、当前页卡片，以及必要的分页信息。卡片允许 imageId、布局宽高比、展示状态、可读 thumbnail URL、必要的大图 URL；仅 showName=true 时包含 displayName。隐藏名称时，alt/title/aria-label 使用“图片”等通用文案，不从文件名补信息。

不返回 originalName、标签、上传时间、存储名称/ID/Key、EXIF/GPS、文件大小、原始像素尺寸、媒体工具错误或版本技术参数。用于布局的比例不作为图片技术详情展示。名称和相册描述按纯文本转义，不解析 HTML/Markdown。不能只在 CSS 中隐藏字段而仍发送后台 DTO。

封面完全沿用 collections：指定的公开封面不可呈现时显示占位，不跳过到下一张；临时私有/回收的回退和恢复、移出后的清空均遵守上游。匿名数量只统计上述公开成员，不展示“另有 N 张私有图片”。相册没有公开成员时显示空相册，不泄露是否存在私有或回收图片。

**已确认补充：** 公开且正常库中的 pending/processing/failed 图片仍保留卡片位置。处理中显示占位，失败显示“暂不可用”，不输出已有失败版本链接；ready 重处理失败仍展示原有可读版本。存储停用保留卡片并显示“存储已停用”；缩略图读取失败明确显示加载错误，不偷偷换原图或另一存储。这与已批准封面规则一致，列表占位也已由用户确认。

内容地址始终交给 delivery 处理，分享 Cookie 不解锁私有/失败图片，不建立公开的媒体代理旁路。S3 签名不持久保存到分享表；先使用 Ariso 稳定内容地址，真正 GET 时由 delivery 签名。SVG 只显示既有 WebP 预览，原文件继续附件语义。

关闭分享、密码变更或移出相册不能撤销已公开图片本身的独立外链。图片改私有/回收/停用后停止新的匿名内容访问，已下载到浏览器的字节和剩余最多 5 分钟的 S3 地址沿用 delivery 边界。产品文案不能把“设分享密码”描述成保护原本公开的图片文件。

## 7. 列表、大图与打开中的变化

首版匿名页采用每批 40 张的加载更多；不增加后台筛选、标签搜索、批量选择和管理菜单。网格/瀑布流以及是否显示名称由每个相册的分享配置决定，访客不覆盖所有者设置。卡片只加载 thumbnail，并按比例占位；不为了瀑布流先加载所有原图。

读取 collections 成员，固定按加入时间降序、图片 ID 升序展示，分页前过滤公开集合。公开游标仅含锚点 imageId，不包含名称或加入时间等属性；服务端在同一查询中从仍属该公开集合的锚点取得加入时间，采用上游相同固定规则。锚点已移出/私有/回收或不存在时返回游标失效并刷新，不泄露其旧属性，不维护分享副本顺序。参数校验、分页限制和 SQLite 查询均在服务端执行；不逐图查询关系或 HEAD S3。

可见页面每 5 秒进行一次轻量状态检查，重新校验授权和当前已加载成员；每次最多 80 个明确 ID，有界分批。隐藏标签页停止轮询，恢复可见立即检查。每个服务端响应立即使用最新权限；“已打开页面同步”受轮询与网络延迟影响，不承诺已加载像素瞬间消失。

变私有/回收/移出立即从下一次响应移除，客户端清掉对应卡片/大图；授权失效则清除全部相册数据并回到状态页/密码表单。待处理变 ready 时可更新原卡片。布局/名称显示改动在检查响应中同步；关闭名称时清除已返回的名称展示。成员加入、移出或状态变化可通过刷新重新读取，不能承诺跨多次请求的数据库快照。加载结果按 ID 去重，失效游标有明确刷新入口。

一次状态检查未完成时不叠加新轮询。授权状态、名称显示策略或查询批次改变时，取消旧请求并忽略旧批次的列表/邻居/刷新响应，不能在清空后被迟到响应重新填回图片或隐藏名称。大量卡片使用 library 已要求验证的分段渲染/虚拟化组件，避免把整个相册同时装入 DOM；共享组件只接收匿名裁剪结果。

**已确认：允许点击可读图片看大图。** 采用已确认的默认预览选择：普通静态优先可显示的 compressed，否则可显示的 original，再用现有预览；动画优先 original，SVG/ICO/多页按既定预览。选择现存版本使用显式 type，不依赖站点默认外链，也不生成新文件。没有可读展示版本则占位，实际网络/文件错误不自动换版本。

查看器只提供前后切换、缩放/平移、关闭及浏览器支持时的全屏；首尾不循环。按当前公开相册顺序按需读取邻居，最多预加载前后各一张，不请求后台详情。没有版本切换、技术信息、下载原图、分享、幻灯片按钮；名称仍服从 showName。关闭恢复原卡片焦点与滚动位置；当前图被移除时返回列表。手机手势和键盘规则复用已批准的大图交互，具体设计归 DES-03。

## 8. 接口与一致性

| 入口（草案）                              | 职责                                                                                       |
| ----------------------------------------- | ------------------------------------------------------------------------------------------ |
| `GET /api/shares`                         | 所有者管理列表，含相册、当前地址、启停/到期/密码标记、布局及名称设置；分页，不返回密码哈希 |
| `POST /api/albums/{albumId}/share`        | 明确创建并启用；已存在返回当前记录，不覆盖                                                 |
| `GET /api/albums/{albumId}/share`         | 所有者读取当前配置，供编辑/复制/结果核对                                                   |
| `PATCH /api/albums/{albumId}/share`       | 独立更新配置及按规则撤销授权                                                               |
| `POST /api/albums/{albumId}/share/rotate` | 明确重生成 Token；保留配置，撤销旧地址和授权                                               |
| `GET /s/{token}`                          | 匿名品牌、状态/密码页或已授权相册首批                                                      |
| `POST /s/{token}/unlock`                  | 密码验证及 Cookie；不接受所有者/API Token 代替密码                                         |
| `GET /s/{token}/items`                    | 已授权公开列表或指定 imageId 的前后邻居，参数不能改变可见性范围                            |
| `POST /s/{token}/refresh`                 | 只读状态检查及最多 80 个已加载 ID 的当前公开状态；未知/非成员/私有统一表示不可展示         |

所有管理写入口复用 identity 所有者和来源检查；匿名 unlock/refresh 检查 site origin，但不能要求所有者登录。上传 Bearer 不能调用任何管理分享接口。协议字段使用 Zod 显式 schema；参数错误 400、未登录管理 401、来源拒绝 403、相册不存在 404、并发配置变化 409、限流 429；实际依赖故障保留可诊断的服务端上下文，匿名只返回必要提示。

匿名响应统一 Cache-Control: private, no-store，页面不静态生成、不跨用户缓存。分享页使用 noindex 与 Referrer-Policy: no-referrer，避免能力地址经搜索/跳转外泄；不把访问 Token 放进分析脚本。分享路径需从访问日志中按既有脱敏规则裁剪，错误日志保留分享 ID 便于诊断。

授权检查与本次相册/成员读取在同一短 SQLite 读事务中取得一致视图。事务内不等待哈希、网络或文件传输。事务之后状态可能变化，内容请求仍由 delivery 再检查，不能把读取列表时的判断当永久文件许可。Next 异步请求上下文与事务读取分开，不把异步函数传给同步 Drizzle transaction。

## 9. 模块组织、依赖与统计

拟放 `src/server/sharing/`：schema、输入定义、配置命令、授权、匿名查询及响应裁剪，按职责拆文件，不构建通用权限框架。Route Handler 只做输入/身份/调用/响应。迁移由现有 `src/server/**/schema.ts` 入口收集；页面及组件沿项目实际 app 目录布局，匿名组件不能导入 server 管理 DTO。

collections 提供相册成员、固定展示规则和封面身份的只读查询契约，sharing 组合筛选并裁剪，不直接写 collections/media 表。生成页面内容候选时按匿名规则判断 ready/公开/可读，只使用 delivery 已有版本与 URL 能力，不用所有者权限补入异常图片。独立 `/i/` 请求仍遵循 delivery 的真实会话规则：所有者的独立读权限不因浏览分享页消失，分享页列表也不能因此扩大。若共用组件需要新增提供方接口，先在提供方规格定义，不反向依赖 library 服务端或新增依赖环。

示意调用保持显式上下文，具体类型以实施时上游接口为准：

```ts
const access = readShareAccess(tx, { token, grantSecretHash, now });
if (!access.allowed) return access;
return readPublicSharePage(tx, { share: access.share, cursor, limit: 40 });
```

访问统计完全沿 delivery：匿名非 thumbnail 内容 GET 在开始本地传输/成功 S3 302 时计数；缩略图、HEAD、错误与所有者访问不计数。匿名大图预加载也可能产生实际 GET，不能把统计解释为独立访客或完整阅读次数。打开相册页/验证密码不新增一套访问量；analytics 仍负责统一聚合。

实现顺序：分享模型和管理配置 → 授权/撤销 → 公开查询 → 匿名界面及异常状态 → 与删除、隐私变化、S3 的完整集成。前置规则以任务索引为准；删除相册与分享联动只有真实分享表/授权接入后才能关闭，不能用模拟回调作为最终验收。

## 12. 用户确认记录

1. **访客点开图片。** 朋友打开旅行相册，点击风景图可以放大、缩放和切下一张。普通静态图优先已有压缩版，动画展示原图，SVG 等展示既定预览。不显示后台的版本选择、文件大小、拍摄信息或下载按钮。用户已确认采用精简大图查看。
