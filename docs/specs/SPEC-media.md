## 1. 目标与职责

每次上传成为独立图片资产，原图字节保持不变。系统根据任务创建时的设置生成适用版本，支持元数据读取、预览、重处理、回收站和可恢复的永久删除。失败必须能看见原因，保留已有内容，并能明确判断哪些操作可以重试。

media 拥有图片、版本、处理设置、水印素材、元数据和处理/清理任务。底层通过 storage 访问对象；不拥有上传传输会话、相册标签、图库查询页面、公开 HTTP 响应或访问统计。管理入口使用 identity，启动与跨模块事务由组合入口接入。

不提供原图替换、内容去重、历史版本回滚、自动清空回收站、多水印、自定义字体或独立 Worker。正常图库的一条记录对应一个图片 ID，不把派生图拆成图片记录。

## 2. 已核对能力与实现边界

仓库已有 Drizzle/better-sqlite3、Zod、execa 10.0.1 和 runtime 日志/目录；还没有业务 schema、图片处理封装或持久任务消费者。任务消费接入 `startServer()` 的 Web 进程单例；prestart 只准备基础条件，构建期间不能启动队列。

Docker 镜像安装 ImageMagick 7、ExifTool、HEIF/AVIF 相关插件与中英文字体。归档双架构证据仅验证 JPEG/PNG 转 JPEG/WebP/静态 AVIF 和字形渲染。APNG、动态 AVIF、HEIC、多页文件、SVG、完整元数据和资源限制仍需真实样本验证；不能用历史检查替代本模块验收。

格式签名与 XML 解析优先采用成熟库，先核对现有依赖，再在实施任务中比较、固定实际版本。本稿不提前指定未经验证的库 API，不自行重写完整图片容器解析器。

官方能力依据：

- [ImageMagick 格式](https://imagemagick.org/formats/)与 [AVIF 序列](https://github.com/AOMediaCodec/libavif/wiki/Sequences)：PNG 首帧读取不证明 APNG 分类正确；静态 AVIF 转码不证明动画支持。是否需要额外解码组件，以完整样本验证决定，不能削减 PRD 格式范围。
- [ImageMagick 资源](https://imagemagick.org/resources/)与[策略](https://imagemagick.org/security-policy/)：尺寸、序列、缓存、时间等可约束；`area` 超限会转磁盘缓存，不是最大像素拒绝阈值，也不作为上传准入限制；`disk` 也不包含全部任务文件。
- [ExifTool JSON 选项](https://exiftool.org/exiftool_pod2.html)：用分组与实例标识保留重复标签，保留结构化 XMP；具体命令必须用同名标签样本验证。

上述为资料和仓库核对，未执行本模块真实处理测试。

## 3. 数据与状态

### 3.1 图片、版本和对象

| 表                       | 主要字段与约束                                                                                                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `media_images`           | 随机 `id`、固定 `storage_id`、只读 `original_name`、可改 `display_name`、`visibility`；识别格式/MIME、宽高、原图字节数、动画/页数/分类；`processing_status`、`trashed_at`、`deletion_status`；UTC 创建/更新时间                            |
| `media_objects`          | 所属图片/任务、storage 外键、唯一 Key、用途、`planned/writing/stored/cleanup_pending/cleanup_failed/deleted`、已知实际字节数、实际编码、错误与清理结果；对象写入前就登记                                                                   |
| `media_versions`         | 每图每种 `original/compressed/thumbnail/watermark` 最多一行，指向当前已存对象，记录实际尺寸/类型/字节数；不以文件扩展名推断类型                                                                                                            |
| `media_jobs`             | 图片可空（预览）、种类 `process/metadata/preview/delete/cleanup`、处理范围、不可变设置快照与素材引用、应生成版本集、步骤与已保存结果、`queued/running/succeeded/failed/cancelled`、自动重试次数/下次时间、错误、UTC 时间；预览另有到期时间 |
| `media_metadata`         | 每图一行，读取状态、完整分组 JSON、读取时间、可读错误；重新读取失败保留上次成功内容并标明旧结果                                                                                                                                            |
| `media_settings`         | 固定 `id=1`；处理参数、默认可见性、默认链接版本、并发数、水印模式与当前素材引用、更新时间                                                                                                                                                  |
| `media_watermark_assets` | 不可变素材 ID、站点 assets 下的受控相对路径、实际类型/尺寸/字节数、临时素材到期时间、清理状态；设置和任务引用素材 ID                                                                                                                       |

这些对象记录只服务 media 的版本发布和清理，不复制 storage 的 probe 或 upload 的临时对象记录。`media_versions` 最多四种；候选、待清旧对象不构成可选择的历史版本。

同一文件重复上传生成不同 ID。`originalName` 是上传入口提供的原始文件名，不作为路径；`displayName` 初值只去掉最后一个扩展名，例如 `trip.final.JPG → trip.final`，无扩展名保留。隐藏文件名和空结果规则由 upload 的名称归一化契约明确，不能各入口自行截断不同部分。重命名不修改原图、Key、ID、关联、统计或链接。

### 3.2 三个独立维度

1. `processing_status`：新图片 `pending → processing → ready/failed`。只有本次应生成版本全部保存成功才能 ready。格式不适用不算失败；元数据读取失败也不阻断 ready。
2. `trashed_at`：是否处于回收站，独立于处理状态。移入回收站不覆盖处理状态，不删除关系。
3. `deletion_status`：正常为 null；永久删除为 `deleting/cleanup_failed`。开始永久删除后禁止恢复或重新处理。

已有 ready 图片重处理期间一直保持 ready，任务另行显示处理中/失败。旧对象后台清理失败只影响该清理任务，不把可用图片改成回收站的 `cleanup_failed`。

对外版本查询同时给出“格式是否适用”“当前是否存在已保存版本”“最近任务目标及结果”。开关关闭、格式不适用、尚未生成、生成失败不能合并成一种状态。不能因当前关闭压缩就隐藏仍存在的历史 compressed 版本。

## 4. 初始化、设置与水印素材

### 4.1 初始值和原子保存

`prepareInitialMedia(tx)` 在 identity 的 setup 同步事务中插入默认设置，与站点和唯一所有者一起提交。已存在时不覆盖。初始压缩开启、WebP、质量 82、最长边关闭、JPEG 背景白色、水印关闭、默认链接 compressed、默认可见性 public、并发 1。

压缩与水印共用输出格式、质量、最长边、JPEG 背景色。默认链接仅 original/compressed/watermark；选择 compressed/watermark 要求对应开关开启。关闭当前默认所用开关时，须在同次保存选择另一个有效默认值；否则拒绝保存并定位字段，不静默改为 original。

默认外链按 [delivery 规格](./SPEC-delivery.md)采用不带 type 的地址，修改默认版本影响历史默认链接；主动选择具体版本的链接才固定。访问规则读取当前默认值，不用处理任务快照冻结链接选择；改默认不自动生成历史缺失版本。

修改默认可见性只影响后续上传。修改处理设置只影响后续创建的快照。并发数是调度设置，变更后控制新任务领取；调小并发不杀死已经运行的任务。

### 4.2 本稿提议的参数范围

| 参数         | 提议                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| 输出         | JPEG/WebP/AVIF；质量整数 1–100；最长边为空或整数 1–32768；背景色 `#RRGGBB`       |
| 并发         | 整数 1–4，初始 1                                                                 |
| 水印模式     | 关闭、文字、图片三选一；切换模式保留另一模式已填参数，但只应用当前模式           |
| 文字         | 1–200 个 Unicode 字符，最多 5 行；中文/拉丁内置字体 ID；颜色及描边颜色 `#RRGGBB` |
| 相对字号     | 图片短边的 1%–20%，初值 3%；向最近整数像素取整，最小 1px                         |
| 描边         | 0–10px，初值 0；以最终输出画布像素计                                             |
| 透明度       | 0–100%，初值 50%                                                                 |
| 位置与边距   | 九宫格，初值右下；边距为短边的 0%–20%，初值 2%；居中方向不加偏移                 |
| 图片相对宽度 | 最终画布宽度的 1%–100%，初值 20%；保持素材比例，再缩小至边距内可放置尺寸         |

以上为水印行为的工程参数基线，不从 Figma 示例数字推断产品要求；仍需结合实际渲染验证。文字按换行计算尺寸；超出可用画布时返回明确错误，不裁掉一半内容、不悄悄减小字号。手机端使用同一参数规则。

### 4.3 素材生命周期

图片水印仅 PNG/WebP/静态 SVG，不超过 5 MiB；拒绝 APNG、动态 WebP 和带动画的 SVG。SVG 必须是无脚本、无外部资源的静态图像。原文件先保存为新的不可变素材，再在设置事务中切换引用；不覆盖原路径。

上传但未保存设置的素材为临时素材，提议 1 小时到期；设置、upload 批次/会话、排队/运行任务或预览仍引用时不能清理。保存设置只允许选择校验成功的正式素材或未到期临时素材；正式采用临时素材时在同一事务解除临时到期限制，后续保存当前素材不受原一小时时间限制。替换或移除水印后，旧素材等最后一个设置、upload 批次/会话或未完成任务引用释放才进入清理；失败保留记录和错误，下次启动可恢复。

完成或最终失败任务释放运行所需素材引用；手动重新处理用最新设置重新创建任务，不承诺复活已结束任务的旧素材。自动重试尚未结束，必须保留原素材。终态任务的快照保留素材 ID 和属性用于说明历史参数，但不阻止不再使用的素材清理。

## 5. 上传交接与不可变任务快照

upload 为每个批次在提交时取得同一份 `createProcessingSnapshot(tx)`，含处理设置、默认可见性和确切水印素材引用；显式上传可见性覆盖默认。快照在排队期间不会随设置改变。该批次尚未交接的图片也必须保有所需素材引用，upload 的会话/批次记录提供引用查询。

原图传输、S3 临时 Key 和取消归 upload。原图只有在 upload 已验证输入并固定到不可被旧签名改写的正式对象后，才调用 `acceptOriginal(tx, input)`：

1. 入口在同一短事务内检查会话尚未完成/取消，固定 imageId/storageId/正式 Key、原始名、实际字节数和批次快照。
2. media 建立图片、original 对象/版本和 queued 处理任务；upload 同事务标记完成、转移正式原图清理责任和素材引用。
3. 仍可被签名写入的临时对象继续由 upload 引用和清理，不因交接完成而提前删除会话责任。

正式 Key 在实际写入前已有 upload 的持久引用；交接不会出现无人负责的窗口。重复完成返回同一个交接结果，不创建第二张图；重新上传相同内容则是另一个会话和新图。

事务内不得下载、解码、散列大文件或等待子进程。签名/格式初验与正式识别的重复部分复用已有结果及其对象身份，不对可信内部结果无理由再读一遍；完整解码后发现损坏/超限仍保留已接收原图，图片 failed。

## 6. 格式分类和派生流水线

### 6.1 分类矩阵

| 分类                                                        | 原图         | 缩略图                      | compressed / watermark |
| ----------------------------------------------------------- | ------------ | --------------------------- | ---------------------- |
| JPEG、PNG、静态 WebP/AVIF、BMP、单主图 HEIC/HEIF、单页 TIFF | 字节不变     | 静态 WebP                   | 按快照开关生成         |
| 动态 GIF、APNG、动态 WebP/AVIF                              | 保留完整动画 | 首个实际展示画面的静态 WebP | 不适用                 |
| SVG、ICO、多页 TIFF、多张独立主图的 HEIF/AVIF 等图像容器    | 保留完整文件 | 静态/首个主页面 WebP        | 不适用                 |

“其他多页/多图”拟指支持的图像容器内多个独立图像；首版不由此开放 PDF、PostScript、办公文档、视频或任意 ImageMagick delegate。静态 GIF 拟沿用 GIF 的仅预览规则。这两项范围解释已由用户确认。

分类按实际字节和可靠容器信息进行：大小→二进制签名→XML/SVG 检查→受限 ImageMagick 解码→ExifTool 格式、帧页及完整元数据。后两者交叉核对，但 ExifTool 失败不自动把未知格式判为静态；若无法可靠判断动画/页数，处理失败并给出识别原因。

只生成预览时按需解码首个展示画面/主页面，不展开全序列再丢弃；格式识别仍要可靠，不能把按需读取误认为文件只有一帧。APNG 不能因为普通 PNG 解码只读到首帧而归为静态；动态 AVIF 不能因单图解码成功就判静态。HEIF 的缩略图、alpha、depth 辅助图不算独立主页面。优先选择容器定义的主图，其他独立页按容器顺序；动画预览须正确处理首个展示画面的合成，而非展示孤立的增量区域。

普通 SVG 原图也不改写；预览不能执行脚本或读取其指定的网络/本地资源。发现这类引用时拒绝该预览处理，保留原图并说明原因。XML 外部实体、ImageMagick URL/delegate/间接文件读取约束针对的实际边界是上传者控制的图片内容；须在所选 renderer 中验证，不只检查文件名。

### 6.2 生成规则

- 派生先应用方向，再转换到适当的 sRGB 表示、缩放，最后清除源附加信息。用真实旋转/镜像样本避免 HEIF 被二次旋转；不保证未经验证的 HDR 色彩还原。
- 压缩最长边只等比缩小，绝不放大。透明输入输出 JPEG 时先按指定背景合成，产物必须真是 JPEG；不能偷偷保存透明 WebP。
- 缩略图固定 WebP、最长边 640、质量 80、保比例、不放大，清理附加信息；网格裁切交给 CSS，瀑布流使用真实比例，共用同一缩略图。
- 压缩开启时，水印基于本次新压缩结果；关闭时基于原图经方向/尺寸处理的画布。不能用旧 compressed 代替。水印最后以共同设置编码，结果不保留源 EXIF/GPS/XMP/IPTC/ICC 等附加信息。
- 文字使用固定字体 ID 到镜像字体路径的映射。复用 execa 参数数组，不拼接 shell；同时处理 ImageMagick 自身的文字解释，用户 `%[...]`、`@路径`、反斜线等必须呈现为字面文字，不能读文件或插入绘图指令。

每一步把预定的新 Key 先写入对象记录，再进行 I/O，保存成功后登记实际结果。初次处理、失败图重试和 ready 图重处理在每次发布版本及最终改状态的短事务中，都必须复核任务仍有效、图片未开始永久删除、存储启用；不满足时只结算对象责任，不建立可访问版本。部分失败保留原图与已成功发布的初次派生版本，详情可见；未完整写完的对象仅作待清理对象，不冒充成功版本。

## 7. 队列、重试、重启与停用

一个 Web 进程内一个调度器管理 SQLite 持久任务，内容处理并发 1–4。预览和元数据重读也占处理名额，不能绕过限额；同一图片最多一个活动内容任务，重复提交返回现有任务/冲突，不让两个重处理交错发布。

领取任务使用短事务条件更新 queued→running，事务外执行各步。队列等待与运行时间分别记录。暂时失败按错误类别自动重试一次，建议 5 秒后；次数和下次时间持久保存。网络暂时中断或可恢复临时文件错误可重试；权限/停用/损坏/不支持/参数错误/资源超限不自动重试，不把所有异常都归类为网络问题。

自动重试沿用同一快照和已确认成功步骤，不能重新读取全站设置。SDK 的请求尝试次数要与此预算分开配置和记录，避免两层默认重试相乘且无法解释。

进程正常停止先停止领取、取消或等待当前步骤有界结束，记录对象结果。启动恢复只读取本模块未结束任务和确切对象：已登记 stored 的结果可复用；writing/结果未知的对象先核对，完整有效才认领，否则清理并重新做该步。不能仅凭 Key 存在认领部分本地文件。

进程被中断不消耗一次“临时错误自动重试”；但同一未完成步骤最多自动恢复两次，再次无进展中断则 failed 并提示手动重新处理，避免会杀死进程的样本造成永久启动循环。持久恢复计数按已完成步骤前进重置，不因每次启动清零。不得启动时清空整个 tmp 目录。

存储停用后不开始新的读取/生成/写入步骤。未开始或正在处理的任务结算已有结果后失败为 `STORAGE_DISABLED`，新图 failed；已有 ready 图保持 ready，但 delivery 因存储停用拒绝访问。重新启用后由所有者重新处理，不悄悄换存储或自动重启整批内容。删除和维护清理仍可执行。

移入回收站只改变可见范围；已提交处理可继续完成，但所有链接仍不可用。回收站中不提供新重处理入口；需要先恢复。永久删除则必须按第 11 节停止写入并清理。

## 8. 手动重新处理与发布

范围为全部派生（默认）、仅压缩、仅缩略、仅水印。每次手动提交取当前最新设置建立新任务快照；排队后再改设置不影响该任务。失败图片的“重试”拟同样使用最新设置和全部派生，界面明确这一点，不创建新图片 ID。

压缩关闭不能选仅压缩；水印关闭不能选仅水印；格式不适用不能提交对应单项。失败图片仅接受 `scope=all`，其他范围返回状态冲突；完整生成该新快照全部应生成版本后才可 ready，不能用仅缩略绕过未完成的必需版本。

“全部派生”更新当前设置要求的适用版本。当前关闭的旧 compressed/watermark 保留，不当成待删除对象。仅水印且压缩开启时，可生成新的临时压缩中间产物供水印，不切换用户未选择的 compressed 版本。

已有 ready 图的发布步骤：

1. 先登记并生成所选候选对象；所有候选保存成功前，当前版本引用不变。
2. 同一短事务核对任务仍有效、图片未开始永久删除、存储仍启用；一次切换本任务选中的版本引用，登记旧对象的清理责任，标任务成功。
3. 事务成功后再清理旧对象；失败保留清理记录供恢复/重试，不回滚新版本。若事务未成功，候选留待清理，当前版本不变。

本地在目标文件系统写完再发布新对象，S3 使用新 Key；数据库事务只切引用，不假装与文件系统/S3 构成跨系统事务。既有本地读取流可读完；S3 旧签名本身最多 300 秒，但旧对象删除后不保证旧签名继续读到文件，新 Ariso 请求按当前版本处理。

初次失败图片已有成功版本可保留到新任务对应版本成功替换。手动任务不能把旧快照的结果直接当新快照结果；已有 ready 图片失败时所有旧版本继续可用。候选清理失败仍占存储引用和实际空间。

## 9. 完整元数据与临时预览

### 9.1 元数据

ExifTool 读取原图，基线参数为 `-json -a -G1:3:4 -struct -api structformat=jsonq`，以家族分组、文档和实例区分同名标签；不使用会主动跳过信息的 fast 模式，也不另存原始 EXIF 二进制。路径由服务器生成，客户端不能传 ExifTool 参数。

格式/资源探测与完整元数据读取分别记录结果。完整 JSON 的超时或超限不能推翻已经可靠确认的分类；必要的帧页分类仍未知时才按格式探测失败处理。JSON 输出完整解析成功后一次替换 metadata 结果；不得静默截断字段后标成功。数字样式文本（如 `1.10`）、长序列号和结构化 XMP 不得因 JavaScript 数值转换丢失原值；以保值结果持久化和展示，常用摄影数值另行显式转换。归档镜像为 ExifTool 13.25；[官方历史原文](https://github.com/exiftool/exiftool/blob/master/html/ancient_history.html#v13.00)已在 13.00 记录 JSONQ 结构内数字修复。先验证现有版本，不为此预设升级；参数能力仍须用真实样本验收，不使用 `-sep` 将数组压成字符串。读取失败单独记录步骤、错误和时间，原图保留，派生处理不因此失败。所有者可单独重读，重读不重新生成图片版本；失败时旧成功结果标为历史结果，不能显示成刚读取成功。

所有者详情显示常用参数与完整分组列表。不建立相机/ISO/GPS 搜索能力。匿名分享不主动返回完整元数据；复制或下载公开原图提示其可能含 GPS/拍摄信息，但不阻止操作。页面由 library/sharing 接入这些约定。

### 9.2 预览

处理设置页可上传临时测试图，用尚未保存的表单参数和水印素材在服务端执行同一处理函数，展示实际编码、大小、尺寸及效果；不能用浏览器滤镜冒充真实输出。需要选择和正式流程一致的目标版本；不适用时明确说明，不把缩略图标成压缩或水印结果。

preview 任务无图片 ID、不建图片/图库/相册/统计记录、不写配置存储；输入和输出只在 `${DATA_DIR}/tmp`。预览结果仅所有者访问，提议完成后 30 分钟到期；临时素材保留至引用结束。新预览可取消旧任务，取消同样等待子进程和写入结算后清理。过期后返回已过期，可重新预览。

失败、取消、到期和启动恢复都清理自己的确切临时文件；清理失败留任务可见错误。任务可以短期持久化用于恢复，但不能把测试图长期留存。

## 10. 文件大小与按需资源使用

用户已确认：上传以文件大小限制为主，不设固定输入宽高、像素、帧数或页数拒绝规则；不为每个任务预留固定 4 GiB 工作区。默认上传限制仍为 PRD 的 50 MiB，后台可配置范围及底层传输限制由 upload 规格闭合；取消本稿额外提出的 1 GiB 原文件硬上限。实际接收/下载必须计数字节，不能只信 Content-Length。

以下是工程起始参数，用于约束实际处理过程，尚需真实样本验证，不表示每个任务都需要这些资源，也不是用户逐项确认的新产品限制：

| 项目                       | 工程起始方案                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 输入尺寸、像素、帧数、页数 | 不设置固定拒绝阈值；识别真实格式，特殊格式只解码预览所需画面                                                       |
| 单次 ImageMagick           | 120 秒墙钟时间，含委托子进程；每任务最多同时一个图片工具进程                                                       |
| 单次 ExifTool              | 30 秒；JSON 输出最多 32 MiB，超出仅记元数据读取失败，不保存残缺 JSON                                               |
| 内容任务运行               | 600 秒，不含排队；超时不自动重试；取消后 5 秒内强制结束未响应子进程                                                |
| ImageMagick 缓存           | memory 256 MiB、map 0、disk 至多 512 MiB、thread 1；缓存按需增长，无文件预分配；disk 还受当前可用空间约束          |
| 单任务工作区               | 无固定预留或总容量门槛；仅存需要的源文件副本、当前步骤产物与缓存，及时释放不再需要的中间文件                       |
| 磁盘低水位                 | 工程起始值为每个实际写入文件系统保留 256 MiB；按当前可用空间及已知在途剩余写入量判断，不按并发数乘一个固定任务配额 |

本地原图可直接受控读取，不复制一份完整原图到临时盘；S3 原图需要落临时盘时，按已知实际字节数检查空间。相同文件系统只计一次，外置本地卷分别检查，S3 仍需检查服务器临时盘。原图可用字节数不是派生文件或解码缓存大小的可靠倍数，禁止采用“输入大小乘固定倍数即可保证够用”的假定。

每个步骤开始前检查可用空间；对已知长度的接收/下载登记尚未写出的字节需求，随写入减少，完成/取消后释放。未知长度的上传按有界缓冲逐块检查与计数，不预留整个允许上传上限。队列启动依据仍活动的持久任务/上传记录恢复已知在途需求，不恢复不存在的固定配额。

派生结果用流计数并检查剩余空间；工具缓存以该步骤开始时可用空间和缓存上限中较小者设置。过程中监测实际用量，发现低空间终止当前步骤，并正确处理 ENOSPC。监测不是文件系统硬配额，不承诺外部程序或并发写入不会抢占空间；不能据此吞掉磁盘满错误。多个任务共享缓存所在磁盘时减少领取或缓存预算，不能各自按同一份空闲空间承诺独占。实现保持单进程调度，无分布式锁或配额系统。

不再设置每个派生 128 MiB、派生累计 512 MiB 的固定准入限制。输出、中间文件和工具缓存均按实际写入管理。及时清理已不再使用的中间产物，但失败初次处理已成功的版本、原图与重处理旧版本按既有规则保留，不能为了腾空间删除。

不以 ImageMagick width/height/list-length policy 重新引入已经取消的业务阈值；核对镜像和解码库实际能力，用大尺寸、多帧、多页真实样本验证不会被遗留配置拒绝。工具自身无法处理某个文件时，报告真实解码/资源错误，不承诺无限资源或任何尺寸都必定成功。

原图已保存后实际解码失败、超时或资源不足：新图 failed，保留原图和已成功版本；已有 ready 图重处理失败仍使用旧版本。完整元数据输出/时间超限只影响元数据状态，不推翻已可靠确认的格式分类。低空间返回 `INSUFFICIENT_DISK_SPACE`，停止接收新上传或无法继续的步骤；不自动清空回收站。

upload 必须闭合实际传输大小、各写入路径的空间检查及在途字节需求交接。实施验收包括：只有几百 MiB 空闲时小文件仍可处理；同样空闲下较大原图下载能明确拒绝；并发/取消/进程恢复不重复扣算空间；实际磁盘耗尽能保留数据并准确报错。上述起始数值可依据测试调整并记录，不改变用户已确认的按需使用规则。

## 11. 回收站、永久删除与清理恢复

移入回收站只写 `trashed_at`；normal library/sharing 查询排除，delivery 所有版本入口拒绝。保留名字、可见性、处理状态、版本、相册/标签关系、原加入时间和历史统计，不自动清理。存储停用时仍可移动和恢复记录。

恢复清空回收时间，沿用原 ID/链接和仍存在的关系；相册/标签已被删除就不重建。存储未启用时可恢复记录，文件仍不可访问。永久删除开始后的 deleting/cleanup_failed 记录不能恢复，因为部分对象可能已删除。

永久删除仅从回收站发起，并返回持久任务：

1. 短事务设置 deleting，取消未开始的内容/元数据任务，禁止新任务和旧任务发布；保留原处理状态。
2. 对正在运行的步骤发送取消并等待有界结束，登记成功、失败或结果不确定的 Key；清理前确认这些操作不会继续生成新文件。
3. 清理该图片全部原图、当前派生、候选、待清旧对象和写入结果不确定的对象。存储停用不阻止操作；明确对象不存在可当已清，权限或网络失败不能当不存在。
4. 每个对象成功删除即持久记录；仅临时错误对剩余对象自动重试一次，权限等非临时错误直接保留失败。再次失败保留图片为 cleanup_failed、剩余清单和错误，允许手动幂等重试，不恢复已删除文件。
5. 全部对象及活动写入责任清空后，短事务删除图片、版本、元数据、终态图片任务和相关关系；collections 的关联须通过已声明外键清除，analytics 的历史统计保留方式由其规格定义，不能随便级联删除。

取消远端请求不等于服务端写入已经停止。storage 写入提供方必须给出操作结束/结果核对的证据；仍可能迟到的对象继续保留引用和再次核对责任，不能“删一次后就忘记”。upload 的可再次写入临时 Key 仍由 upload 持有和清理，不能在本次图片删除中顺带释放尚未到期的会话。

删除任务与普通旧对象清理共用确切对象的幂等删除步骤。对同一个 Key 的责任合并，不能两个任务各自认为另一个已经删除。重启按 deleting/cleanup_failed 与对象结果恢复被中断或预算未耗尽的任务；已耗尽预算的终态 cleanup_failed 等待手动重试，重启不重置次数。手动重试创建新的有限尝试周期，已成功项不重做业务发布。

`getStorageReferences(tx, storageId)` 返回图片（含回收/删除失败）、对象、未完成任务和遗留清理责任。storage 管理入口在同一写事务内检查汇总引用；无引用以前不能改位置或删配置。实际空间统计包含尚未清掉的旧/候选对象，不能只统计四个当前版本；未知字节数保留待核对标记，不编造为零。

### analytics 用量只读提供方

补充 `readMediaUsage(tx)`：按 storageId 汇总正常/回收资产数量、当前未解决处理异常，以及媒体对象的已确认字节/待核对数。对象按回收全部对象优先，再正常当前原图、正常当前派生、其余候选/旧对象互斥归类；不把 media_versions 与 media_objects 重复相加。planned 未写入不算已占用，写入未知与删除未确认保留状态；确认删除后才减少。返回记录确认时间，不在统计请求中读取文件。消费方的数量/历史展示规则见 [已评审 analytics 规格](./SPEC-analytics.md)，函数不依赖 analytics。

## 14. 工程组织与验证

拟按现有 `src/server` 风格增加 `media/`：模型与查询、设置、格式探测、处理流水线、任务消费、元数据、清理各有明确职责；HTTP 在 App Router 的对应入口组合。沿用 TypeScript 严格检查、Zod 边界解析、同步 Drizzle 短事务、Pino 结构化日志。示例：

```ts
const job = createReprocessJob(db, { imageId, scope: 'all' });
logger.info({ imageId, jobId: job.id, scope: job.scope }, 'Media job queued');
return { jobId: job.id, status: job.status };
```

运行中日志包含 imageId/jobId/storageId、步骤、次数、时长、工具退出信息与清理结果。正常日志不写完整原图元数据、SMTP/存储密钥或签名查询串；所有者能看到实际错误和受控对象定位，不用通用“处理失败”吞掉原因。

单元测试放 `tests/unit/media/`，覆盖参数、分类规则、状态和快照。集成测试放 `tests/integration/media/`，使用真实 SQLite/临时目录/工具，验证发布与清理故障时点、进程恢复、字节与像素。新增格式样本和扩展 `scripts/verify-image.mjs` 的任务单列；不把现有 JPEG/PNG 脚本通过等同完整 media 通过。

实施时运行适用命令：

```sh
pnpm run format:check
pnpm run lint
pnpm run typecheck
pnpm run test:unit
pnpm run build
pnpm run test:integration
pnpm run test:browser
node scripts/verify-image.mjs --output-dir verification/media
```

schema 变更才执行 `pnpm run db:generate` 并审查 SQL。镜像内执行工具验证并由 Actions 跑 amd64/arm64；真实 S3、故障注入、浏览器与资源边界分别记录证据。最后一条命令是当前已有入口，必须先扩展完整样本断言才满足本规格。

始终保留原图、错误和清理责任；新增依赖或格式组件必须有实际缺口与验证依据。禁止跳过未支持格式样本、假造成功或以缩略图替代原文件。范围或资源数值影响产品行为时先修订规格，不为了检查通过降低验收。本轮只编写文档，不宣称任何业务测试已通过。

后续 delivery 闭合公开/所有者权限、版本选择、缓存和下载；collections 闭合关联外键与顺序；upload 闭合传输大小/空间预留/素材快照及正式对象交接；library 闭合列表和批量交互；analytics 闭合实际空间及删除后的统计。缺失这些联验不能把完整上传、外链或永久删除流程标 Done。

## 15. 已确认的评审意见

用户于 2026-09-17 确认以下产品行为；资源部分按反馈修订，第 10 节工程起始值仍需实测，不把未实测的参数当作性能承诺。

1. **上传与资源**：以文件大小限制为主，取消固定宽高/像素/帧页拒绝规则；取消每任务固定 4 GiB 预留，按实际需要使用磁盘。保留实际处理超时、资源错误和低空间反馈，相关 PRD 与覆盖表已同步。
2. **水印与预览**：排队任务继续使用提交时的水印；新设置只影响新任务；测试图不入图库，预览 30 分钟过期，未使用临时素材 1 小时后可清理；文字放不下明确报错。
3. **格式范围**：静态 GIF 同样按 GIF 仅生成预览；多页图片保留完整原文件并生成首页预览；不支持 PDF/办公文档/视频。APNG、动态 AVIF 等 PRD 格式必须验收。
4. **恢复与重试**：自动重试沿用原快照，手动重试使用最新设置；失败图片重试全部派生且不换 ID；停用后启用由所有者重试；连续无进展恢复有限；ready 重处理失败保留旧版本。
5. **回收与删除**：回收可恢复，已提交处理可继续而链接关闭；永久删除开始后不可恢复；部分删除失败保留记录及剩余对象，有限自动重试并支持手动继续清理。

本次确认不代表图片处理已经实现。十份业务规格现均完成产品评审，代表原型已补充；当前展开有明确前置的实施任务。
