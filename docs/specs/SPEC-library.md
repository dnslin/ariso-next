## 1. 目标与职责

所有者可以在同一图库查询正常图片，包括私有、处理中、失败和存储停用的图片；查看详情、已有版本和元数据；只对当前选择的图片执行批量操作。回收站保留记录并允许所有者管理预览，外链仍关闭，恢复和永久删除调用 media，不另外实现生命周期。

library 负责查询参数、分页/加载更多、界面偏好、选择范围、详情与大图查看、批量编排和逐项结果。图片字段/版本/任务归 media，关系/相册固定展示规则归 collections，存储状态归 storage，访问和链接归 delivery。查询可组合提供方的只读数据，修改必须调用提供方业务函数，不直接复制其校验或维护第二份图片索引。

不提供全站匿名图库、一次选中全部筛选结果、批量 ZIP、文件替换、跨存储迁移、AI 搜索、拍摄参数搜索或新的媒体版本。library 不新增业务数据表或后台工作队列；浏览器偏好不写站点设置。

## 2. 工程与库能力依据

目前只有 runtime，没有图库路由、业务表或组件。沿用现有 Node/Next、Drizzle、Zod、Pino；PRD 指定的 HeroUI、TanStack Query、nuqs、Yet Another React Lightbox 尚未安装。实施时固定版本并验证 React/Next 兼容性，不用文档示例版本替代实际锁文件。

- [TanStack Query 分页](https://tanstack.com/query/latest/docs/framework/react/guides/paginated-queries)用于请求缓存和加载状态。筛选/排序/范围/页码必须进入 query key；切网格与瀑布流不改变数据 key。新查询加载时若暂显旧数据，必须禁用旧数据的选择和操作，不能把旧图当新查询结果。
- [nuqs 参数选项](https://nuqs.dev/docs/options)用于解析 URL 和浏览器历史。搜索输入先本地编辑，提交搜索、应用筛选和翻页才写一条历史；后退恢复已应用查询，不为每个输入字符创建历史记录。
- [Lightbox 文档](https://yet-another-react-lightbox.com/documentation)及 [Zoom](https://yet-another-react-lightbox.com/plugins/zoom)提供前后切换、缩放/平移，按 imageId 保持当前图片身份；不启用 Download、Share、Slideshow 插件。
- [Fullscreen](https://yet-another-react-lightbox.com/plugins/fullscreen)使用浏览器全屏能力。部分移动浏览器不支持时，仍提供占满视口的查看器，不显示无效的系统全屏按钮；不能因此取消手机缩放和平移。
- 加载更多使用顺序值与 ID 的游标查询，避免深处反复跳过前面所有记录；这是 [SQLite 滚动窗口查询](https://www.sqlite.org/rowvalue.html)的已有用法。页码跳转仍使用有界 LIMIT/OFFSET，是否达标用真实十万图片数据验证。

本轮仅核对资料和现有目录，不代表浏览器、查询性能或这些依赖已经验证。

## 3. 页面、URL 与查询语义

页面为 `/library`、`/albums/{albumId}` 的图片内容及 `/trash`。同一套列表/详情组件承载三种范围。详情可通过当前页面 `image=<imageId>` 打开，直接进入 `/library?image=<id>` 也能查看正常图片；相册不包含该图或普通图库中的图已回收时明确提示，并给到合适管理入口，不伪造不存在的预览。

### 3.1 筛选与排序

| 参数                              | 语义                                                                                                                                              |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `q`                               | displayName 或 originalName 命中完整输入子串；去首尾空白，空值不筛；不拆词、不把 `%`/`_` 当通配符；ASCII 英文大小写不敏感，其他字符按保存文本匹配 |
| `albumId`                         | 图库中单个相册 ID；相册内容页由路径固定，不能再指定不同 albumId                                                                                   |
| `tagId`（重复参数）               | 一个或多个真实标签 ID；匹配任意一个选中标签，重复 ID 去重；不会因同名新建而绑定新标签                                                             |
| `uploadedFrom` / `uploadedBefore` | UTC 时间区间，前者含、后者不含；可以单边，两个均有时必须开始早于结束                                                                              |
| `format`                          | media 已识别的原文件格式枚举，不按扩展名、压缩结果或下载格式筛选；具体格式键见下表                                                                |
| `storageId`                       | 真实存储 ID，含停用存储；不因为停用从筛选项消失                                                                                                   |
| `visibility`                      | public/private；省略全部                                                                                                                          |
| `status`                          | pending/processing/ready/failed；只匹配图片 processing_status，不把重处理任务失败或存储停用当图片 failed                                          |
| `sort`                            | 图库 uploaded_desc（默认）/uploaded_asc/size_desc/size_asc；size 为原文件字节数，不取总占用或派生大小                                             |
| `pageSize`                        | 20/40/80，默认 40；写 URL 以便复制查询时一致                                                                                                      |
| `page`                            | 分页模式正整数，默认 1；加载更多不使用它                                                                                                          |

格式筛选按以下原文件家族统一，不新增派生格式索引；卡片仍可显示更具体的动画/页数信息：

| format 键         | 包含                                                                     |
| ----------------- | ------------------------------------------------------------------------ |
| jpeg / png        | JPEG（含 jpg 命名）；PNG 与 APNG，选择器标明 PNG/APNG                    |
| gif / webp / avif | GIF 静态与动态；WebP 静态与动态；AVIF 静态、动态及多图容器，各属对应家族 |
| heif / tiff       | HEIC/HEIF 的单图与多图；TIFF 的单页与多页，选择器明确家族名称            |
| bmp / ico / svg   | 对应实际识别的 BMP、ICO、SVG                                             |

尚未可靠识别格式的图片显示“格式待识别”，无格式筛选时正常出现，有具体格式筛选时不猜测归类。回收站删除状态使用 `deletionStatus=none/deleting/cleanup_failed`，默认不筛；回收排序固定 `trashed_desc`。页面不提供的范围参数由对应 scope schema 拒绝，不静默忽略。

同类多个标签之间取并集，不同种类条件之间取交集，名称的两个字段之间取并集。所有排序用 imageId 升序作固定次级排序；游标谓词与混合升降序完全一致，不能只比较主排序值造成漏项。查询不因私有/failed/存储停用而省略正常资产。

时间选择器按当前站点时区显示日期；用户选“9 月 1 日至 9 月 3 日”，转换为当地 1 日开始到 4 日开始的 UTC 区间，处理夏令时而非固定加 24 小时。URL 保存解析后的绝对时刻，复制和以后改站点时区不改变这个区间；显示当前时区及边界。站点时间转换复用成熟时区能力，不能自己写固定偏移表。

相册内容固定按 collections 的加入时间降序、图片 ID 升序展示，不接收 sort 参数。普通图库的 sort 只影响本次查询；在图库中筛选 albumId 仍属于图库查询，不修改相册规则。相册中的搜索/筛选只取固定顺序的子集。回收站默认回收时间倒序、ID 升序，提供名称/原存储/原处理状态及删除状态筛选，不开放重命名或修改关系以改变恢复结果。

已删除的相册/标签/存储筛选引用返回明确失效结果，保留 URL 供用户看见并移除条件，不能静默去掉条件后展示更广图库。语法错误或非法枚举返回 400，页面给出重置入口，不在后台操作接口悄悄采用默认值。UI 状态与 HTTP schema 共用定义。

### 3.2 偏好与历史

首次网格 + 加载更多；网格/瀑布流、分页/加载更多分别存浏览器 localStorage。不可用时使用当前会话内偏好，不影响读取图片。不同浏览器复制同一筛选链接时可以采用各自布局偏好，查询条件和排序必须一致。

切布局只重新排已有卡片，不重新请求已加载列表，不丢筛选、排序或选择。切加载方式保留查询，回到第一页并清空选择。改变每页数量、筛选或排序同样回到开头；本地历史前进/后退重新应用完整参数。image 参数开关只打开/关闭详情，不触发列表重新查询。

加载更多的已加载页和滚动位置可在当前页面会话缓存内恢复，但刷新或跨浏览器链接只保证恢复筛选/排序及第一批；不在 URL 存数千图片 ID，也不逐批自动重放所有历史加载。分页 URL 可恢复指定页，越过末页时返回空结果和实际总数，提供回到有效页入口。

## 4. 查询结果与十万图片规模

列表只返回本页轻量信息：ID、displayName/originalName、原图大小和格式、展示比例、visibility、processing_status、当前活动/最近失败任务摘要、storageId/名称/启用、版本存在性及 thumbnail URL、回收/删除状态和操作可用原因。完整分组元数据不塞进每张卡片；详情单独获取。对象 Key、凭据和永久 S3 地址不是列表链接。

同一图片命中多个所选标签也只出现一次。列表、总数及筛选使用同一谓词，计数不因多标签或多相册联表重复图片。关系过滤用 EXISTS 或按图片聚合后判断，不用 DISTINCT 掩盖错误联表。分页数据和总数在同一短只读事务取一致视图；事务内不请求文件或 S3。

普通分页返回 items/total/page/pageSize；加载更多返回 items/total/nextCursor/hasMore。cursor 只包含需要的排序值与 imageId，并绑定规范化查询及对应范围的展示规则；它不是权限凭据，不加签名系统，但服务端必须校验结构、范围和对应查询。查询参数改变后旧 cursor 无效。

翻页与加载更多不承诺跨多个请求的数据库快照。自己提交的修改更新已加载卡片并重算查询归属，删除/移出/恢复后移走不再匹配的项；分页重取当前页，加载更多在仅移除成员或图片离开筛选时保留原服务端游标中的排序值，不用当前最后一张卡片猜新边界；若修改当前图库查询使用的排序字段，则作废游标并从首批重载。只有查询筛选/排序规则等身份改变才按第 7 节清空选择；仅数据位置变化或游标失效，保留仍属于同一查询的显式选择，不因重载首页清掉其他页。新上传或其他窗口引起排序集合变化时提供刷新提示，重新开始查询再获取最新顺序，不偷偷替换整屏导致选择错位。加载结果按 ID 去重，不能把去重等同于保证并发变化下绝无漏项。

查询使用 media、collections、storage 的索引字段；需要的索引由表所属模块迁移维护，不建立所有筛选组合的索引。至少验证上传时间/大小排序、单相册/多标签、状态/存储、深页和混合条件。名称子串搜索先使用参数化查询，不默认引入全文服务；若十万规模未达标，再依据执行计划选择 SQLite 能力，不能声称普通前缀索引已优化任意子串。

每请求最多 80 张列表；已加载大量卡片采用可验证的虚拟化或分段渲染，维持文档/键盘顺序、选择和焦点。使用真实尺寸占位、懒加载 thumbnail；不先下载原图再缩小，不对每张卡片单独查关系/读文件/HEAD S3。Lightbox 图片请求同样不通过 Next 图片优化代理绕过 delivery。

工程验收基线建议在记录 CPU/内存/磁盘的 Docker 环境，用十万图片及真实密度关系数据，热查询 p95 ≤500ms、冷查询 ≤2s；这些是待测工程目标，不是当前性能结论。记录首屏、深页、复杂筛选和持续加载的浏览器内存，不以空库演示代替规模验收。

## 5. 详情与可操作状态

详情显示 ID、显示名/原始名、格式、尺寸、原图大小、上传时间、公开/私有、存储、相册/标签、当前处理状态、失败步骤、已有版本及各版本实际编码/尺寸/大小。处理和存储是独立信息，不能用一个红色“失败”混为一谈。相册和标签可从这里调用 collections 修改；回收后的详情只读记录并允许所有者管理预览，不修改恢复信息。

显示名称编辑提议为去首尾空白后 1–255 个 Unicode 码点，禁止控制字符，纯文本；可保留用户自己写的点和后缀。只更新 display_name，不改 original_name、原图、Key 或图片 ID。visibility 修改只作用选中图片，不改变默认设置。

字段写入由 media 提供 `updateImageFields(tx, imageId, patch)`：只允许 displayName/visibility，验证资产存在且正常库、未开始永久删除；允许 failed 和存储停用的元数据修改。相同值无变化成功；真实异常保留原因。library 不新建平行的图片更新逻辑。

| 状态                        | 展示与操作                                                                                                |
| --------------------------- | --------------------------------------------------------------------------------------------------------- |
| 正常 ready                  | 已保存缩略图、详情、逐版本查看/下载、关系/名称/可见性、重新处理、回收                                     |
| pending/processing/failed   | 保留卡片；有已保存可读 thumbnail 才展示，否则状态占位；所有者可读已存版本，候选不可读；活动任务不重复提交 |
| ready 正在重处理/重处理失败 | 图片仍 ready、旧版本继续可读，任务状态单独列出；不能混入初次处理 failed 筛选                              |
| 存储停用                    | 名称/状态记录可管理，图片/下载/新处理不可用，统一“存储已停用”占位；恢复存储不自动重试任务                 |
| 回收站                      | 所有者可看管理缩略图和详情预览；无内容外链、下载或 Lightbox，允许恢复或开始永久删除                       |
| deleting/cleanup_failed     | 仍在回收站，不可恢复；清理进度/剩余对象/错误可见，失败可重试清理                                          |

元数据详情按 media 提供的完整分组 JSON 展示，保留结构与值；可以折叠/搜索已取回的字段，不扩展为全图库 EXIF 检索。读取失败说明旧内容是否存在，单独重新读取不重新生成版本。公开原图可能含 GPS 等信息的提示沿用已批准规则，不增加确认拦截。

列表/详情有活动媒体任务时，可见页面按需批量查询其状态，终态停止；每次状态查询最多 80 个 ID，多个批次有界排队，不每张图独立轮询。状态更新保持其他卡片和选择；若图片不再匹配当前筛选，从可操作集合移除。注销或会话失效清除私有管理查询缓存，不能回退成匿名管理查询。

## 6. 大图查看

### 6.1 默认展示提议

卡片始终使用已有 thumbnail。点击大图时，默认展示与站点默认外链分开：

- 普通静态图片优先已有且浏览器可显示的 compressed；没有时使用可显示的 original；两者都不能显示时使用现有 thumbnail，并明确标注预览。不临时生成新版本。
- 动画 GIF/APNG/WebP/AVIF 优先 original 保留动画；浏览器不能解码时明确提示并可手动查看静态预览，不能把静态预览标为完整动画。
- SVG 一律现有 WebP thumbnail，不内联或打开 SVG 原文；ICO、多页容器使用 media 的既定预览，HEIC/TIFF 等不保证原图可在所有浏览器解码，使用现有可显示派生或预览。
- 初次处理失败时只选择已保存可读的版本；存储停用或全部无可读版本则占位。网络或真实文件读取错误直接显示错误，不因加载失败悄悄换版本。

“自动预览选择”是界面展示规则，不修改 delivery 的默认/显式 URL 规则。详情中用户明确点选原图、压缩图、水印图或缩略图时，只查看指定版本，缺失不得回退；可选择的浏览器可显示版本也可带入 Lightbox。下载全部留在详情页。SVG 的明确原图入口标为附件下载，不能在用户选择原图后悄悄改成 thumbnail；自动预览与这个入口分别说明。

用户另要求在集中补 Figma 时设计方便的版本切换入口：在同一张图片的详情/大图中可直接选择已有原图、压缩图、水印图或缩略图，清楚标出当前实际版本、格式和大小；缺失/不适用版本说明原因，不伪装可点。切换不要求退出后重新打开图片，不改变全站默认外链。SVG 原图等只能下载的版本给明确附件说明，下载仍留详情。桌面控件与手机紧凑选择器的具体视觉形式在设计阶段评审，不新增对比编辑或第五种版本。

### 6.2 导航、交互与权限变化

前后切换沿打开时当前图库/相册筛选及排序，支持跨页按需取相邻图片，不一次加载全部筛选结果，也不改变底层列表页码或选择。直接链接详情没有列表上下文时，仅查看当前图片，不猜测用户要浏览全库。当前图片已经删除而无法定位时，使用已有相邻窗口或提示刷新，不能猜它原来的排序位置。

通过服务器邻居查询按当前 imageId 和同一规范化查询定位前/后项；首尾不循环。Lightbox 只保留当前与相邻窗口，最多预加载前后各一张；请求身份都走 delivery。切换按 imageId 保持焦点，不能因为 slides 数组重建跳回第一张。关闭返回原列表位置与触发控件；原图卡片已移除时焦点回列表工具栏。

支持键盘左右/关闭/缩放、鼠标缩放/平移、触摸缩放/拖动及全屏；放大后的平移与切图手势不相互抢占。文本框和弹窗内的方向键不触发底层导航，减少动态效果设置仍可完成所有功能。没有 Download/Share/Slideshow 按钮。

打开后图片变私有，对有效所有者仍可读；变回收、开始删除或存储停用后，下一次状态更新关闭当前内容并显示原因。邻居仍存在可继续切换；不再符合查询时提示刷新该浏览上下文。不能撤回已经下载到浏览器或仍有效 S3 签名中的字节，此边界沿用 delivery，不额外保证“已经显示的像素瞬间消失”。

## 7. 选择与批量操作

“全选当前页”只把当前页图片加入已有选择；取消当前页全选只移除当前页，不清掉其他页已选项。加载更多模式只全选已加载图片，后续新加载项不自动选中。另提供“清空全部选择”。selectedIds 保存在本次页面会话内，不写 URL/localStorage，刷新后不恢复，不提供全筛选结果全选。

已确认：同一查询的上一页、下一页、跳页以及仅改变页码的浏览器前进/后退保留选择，回到原页恢复勾选。改变筛选/排序/每页数量、切加载方式或换相册/图库/回收范围时清空选择；单纯换网格/瀑布流或打开/关闭详情保留。查询身份排除 page/image，包含实际筛选、排序和范围。图片只是位于其他页不能取消选择；确认已删除或不再满足当前查询时才移除该项，并说明原因。

工具栏展示“共选 12 张：当前页 2 张，其他页 10 张”，允许查看/移除已选项及清空全部选择。批量操作和确认框按总数执行，明确包含其他页。仅保存所选 ID 和名称/排序等轻量信息，不为保留选择预加载所有页面或图片文件。

点击操作时固定“本次选中 IDs + 明确操作参数”，之后新增/加载图片不加入这次操作。UI 展示目标数量、目标相册/标签或公开状态等；永久删除必须确认不可恢复和实际选中数量，沿用已有删除确认，不新增输入短语验证。

| 批量命令          | 规则                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ |
| 加入/移出相册     | 多个明确相册 ID；普通图库移出需选择目标，相册页默认当前相册；每张图的多个关系在一次短事务中修改                    |
| 添加/移除标签     | 真实标签 ID，网页快速创建后再引用；重复添加/已无关系为无变化成功                                                   |
| 设公开/私有       | 调用 media 更新当前图，不覆盖其他字段；停用存储不阻止记录修改                                                      |
| 移入回收站/恢复   | media 状态函数；回收仍占空间，恢复保留幸存关系，不重建已删除目标                                                   |
| 永久删除/重试清理 | 仅回收站；成功受理返回任务，不把任务受理写成文件已清完；已在 deleting 不重复创建                                   |
| 重新处理          | 逐图调用 media；失败图只接受全部派生，ready 可选既定四范围；混合图选“仅水印”时 failed 项单独冲突，不能偷偷改为全部 |

批量重处理按每张任务被受理时的最新设置创建不可变快照，之后执行不再改动；后续 HTTP 分批请求若设置已变，使用新设置，不承诺跨所有分批共用同一快照，也不为此新增批次系统。

批量请求每次最多 200 个明确 ID，更多已加载或跨页保留的选择由客户端按固定选择清单分批提交；不是把选择范围限制为 200。每张图独立事务或提交自己的持久任务，一项失败继续下一项；不让一千图片变更包在一个长事务中。请求之间让出执行时间，数据库事务内不等网络或工具。

响应逐项区分 changed/unchanged/accepted/failed，任务受理带 taskId。整体 200 表示逐项结果已返回，页面仍必须标出失败和处理中；顶层鉴权/结构错误才整体失败。受理的任务关闭页面后继续；尚未发送的分批操作不会由服务器猜测补发，不需要新建通用批量任务引擎。

完成后 changed/unchanged/accepted 项从整个选择集移除；失败项只要仍属于当前查询就保留选择，包含其他页，并在已选清单与结果中说明。已经删除或不再满足查询的失败项移出选择但保留结果说明；不能只因不在当前页就丢弃。网络断开/响应丢失时先查询相应资产/任务核对，不自动重发“重新处理”制造新任务；不能核实时显示结果待核对。

批量请求携带本次规范化查询范围；每个请求都重新检查所有者、各图片当前状态及其是否仍属于本次查询，失效项逐项返回原因，不能用弹窗打开时的可操作标记授权。上传 Token 和分享 Cookie 均不能使用这些命令。

## 8. 批量复制与逐版本下载

复制格式为 URL/Markdown/HTML，默认模式不带 type，明确选具体版本才带 type；一次选择统一模式。按当前查询在完整结果中的展示顺序输出，包含其他页的已选项，一张一行，瀑布流视觉分列不改变数据顺序。相册顺序由 collections 决定，不能按选中先后或 ID 重新排序。

客户端每次提交最多 200 个明确选中 IDs、同一规范化查询及版本/输出格式；服务器检查当前查询归属，返回每个有效项的展示排序键与已转义文本行。客户端按完整比较规则跨批排序合并后一次复制，不按访问页次、点击顺序或网络返回先后拼接。服务器逐项调用 delivery 的解析与链接生成能力，检查现存版本和可访问状态；不为复制进行 GET、签名或访问计数，也不逐张 HEAD S3 来声称远端必然可读。返回可复制文本和不可复制列表，包含 imageId、显示名、原因与实际解析版本。

显式版本缺失或格式不适用不回退；默认版本只允许 delivery 已批准的格式不适用→原图规则。当前默认适用却缺失、已回收/删除、存储停用的项不输出链接，其余项继续。private 或正常库 failed 的已有版本可以为所有者生成链接，但清楚说明外部访客无权访问；链接生成不是授予公开权限。

Markdown/HTML 的 alt 使用 displayName，按目标语法转义中括号、引号、尖括号、换行等；URL 使用 delivery 的编码规则，不能把任意名称拼成可执行 HTML。全部失败时不覆盖剪贴板。浏览器拒绝 Clipboard 写入时显示可选择文本和手动复制，不能先 toast 成功。

详情提供每个已存版本独立下载，文件名和 SVG 附件遵循 delivery；缩略图用于预览不冒充原文件。复制后版本/权限仍可变化，结果只描述生成时检查，沿用稳定外链边界。

## 9. 回收站与状态恢复

2026-09-26 用户明确批准回收站管理预览，取代原“所有者也只看记录占位”的规则。列表在已保存名称/大小/原存储/原可见性/处理状态/回收时间旁显示可读缩略图；详情保留记录并复用图库预览组件。仅有效所有者 Cookie 可通过管理预览路由读取已保存版本；匿名、API Token 和分享授权不构成该权限。原 `/i/{id}` 所有版本仍拒绝回收图片，包括所有者。存储停用、deleting、cleanup_failed 或无可读版本时保留占位和原因，不临时生成版本，不静默换版。没有 Lightbox、复制内容外链、版本下载或新重处理入口。Figma 不修改，新增预览属于用户明确批准的设计变化；冻结 PRD 保留原文，此处记录当前已批准契约。

恢复沿用 imageId 和原 visibility；存储停用时允许恢复记录，仍显示停用占位；原关系和顺序按 collections 恢复，已删目标跳过。后台处理已完成时显示其实际结果，不把回收时旧 processing_status 覆盖回来。

永久删除按 media 排队/执行/cleanup_failed 展示，剩余未清对象及错误可见。deleting 和 cleanup_failed 不允许恢复；只能等待或重试清理。只有全部对象清理成功后列表项消失，不能请求刚返回 202 就从数据库/UI 永久抹掉。

选中项批量恢复/永久删除遵守第 7 节范围；首版不新增“清空所有筛选结果”入口。回收站无自动清理天数，不把 upload 临时会话到期规则应用到回收图片。已开始永久删除的图仍占真实存储引用，不能替 storage 提前解除阻塞。
