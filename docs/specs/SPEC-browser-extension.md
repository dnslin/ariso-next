# Ariso 浏览器插件首版规格

- 日期：2026-10-25。
- 状态：用户已认可简约原型并授权实施；Chrome 首版与后台能力接口已实现，实际验证及边界见[实施记录](../verification/browser-extension/README.md)。未部署生产，项目全量检查仍有并行工作未关闭项。
- 浏览器边界：用户明确不希望安装或使用 Edge，本轮只交付和验收 Chrome；原有两浏览器计划由此修订。
- 图标修订：用户不喜欢通用多图图标，改用 Ariso 内置 Caveat「A」品牌标识，页眉去掉重复图形。
- 界面修订：用户反馈“这个插件好大呀，一点都不简约”。下文紧凑小窗方向替代上一轮完整上传工作台布局，核心上传与错误语义不删减。
- 目标：无需安装 PicGo，在浏览器中把图片上传到自己的 Ariso，并取得可使用的图片链接。
- 本文描述一个上传客户端能力，不新增图库管理、远端抓取或另一套媒体处理系统。

## 1. 定位与首版范围

首版建议覆盖桌面 Chrome，采用 Manifest V3，即当前浏览器扩展的清单与运行规范。Firefox、Safari 和移动浏览器另行安排，不从框架支持推定已经兼容。

插件连接用户配置的 Ariso 站点，不依赖本机 PicGo、Node.js 或辅助服务。开发环境需要 Node.js，普通使用者不需要。

| 能力     | 首版建议行为                                                                          |
| -------- | ------------------------------------------------------------------------------------- |
| 连接     | 填写站点最终根地址和专用上传 API Token，测试后保存。界面沿用 Ariso 的“上传 Token”名称 |
| 本地图片 | 多文件选择、拖拽、在插件小窗中主动粘贴图片，进入同一个队列                            |
| 网页图片 | 图片右键菜单“保存到 Ariso”，打开或聚焦同一小窗，获取图片后进入同一个队列              |
| 上传反馈 | 每项分别显示待上传、传输中、等待服务器结果、完成、失败或结果待核对                    |
| 输出     | 复制 URL、Markdown、HTML；批量复制已取得有效链接的结果                                |
| 可见性   | 建议支持公开／私有，初始读取站点默认值；开始上传前明确展示本次选择                    |
| 私有图片 | 可上传，但明确提示需登录 Ariso 才能访问；不把返回地址包装成可匿名使用的配图链接       |
| 上传设置 | 默认存储；高级设置允许手填存储 ID、一个默认相册 ID、一个默认标签名称                  |
| 链接版本 | 站点默认、原图、压缩图、水印图；使用响应中真实存在的版本地址                          |

截图、整页采集、扫描整页图片、自动识别原图、监控剪贴板、自动替换网页编辑器内容、多站点切换、图库浏览和远端删除均后置。相册和存储下拉列表需要额外读取接口，不纳入首版。

## 2. 已核对的现有能力

| 当前依据                                                     | 结论                                                                                             |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| [上传 Token 验证](../../src/server/identity/tokens.ts)       | 现有 Token 验证仅接纳 `POST /api/upload`，权限为 `upload:create`；不能用来登录后台或读取管理接口 |
| [公开上传入口](../../src/server/upload/public-http.ts)       | 单文件表单上传，先验证 Bearer Token，再接收文件                                                  |
| [请求与响应契约](../../src/server/upload/public-contract.ts) | 支持存储 ID、重复相册 ID、重复标签和公开／私有；返回图片 ID、版本、处理警告及请求 ID             |
| [完成等待](../../src/server/upload/public-result.ts)         | 等本次处理完成才返回成功；交接后的默认等待预算为 900 秒                                          |
| [上传规格](./SPEC-upload.md)                                 | 不接受远程 URL，不提供公开状态轮询或通用幂等键；断连不能据此判断图片未创建                       |
| [PicGo 结果处理](../../integrations/picgo/lib/result.cjs)    | 只在真实成功且所选版本存在时输出链接，不默默改用其他版本                                         |

当前工作区还有尚未提交的重复检测改动：`409 / UPLOAD_DUPLICATE` 不返回已有图片 ID 或链接。插件应显示“已存在，未新增，请到图库查看”，不得猜测旧图地址。正式实现前应核对这些改动是否已经合入目标版本，本文不把工作区行为当作线上承诺。

## 3. 用户流程与页面

### 首次连接

1. 点击扩展图标，打开紧凑插件小窗；尚未配置时进入设置视图。
2. 输入 Ariso 最终根地址和专用上传 Token。
3. 点击“测试并保存”，由浏览器请求该站点访问权限，再验证 Token 和上传能力。
4. 显示连接结果、单图大小限制和默认可见性。Token 错误、站点不存在与接口不支持分别提示。

站点使用最终 HTTPS 根地址，不依赖登录或域名重定向。本地开发允许 localhost HTTP。首版要求服务端具备本文建议的能力查询接口；旧站点明确提示升级，不假装已经验证 Token。

### 本地与剪贴板上传

选择、拖拽或粘贴图片 → 检查文件及大小 → 预览队列和本次设置 → 点击“开始上传” → 逐项等待结果 → 复制链接。

粘贴只读取用户本次粘贴事件中的图片 File／Blob，不读取文字 URL，不持续监听系统剪贴板。网页中复制的图片若只提供文字地址，提示使用右键保存或选择本地文件。

### 网页图片右键保存

图片右键“保存到 Ariso” → 同一插件小窗接收浏览器提供的图片地址 → 必要时点击授权来源域名 → 插件获取图片文件 → 预览并确认可见性 → 调用相同上传流程。

建议首版仍由用户点击开始上传，避免把私有网页图片意外公开；后续可根据实际使用反馈决定是否提供显式开启的一键上传。

来源地址和 Ariso 上传地址是两个不同的请求目标。来源请求绝不带 Ariso Token。Ariso 后台只接收文件，不代替插件下载网页图片。

首版承诺普通、可直接获取的 HTTP(S) 图片。需要站点登录、存在防盗链、地址失效、来源拒绝访问、`blob:`、画布或 CSS 背景图时，明确说明不能获取，并保留本地文件／粘贴入口。不承诺浏览器看得见就一定能保存。

### 界面组成

日常界面按约 360px 宽的小窗设计：顶部只保留 Ariso 小标题和设置图标，中间是拖入／粘贴／选择入口及紧凑图片列表，底部提供上传和复制。移除大标题、全页导航、右侧设置栏和宣传说明卡，不再要求使用全屏工作台。

连接、默认相册、标签、存储、链接版本和主题收进设置视图。公开／私有、上传中、失败和结果待核对等必要状态仍应在操作处看得见，不能用界面精简隐藏实际后果。网页右键保存汇入同一小窗和队列，不再要求进入大型页面。

视觉小窗与请求运行位置分开处理：实际请求仍由扩展页面承载，正式版建议把该页面放在同尺寸、可持续打开的小窗中。不得假定普通 action popup 关闭后仍能等待长上传；具体窗口创建、聚焦和生命周期在正式扩展阶段验证，尚不是原型已证明的能力。

上传期间承载请求的小窗需要保持打开，可以切换到其他浏览器页面。关闭、刷新、浏览器退出或页面被回收可能打断客户端请求；服务端已接收的处理仍可能继续。首版不承诺关闭窗口／浏览器后继续上传或自动恢复文件队列。

文件传输完成后显示“等待 Ariso 处理”，不能把 100% 传输进度当作图片保存成功。获取失败与上传失败分开显示，批量操作保留每项真实结果。

## 4. 技术方案

建议采用 WXT、TypeScript、React。WXT 负责扩展入口、开发和打包；保留项目现有 Tailwind CSS、HeroUI 与图标来源规则，不把 Next.js 管理后台整体装进扩展。

上传队列优先复用项目已有 `@uppy/core` 与 `@uppy/xhr-upload`。已核对本地类型和官方文档：支持上传进度、并发、表单字段白名单、自定义响应解析和 `shouldRetry`。无需重新实现一套通用队列。

| 位置                    | 责任                                                         |
| ----------------------- | ------------------------------------------------------------ |
| 扩展后台 Service Worker | 注册右键菜单、转交任务、打开／聚焦小窗；不执行长时间上传     |
| 小窗内的扩展页面        | 来源图片获取、文件队列、上传请求、进度、结果和复制           |
| 设置模块                | 单个站点、Token、默认选项和浏览器域名授权                    |
| Ariso HTTP 客户端       | 调用公开契约，解析成功、重复、版本缺失和结构化错误           |
| Ariso 服务端            | 复用认证、上传、处理、重复检测和外链模块，仅补必要的能力查询 |

Chrome 官方说明，扩展后台的 fetch 等待响应超过 30 秒时可能被终止。现有 Ariso 同步接口不适合直接放在该后台执行。请求由小窗中的扩展页面承载，不以扩大界面解决运行限制，也不新增公开轮询或后台保活。实施时必须验证具体窗口方式、失焦、切换浏览器页面、最小化和长处理场景。

Uppy 建议配置：每次请求一个文件、不合并表单，并发 3；只发送现有 API 允许的字段；关闭自动重试，显式设置适合 Ariso 接收和处理预算的空闲超时，不沿用其 30 秒默认值。仅 `201`、`status=ready` 且响应结构有效才能报告上传成功。

复制站点默认版本时，使用本次响应解析出的实际版本地址。图片保存成功但所选版本不存在时，显示“已保存，所选版本不可用”；用户可选择已有版本，不自动替换成原图，也不重新上传。

插件只通过 HTTP 契约复用 Ariso，不导入服务端、数据库或带 Cookie 的管理上传控制器。PicGo 和扩展分别保留各自适配代码，当前不提前抽取通用 SDK。

## 5. 后台需要补的接口

建议增加 `GET /api/upload/capabilities`，用于真实测试 Token 和读取必要上传限制。它是拟新增接口，目前不存在。

- 认证：同一个上传 Bearer Token；复用现有 Token 验证能力，只明确新增此路径的允许范围，不让 Token 访问任意 GET 接口。
- 成功响应：`maxFileBytes`、`queueLimit`、`defaultVisibility`、`defaultLinkVersion`、`defaultStorageAvailable`、`requestId`。读取现有模块的数据，不复制一套配置；默认存储是否可用不等于实际写入测试。
- 不返回：相册／图片列表、存储配置、存储凭据、Token 原文或所有者资料。
- 错误：沿用公开上传的结构化 `error.code / stage / message / requestId` 和实际 HTTP 状态。Token 失效为 401，未初始化为 409；有合法 Token 但默认存储不可用时返回真实能力状态。
- 缓存：`Cache-Control: no-store`。上传仍逐次校验；测试通过不保证之后 Token 不会过期或存储不会停用。

这项变动需要同步 identity／upload 规格、OpenAPI、鉴权测试和用法文档。`POST /api/upload` 的接收、同步完成、私有访问和重复检测语义不变。首版无需数据库迁移、新登录协议、S3 直传或新增服务器抓图服务。

## 6. 凭据、权限与失败处理

Token 存入扩展本机 `storage.local`，限制为扩展自身上下文访问；不放 `storage.sync`、网页 DOM、页面脚本、地址栏或日志。本机扩展存储不等于系统钥匙串加密，界面不作加密保管承诺。Token 使用现有撤销入口管理，不另建密钥保险库。

初始权限仅为本机配置存储和图片右键菜单。Ariso 站点及来源图片域名通过 `optional_host_permissions` 按实际使用申请；声明可选域名范围不等于安装时获取全部站点权限。遇到 CDN 地址时，核对实际图片域名，不能只授权网页域名。

首版不读取浏览记录、Cookie 或全站 DOM，不注入常驻页面脚本。剪贴板使用用户主动粘贴和点击复制，实施时在 Chrome 验证相应权限需求。普通来源下载不带登录凭据，也不读取登录 Cookie。

网络断开、代理超时或主动中断后，若不能确认服务器结果，显示“结果待核对”，提供打开 Ariso 图库的入口。不得自动重传，也不得宣称取消客户端请求已经删除服务端图片。尚未开始的项目可以直接移除。

错误保留 HTTP 状态、阶段、请求 ID 和可用的图片 ID。渲染 Markdown／HTML 时正确处理文件名中的特殊字符；预览 SVG 不以内联 HTML 执行。复制失败时提供可选取的完整文本。

## 7. 建议目录、命令与代码约定

模块位于 `integrations/browser-extension/`，与 `integrations/picgo/` 平级。三个模块属于同一仓库的 pnpm workspace，各自声明依赖，共用根锁文件。扩展不加入 Ariso 服务端运行包，不导入后台实现；双方通过公开 HTTP 接口连接。组织和发布约定见[模块组织](../guides/modules.md)。

| 路径                        | 内容                                 |
| --------------------------- | ------------------------------------ |
| `entrypoints/background.ts` | 右键菜单及小窗启动                   |
| `entrypoints/workspace/`    | 小窗扩展页面入口，含上传与设置视图   |
| `components/`               | 上传、结果、连接设置组件             |
| `lib/ariso-client.ts`       | API 调用和响应转换                   |
| `lib/source-image.ts`       | 来源图片下载及来源错误               |
| `lib/settings.ts`           | 配置和扩展存储                       |
| `tests/`                    | 客户端、队列适配、设置、链接输出测试 |
| `wxt.config.ts`             | 清单、React 模块和构建配置           |

沿用项目 camelCase、TypeScript 类型和结构化错误。仅在外部接口边界解析响应，不在模块间层层重复验证。例如请求元数据直接对应既有字段：

```ts
const uploadMeta = {
  visibility: settings.visibility,
  ...(settings.albumId && { albumId: settings.albumId }),
  ...(settings.tag && { tag: settings.tag }),
};
```

已提供以下脚本，从仓库根目录执行；实际运行结果以验证记录为准：

```sh
pnpm install --frozen-lockfile
pnpm --filter ariso-browser-extension dev
pnpm --filter ariso-browser-extension lint
pnpm --filter ariso-browser-extension typecheck
pnpm --filter ariso-browser-extension test
pnpm --filter ariso-browser-extension build
pnpm --filter ariso-browser-extension zip
```

`dev`／`build`／`zip` 分别对应 `wxt`、`wxt build`、`wxt zip`。Node 版本沿用项目 Node 24，正式引入依赖时核对实际兼容版本。

| ---- | ------------------------------ | -------------------------------------------------------------------------------------------- |
| 1    | 站点连接与一张本地图片上传闭环 | Token 真验证；真实上传后读取返回版本；在图库核对图片与可见性                                 |

| 4    | 故障与浏览器打包验收           | 长处理、Token 撤销、重复、版本缺失、断网、关闭小窗、浏览器重启；Chrome 分别实测安装包        |

单元测试验证契约解析、链接格式、错误分类、配置和来源请求，不只检查函数调用。后台集成测试验证 Token 对新增能力接口的授权边界，并复用现有上传场景。浏览器验收加载真实扩展，与隔离 Ariso 实例完成上传和图库核对，不能用网页原型代替。

修改后的后台按[开发与发布验证](../guides/verification.md)执行适用检查；前端沿用[设计交付规范](../design/handoff.md)，记录约 360px 小窗、窄视口、深浅主题、键盘和各状态的实际证据。上一轮页面原型证据保留；新版截图和检查单独记录，不能沿用旧版 26 项页面检查作为新版通过结论。不得使用用户本机 Docker／Colima。容器检查只在 CI 或用户指定远端执行。

先交付可加载的扩展包做内部试用。商店发布另行准备图标、截图、权限说明和隐私说明；上传凭据和图片直接发往用户配置的 Ariso，不经过插件作者的中转服务。商店审核时间不计入可保证的开发时间。

## 9. 边界与待确认项

- 始终：复用现有上传与处理；保留失败诊断；用真实扩展验证 Chrome；不覆盖当前未完成计划和未提交代码。
- 需先确认：新增图库读取／删除权限、自动公开上传、关闭浏览器仍继续传输、多站点管理或额外后台协议。
- 禁止：把 Token 暴露给图片来源、用 Cookie 替代上传 Token、不确定时自动重传、把上传进度 100% 当成功、未经本轮请求部署生产。

已确认两类输入都进入首版，继续保留 Chrome 首发、右键后预览并点击开始、公开／私有选择和新增能力查询接口。根据用户对界面过大的反馈，日常交互改为紧凑小窗；新版尚待体验，具体窗口承载方式仍需正式扩展验证。原型的计时、站点、图片和结果都是示例，不是后台能力验证。
