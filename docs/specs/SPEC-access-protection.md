# 访问防护

用户于 2026-10-22 确认保留 S3 直连、有效所有者会话豁免的基础防刷方案，并批准 Tips 精简版原型进入开发。原型与批准范围见 [原型说明](../../design-plans/access-protection/README.md)。正式实施和验证证据另行记录，原型通过不代表功能验收通过。

## 目标与边界

减少匿名持续高频取图，保留正常浏览、外站嵌图和所有者批量下载。沿用单 Web 进程，计数保存在内存，重启清空。没有 CDN 依赖、Redis、访客指纹、验证码、按字节配额或全站自动停用。

本地图片和已有私有分享继续走原交付路径，公开 S3 图片继续返回 302 和 300 秒预签名地址。限频只能约束请求 Ariso 的频率；已签发 S3 地址可重复使用，不能用签发次数推算实际带宽或保证费用封顶。

## 设置与入口

独立单例 `access_protection_settings` 由数据库迁移建立并填入默认值，不借站点信息保存修改。

| 字段  | 默认值  | 规则                     |
| ----- | ------- | ------------------------ |
| mode  | observe | off / observe / enforce  |
| rate  | 10      | 每秒补充额度，正安全整数 |
| burst | 200     | 最大突发额度，正安全整数 |

所有者 `GET/PATCH /api/settings/access-protection` 返回 `{mode,rate,burst,updatedAt,clientIp:{ready,message}}`。PATCH 提交完整三个配置字段，沿用所有者会话、Origin 检查和有上限的 JSON 读取；结果禁止缓存。字段错误 422，JSON 错误 400，请求过大 413，来源 IP 未确认时开启拦截返回 409。保存后对后续请求立即生效，策略变化清空短期计数。

入口为基本设置的关联设置行，编辑页 `/settings/general/access-protection`。复用现有外壳、数字输入、Tips、固定底栏和保存/未知结果核对/未保存导航规则。所有者豁免固定，不提供开关。常驻文字仅保留短标签、单位、必要错误及“已登录所有者免于此限频”。完整规则与 S3 边界收进 Tips。

## 限频语义

- `/i/{imageId}` 与 `/s/image/{token}/media` 的匿名 GET/HEAD 共用按 IP 的令牌桶，不按路径、图片、版本、查询或分享另开额度。
- 初始满额 200，按单调时钟每秒补回 10；GET、HEAD 各消耗一次。拒绝不消耗额度、不延长恢复时间。完全空闲 20 秒后可恢复满额。
- off 不计数；observe 执行相同判断并记录潜在超限，但放行；enforce 在超限时返回 429、`Retry-After: 1`、`Cache-Control: private, no-store, no-transform`，HEAD 不带正文。
- 在打开文件或签发 S3 地址前执行限制。已经开始的文件传输不因后续请求超限被中断。
- 规则只针对匿名媒体入口；登录、管理、上传、内部处理和所有者 ZIP 不计入额度。
- 每个 IP 的超限日志按 30 秒采样，明确标记 would-block / blocked，包含 IP、模式和阈值；不记录分享 Token 或签名 URL。日志是采样事件，不当作完整下载次数或账单。

## 所有者与权限

入口先验证真实所有者会话。有效会话不消耗匿名额度，同 IP 匿名额度耗尽也不影响所有者。HEAD 预检与 GET 下载都适用。

仅凭 Cookie 存在、同一 IP、Referer、User-Agent、分享密码或上传 Bearer Token 不能得到豁免。豁免只影响本规则，不绕过私有/回收/删除/分享到期/存储停用等原有判断。认证故障继续按原错误处理，不能默认为所有者或匿名成功。

## 真实 IP

Node HTTP 适配器先清除外部提供的内部地址头，再从 socket 和显式可信代理链取得地址。模块内使用 Node `SocketAddress` 规范化 IPv6 / IPv4-mapped 地址，使用 `BlockList` 匹配代理 IP/CIDR，不新增 IP 解析依赖。

环境变量 `ARISO_TRUSTED_PROXIES`：

- 未设置或留空：来源尚未确认，允许关闭和观察，设置 API 不允许开启拦截。
- `none`：部署者明确声明没有前置代理，只使用 socket 地址，忽略转发头。
- 逗号分隔 IP/CIDR：仅信任这些代理；从 socket 和 `X-Forwarded-For` 右侧向左找最近的不可信跳点。遇到第一个不可信地址即停止，忽略其左侧可由访客伪造的内容。

不支持自动信任所有代理或固定“取第一个 XFF”。更换部署须保留正确配置。已保存 enforce 却无法解析本次连接来源时，匿名媒体请求明确返回 503 并采样记录原因，不合并成 unknown 桶或让畸形头免限流；所有者和管理入口仍可使用。关闭或观察模式不会因此阻止图片读取。

此边界依赖标准启动入口加载 HTTP 适配器，沿用项目已经要求的 `pnpm start` / `entrypoint.sh`，不直接运行裸 `server.js`。

## 验收

| 类别       | 必需证明                                                                              |
| ---------- | ------------------------------------------------------------------------------------- |
| 确定性计数 | 固定时钟下前200次通过、第201次拒绝；100ms后可通过1次；拒绝不延后恢复；不同IP隔离      |
| 正常匿名   | 41张首屏、80图双页共160、同出口四页各41共164请求不被拦；正常分批滚动与预读            |
| 真实身份   | 伪造Cookie/Bearer不豁免；匿名额度耗尽后owner80图读取、单图HEAD/GET、上传和管理仍可用  |
| 外链       | 外站真实img加载本地和S3，不要求Cookie、Referer或JS验证码                              |
| S3         | 仍302和300秒签名；浏览器直接向对象端获取文件；重复签名下载不经过Ariso                 |
| ZIP        | 200张本地、S3和混合来源分别下载并解包校验文件字节，无匿名额度消耗                     |
| IP         | 外部伪造内部地址头无效；不可信连接伪造XFF无效；可信链从右向左解析；映射地址共用同一IP |
| UI         | 批准原型一致；桌面/手机浅深色、Tips点击/键盘/回焦、字段校验、保存/失败/核对/会话恢复  |

实际执行结果放在 `docs/verification/access-protection/`，区分本地协议服务、真实对象存储、浏览器视口和用户人工验收。
