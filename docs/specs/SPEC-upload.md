## 1. 目标与职责

所有者可以选择、拖入或粘贴文件，检查队列后手动开始上传。浏览器最多同时传输 3 张；每张独立成功、失败或取消。文件安全交给 media 后进入不可取消的服务端处理；Web 显示过程，通用 API 等真实结果返回。传输成功不等于图片 ready。

upload 拥有队列、提交设置、上传会话、接收前文件、S3 临时对象和交接前正式对象的清理责任。media 拥有已接收图片及处理，collections 拥有关系，storage 提供对象操作，delivery 提供链接与版本解析。对象责任必须在同一数据库事务转交。

不增加匿名上传、公开状态查询 API、断点续传、远程 URL 导入、文件夹层级存储、内容去重、上传后替换原图、Companion 服务或独立 Worker。S3 多段上传不在当前直传协议中；HTTP 的 multipart/form-data 与 S3 多段上传是两回事。

## 2. 现有工程与依赖依据

当前仅 runtime；没有上传入口或表。沿用 Node 24、Next Route Handler、Drizzle/better-sqlite3、Zod 4 和 Pino。传输入口使用 Node runtime，业务数据库与恢复调度接入现有 Web 进程单例，事务内不 await。当前包清单未安装 Uppy、S3 SDK 或流式 multipart 解析器。

- [Uppy core](https://uppy.io/docs/uppy/)提供队列和文件状态，使用 `autoProceed: false`，按 Figma 组合界面；不启用 Golden Retriever。文件 MIME 仅供初筛，终态移除 Uppy 中的文件数据，轻量结果另存。
- [Uppy AWS S3](https://uppy.io/docs/aws-s3/)支持单 PUT；显式关闭自动多段上传，服务端签名，不把凭据交给浏览器。固定实际发布版本后核对签名回调类型，不能混用旧版示例。
- [Uppy XHR](https://uppy.io/docs/xhr-upload/)用于本地/中转单文件请求，关闭自动重传；只发送明确元数据。两个传输插件共用一个并发上限，不能分别设 3 后实际变成 6。
- multipart 需要流式解析。[Busboy](https://github.com/mscdex/busboy)提供文件/字段限制及截断信号，可作为候选；实施前核对维护状态、类型及 Node 24 兼容性，必要时选同类成熟实现。不能用无限 `request.formData()` 将整个大文件放进内存。
- 已有 [Zod JSON Schema](https://zod.dev/json-schema)支持 OpenAPI 目标和文件结构，先复用其转换能力，再组装 OpenAPI paths/security/encoding；无需默认新增另一套 schema 转换库。流式运行时校验不要求先构造完整 File。

本轮为工程及官方资料核对，不代表上述依赖已集成或真实传输已测试。

## 3. 设置、限制与文件输入

`upload_settings` 为 id=1 单行，默认 max_file_bytes=50 MiB、batch_size=20、queue_limit=500；首次读取通过迁移已有初值，不在未初始化时开放上传。基本设置页与 media 默认可见性分工，各字段由自己的模块保存。

配置：单文件上限以正整数 MiB 保存；用户已确认批次大小 1–200，队列大小 100–2000，批次不得大于队列。浏览器传输并发固定 3。文件大小配置的上界不得高于首版已验证的单 PUT/Copy 共同容量；具体字节边界在第 13 节完成 AWS/R2/MinIO 验证后固定，不能偷偷恢复此前取消的 1 GiB 原文件上限。界面须展示实际可配置范围，不能先接受必然无法上传的值。

50 MiB 等于 50 × 1024 × 1024 字节，恰好等于上限可上传，超过才拒绝；空文件拒绝。不按输入宽高、总像素、帧数或页数拒绝。文件声明长度、实际接收计数和实际对象大小全部核对；未知 Content-Length 仍逐块计数。media 的真实超时/资源限制照常适用。

队列上限按已确认规则计算页面所有条目，包括成功和失败结果；“清空已完成”后释放名额。扫描发现超过剩余名额时，保留已加入项并汇总未加入数量，不能悄悄丢失、自动上传或无限占用浏览器内存。未支持格式、空文件、大小超限分别统计。

### 3.1 文件、目录和剪贴板

支持普通多文件选择、拖拽、粘贴图片/截图、目录选择与递归拖入。扫描分段执行并可取消，已加入项保留；读取某个目录失败不伪装成全部扫描成功。只加入支持图片，不保留相对路径，不自动建相册，空目录无记录。

文件扩展名、浏览器 MIME 与轻量文件头可作候选识别，服务器真实识别为准。浏览器不能预览 HEIC 等格式不等于不能上传；显示格式占位。SVG 不以内联 HTML 执行。粘贴只读取图片 File/Blob，不把文本 URL 当远程导入。没有名称的截图生成 `粘贴图片-<时间>-<序号>.<声明扩展名>`，真实格式仍由服务端判断。

Uppy 默认文件身份可能按名称/大小等推导，接入时给每次显式添加独立队列 ID，确保同名文件和再次选择同一文件都能上传成独立图片；不做哈希去重。真实目录输入、剪贴板与重复文件行为须在支持的浏览器上验证。能力缺失时明确提示并保留普通选择文件入口，不把手机降为只读。

### 3.2 名称统一

只取传入文件名最后一个路径片段，兼容 `/` 和 `\\`；目录结构不传给存储 Key。控制字符/NUL 拒绝，名称最多 255 个 Unicode 码点；空名称、`.`、`..` 使用 `image`。名称按纯文本显示。

`originalName` 保存上述归一化文件名，`displayName` 按 media 规则仅去掉最后一个扩展名：`旅行.final.JPG → 旅行.final`；无扩展名保留，`.photo` 这样的隐藏名保留，`photo. → photo`；若最终为空则 `image`。Key 和正式后缀由服务器 ID 与真实格式生成，不采用客户端路径。下载名继续使用 delivery 规则。

## 4. 提交、拆批与快照

一次点击“开始上传”创建一个 submission，包含这次待上传文件清单及统一设置；每项有独立 session。服务端按 batch_size 给文件分组，这些组共享本次提交的 storageId、可见性、处理设置/确切水印素材和相册/标签 IDs。例如 45 张、单批 20，拆为 20/20/5；不能因最后一组晚开始而突然采用新水印。

点击之前可移除文件、修改整批设置；点击之后该次提交冻结。上传过程中可以添加下一次待提交队列并配置另一组设置，仍须再次点击开始，所有提交共同遵守浏览器并发 3。当前组各文件交接或终止后开始下一组，不等待已交接图片的派生处理完成。

未显式选择存储时只解析当前默认，不自动找其他存储。没有可用存储禁用开始按钮并显示 PRD 文案；存在可用存储但默认缺失/停用时提示手动选择。默认改变不改变已提交 storageId；存储运行中停用则停止该目标后续接收/交接，不能自动切换。

服务端同一准备事务验证目标并调用 collections 固定关系 IDs、media 创建快照及素材引用。一个提交内文件共享这些结果。没有选相册或标签允许上传；显式指定的目标必须有效。collections 已确认的空相册/标签保留、目标删除报错、不绑定同名新记录等规则原样适用。

修改上传限制只影响新 submission，旧提交沿用创建时已核验的大小、批次规则；存储停用等实时可用性仍每次检查。客户端重复发送同一次创建请求，以本次随机 submission 请求 ID 去重并核对相同输入，返回相同 sessions；同 ID 不同输入报冲突。此去重仅服务内部 Web 协议，不构成通用 API 的幂等承诺。

## 5. 持久状态与责任

| 表                   | 主要数据                                                                                                                                                                                                                   |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `upload_submissions` | ID/内部请求 ID、Web/API 来源、统一设置与素材快照、集合 IDs、大小/批次限制快照、last_activity_at、UTC 时间；API Token 只可保存非秘密标识，撤销 Token 不级联删除提交                                                         |
| `upload_sessions`    | ID、submission_id、组序号/队列项 ID、原始名/声明大小/声明 MIME、storage_id、传输链路、状态、可空 image_id/media_job_id、签名截止时间、各明确临时/正式 Key 或暂存路径、实际大小/对象 ETag、失败步骤/代码/重试时间、清理状态 |

API 在认证及读取当前大小限制后，先创建目标未解析的接收 session；此阶段 submission_id/storage_id 允许为空，登记本地暂存路径后才读取文件体。它只承担 tmp 文件责任，不伪造配置存储引用。完整参数通过后，在准备事务中补齐 submission、真实 storageId、集合和媒体快照；沿用读 body 前固定的文件大小限额。无目标接收行的失败/重启清理按 session 记录执行，不另建账本。

每个会话只接收一份文件。文件写入前登记实际路径/Key；预分配 imageId 不等于已存在资产，不提前向用户提供详情入口。持久信息足够恢复到具体对象，不持久化 File、Blob URL、Token、签名 URL 或任意浏览器路径。

接收状态：`queued → receiving → validating → finalizing → accepted`；交接前可进入 `cancelled/failed/expired`。这些是接收状态，不复制 media 的 processing_status。accepted 通过 media_job_id 查询本次处理结果，image_id 用于访问资产；两个结果 ID 保留为本次接收的历史标识，资产/任务删除不连带抹去已接收事实。清理状态单独记录，用户看到上传失败不代表临时对象已经删完。

建议未交接 submission 连续 1 小时没有实际上传活动后到期：创建、开始文件、接收进展和完成更新活动时间，接收进展最多每分钟落库一次。正在执行的请求先取消并结算；仍可能写入的 S3 Key 继续保留清理责任。页面关闭不恢复队列，不需要保持页面的后台心跳；正常后续批次开始会更新本次提交活动。已 accepted 图片不受 submission 到期影响。

所有会话交接或终止后，释放不再需要的水印素材引用。即使旧临时 Key 还需清理，也不为它保留已经无用途的水印文件。Web 会话结果建议保留 24 小时供当前页面核对，超过时告知去图库查看；有任何对象责任的行不按时间删除。不恢复浏览器队列历史，不把该记录变为新的上传历史产品。

### analytics 上传占用只读提供方

补充 `readUploadUsage(tx)`：按真实 storageId 汇总会话仍负责的各个配置存储对象之已确认字节、待核对数与确认时间；临时 Key 和正式候选同时存在时各计一次。accepted 后不再把转交 media 的正式 Key 计入，但剩余临时对象继续计入。无目标或位于 DATA_DIR/tmp 的中转文件不归入任一配置存储；页面范围由 [已评审 analytics 规格](./SPEC-analytics.md)说明。可能迟到的写入责任不等于当前已存在声明大小；数据未知需明确，不用 HEAD404 提前解除清理责任。本函数只读现有责任记录，不新建占用账本。

## 6. 本地与服务器中转

本地 Web 会话已知目标，流式写入该存储的临时文件，计数字节并检查磁盘剩余空间；完整接收并通过格式初验后，在同一文件系统固定到正式 Key。本地原图不额外复制到 `/data/tmp`。

S3 中转必须由 Ariso 接收。Web 已有设置；API 的字段可能在文件后面，因此两者可以复用受控暂存流程：先流式写到 `/data/tmp/uploads/<sessionId>/`，完整解析单文件请求，再按已验证目标写入正式 S3 Key，成功后清暂存。API 选择本地时可直接在已知目标暂存；字段顺序尚未知时先使用受控暂存，再处理跨文件系统发布。跨盘需流式复制并确认成功，不能假设 rename 总可用。

实际 MIME/格式识别复用 media 的初验能力：明确不是支持图片则拒绝交接并清理；只是头部可识别、后续完整解码失败则按 media 保留原图与 failed 图片。声明 MIME 缺失或通用 octet-stream 可以接受；声明与实际不符时记录差异，以实际格式保存，不仅按后缀或 ContentType 放行。PDF/视频/文档拒绝。

所有实际写入文件系统按已知剩余字节与并发在途写入核对可用空间，未知长度逐块检查；不按每文件上限预留，不新增固定 4 GiB 配额。S3 直传也需在接收前考虑之后验证/处理的本地磁盘需求。ENOSPC 返回明确错误并清理部分文件；当前文件失败不主动取消无关文件。

工程起始值提议：传输连续 120 秒无进展或单次接收超过 30 分钟则失败并清理，不含 media 排队/处理；需大文件、慢网实测后固定。浏览器 XHR 与 Node/反向代理的默认超时应协调，不能用默认 30 秒进度超时意外中止服务端固定过程。服务器等待 S3 响应无浏览器字节进度时显示“正在保存”，不制造假进度。

## 7. S3 Web 直传、固定与清理

### 7.1 选路与开始

文件真正获得传输名额时才调用 begin：读取当前存储与当前 origin 对应的 CORS 检测结果，通过则直传，否则中转并明确显示原因。选路固定到 session；已开始后不切链路。一个旧检测已通过但实际传输网络失败的文件显示失败，不能在原会话暗中重传另一条链路。

直传先持久登记临时 Key，再签发 900 秒 PUT 和要求 headers。浏览器只收到本次受控 URL，不自行选择 Bucket/Key；签名临近过期或已经过期且尚未开始请求时取消旧会话并重新提交，不能让旧 Key 无记录。排队的其余文件不提前拿签名。

### 7.2 完成校验与正式原图

浏览器 PUT 成功只表示传输完成，随后调用 complete。服务器沿用 storage 契约：HEAD 取得大小/声明类型/ETag → 同 ETag 条件 GET 做真实初验、计数 → CopySourceIfMatch 固定到新的正式 Key → 原子交接。下载初验能复用的本地文件与识别结果传给 media，不无理由重复下载/识别；复用文件的路径与清理责任须随交接移交给具体 media 任务工作区，upload 不再提前删除，不能复用时仍由 upload 清理。正式路径从不对浏览器签发 PUT。

源变化、大小不符、格式不支持均明确报错，不能无条件复制。Copy 的响应即使 HTTP 外壳 200 也须由 SDK 检查真实结果。[AWS CopyObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CopyObject.html)包含条件复制及单次复制限制；[R2 限制](https://developers.cloudflare.com/r2/platform/limits/)须一起验收，不能以一个服务的结果代表全部。

complete 只接受 session ID，不接受客户端传来的目标 Key、可信 MIME 或成功证明。并发 complete 共享同一活动操作，单进程内按会话协调；已 accepted 返回同一 imageId，重复通知不造新图。进程中断或 Copy 响应丢失后，依据已登记源身份/正式 Key 核对；不能确认内容对应同一次操作时，清理这次正式候选并报中断，不猜成功，也不换 Key 遗忘旧对象。

### 7.3 取消、到期与迟到写入

临时对象在完成/失败/取消后可立即尝试删除，但签名仍可写时保留清理引用和再次删除责任。用户以后把已接收图片永久删除，也不能顺带丢掉这个 upload 临时引用。

[AWS 预签名有效期说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)说明有效期在请求开始时检查。因此 900 秒到期、浏览器 Abort 或一次/多次 HEAD 404，都不能单独证明更早发起的请求已结束；不能凭固定宽限期就宣布 Key 永远不会再出现。

清理使用确切 Key、记录结果和下一次重试。网络/权限失败有限重试后显示 cleanup_failed，提供所有者重试；等待签名结束或远端写入结算显示 cleanup_pending，不冒充错误，也不清除存储引用。重启继续这些职责，不扫描全 Bucket，不碰回收站。

**待验证的实施前置：** AWS/R2/MinIO 单 PUT 在取消、到期及服务端请求仍在执行时，提供方如何证明写入结束，或需要何种经过验证的收尾方式。本轮资料不足以承诺统一最终删除时刻；未解决前保持责任记录，S3 直传清理与“全部对象清完可删存储”不能标 Done。不能将无限保留记录当成最终交付方案，也不能未经评审增加 Bucket 生命周期配置要求或静默取消 PRD 的直传能力。

## 8. 交接与取消竞争

正式对象已固定且仍由 upload 引用后，在同一同步短事务中：

```ts
db.transaction((tx) => {
  assertSessionCanAccept(tx, sessionId);
  const image = acceptOriginal(tx, acceptedInput);
  attachAcceptedImage(tx, image.id, selection);
  markSessionAccepted(tx, sessionId, image.id, image.jobId);
});
```

事务复核会话未取消、目标存储启用、collections 固定目标仍存在，然后同时提交资产、original 版本、处理任务、关系和责任交接。失败全部回滚，正式候选仍归 upload 清理。事务不得包含文件、网络或解码工作。

取消以此事务提交为界：提交前取消成功，后续不能交接；提交后属于服务端处理，取消返回冲突及 imageId，页面提示已进入处理。以数据库先后决定竞争结果，不能同时显示取消成功和创建图片。传完后的校验/固定阶段仍处于交接前，可请求取消，但须结算在途写入。

文件体尚未完整收完时，Web 关页/网络断开或 API 客户端断开会结束接收并清理。文件已完整接收且服务端已进入校验/固定后，响应连接断开不自动撤销操作；Web complete 失联或 API 等待断开均可继续交接和处理，真正取消须显式变更状态。单纯 PUT 完成但尚未通知 complete 的直传仍按未完成会话到期清理。交接之后只结束等待，不撤销处理任务。accepted 后释放浏览器传输并发名额；media 的处理并发独立控制。

## 9. Web 结果、重试与内部接口

队列区分待上传、上传中、校验/保存中、服务端排队、处理中、成功、失败、已取消。上传进度到 100% 后改状态文字，不将派生处理显示为上传百分比。单项失败不暂停其他项。

已有 imageId 的处理失败显示失败步骤、错误、已保存版本，并提供详情、重新处理、回收。重处理按 media 使用最新设置、保持同 imageId。交接前失败显示“未创建图片”，没有详情/回收/重新处理按钮，不能拿 sessionId 或预分配 ID 冒充图片。

成功和最终失败立即释放 File 引用、Blob URL 和插件中的数据引用；交接成功后也可提前释放原始 File。取消或移除同样释放。保留名字、大小、状态、imageId 等轻量结果，有可用缩略图则从服务端加载，否则占位。传输失败后的再次上传需要重新选择文件；不能释放后仍承诺“一键重传”。自动重发 complete/查询同一会话只核对结果，不重新传原始文件。

成功提供默认 URL/Markdown/HTML、打开图片和详情；默认链接不带 type，明确选择版本才附 type。每次生成默认链接结果独立说明当前是否可解析；如果处理期间默认改成缺失水印，仍显示图片处理成功，同时提示默认链接暂不可用，现有固定版本链接正常。

“清空已完成”移除成功、失败和已取消结果，不删除图片或任务，不中止服务端清理。刷新后不恢复未完成浏览器队列，已交接图片可在图库查看；离开页面时有未提交/传输项则作浏览器能力范围内的离开提醒，不能保证移动系统关闭时弹窗。

| 内部入口（草案）                           | 权限与结果                                                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `/upload`                                  | 所有者上传页面；未登录沿 identity 登录回跳                                                              |
| `POST /api/uploads/submissions`            | 所有者 + 来源检查；完整清单/统一设置，创建 submission/sessions，不传原文件；返回 201 仅代表内部队列提交 |
| `POST /api/uploads/sessions/{id}/begin`    | 选路并开始同一会话；返回直传签名或中转入口，不对已开始会话反复签名                                      |
| `POST /api/uploads/sessions/{id}/content`  | 所有者单文件流式中转；已接收或正在接收不能重复写入                                                      |
| `POST /api/uploads/sessions/{id}/complete` | 直传固定/交接，可返回 202 表示仍在固定或处理中，不等于通用 API 成功                                     |
| `DELETE /api/uploads/sessions/{id}`        | 交接前取消，交接后 409；清理可能仍在进行                                                                |

## 10. 通用上传 API

### 10.1 请求

唯一业务入口 `POST /api/upload`，只认 `Authorization: Bearer <token>`；Cookie 不能替代。读取文件体前由 identity 验证 Token；接纳请求后中途 Token 到期/撤销不追溯取消该次上传或处理，新请求拒绝。Token 撤销不删除任何图片和任务。

| multipart 字段 | 规则                                                                              |
| -------------- | --------------------------------------------------------------------------------- |
| `file`         | 必需且恰好一个文件，不能传 URL；第二个文件使整个接收失败                          |
| `storageId`    | 可省略，单值非空 ID；省略才读默认，空串不当默认                                   |
| `albumId`      | 可省略，多相册用重复同名字段；去重 IDs，不接受相册名称、逗号串或 `albumId[]` 别名 |
| `tag`          | 可省略，多标签用重复同名字段；按 collections 名称匹配/创建，不按逗号拆分          |
| `visibility`   | 可省略，单值 `public/private`；省略采用正式提交时默认可见性                       |

拒绝重复单值字段和未知字段，字段出现顺序任意。解析全部表单才能确认只有一个文件和合法设置；文件位于字段前时写受控暂存，不提前建图片。字段总字节建议限 256 KiB，文件名和单标签按各自长度限制；这是解析开销边界，不改变图片大小配置。流被截断、额外文件、字段超限均清理并报错，不能只忽略解析器的 limit 事件。

完整参数校验后创建单文件 submission，固定当前存储/可见性/处理与集合快照。API 自动创建的标签即使随后初验/写入失败也保留；此前非法参数导致事务回滚则不创建标签。文件经 Ariso 中转，S3 不向调用方暴露两阶段协议。

### 10.2 完成响应

只有本次处理完成且图片 ready 才返回 201；不返回 202 或其他 2xx 冒充“已入队即成功”。按会话保存的 media_job_id 等待已持久化的这次任务，不新建第二套处理器，不把后续手动重处理的成功当作本次成功。status 表示本次上传结果；若后来操作已改变图片状态，另返回 currentImageStatus 说明当前状态。处理失败返回 422 或对应资源/依赖错误状态，包含真实 imageId、`status: failed`、步骤和可读错误，保留原图与已存版本。

接收/初验/关联交接失败尚无资产时 `imageId: null`、`status: not_created`；不能伪造 PRD 所述处理失败图片。HTTP 状态区分 400 输入、401 Token、409 存储/目标状态冲突、413 文件超限、415 非支持图片、422 已接收后的处理失败、502 存储依赖故障、507 空间不足。每个错误响应带稳定 error.code、stage、message 和 requestId。

服务端等待起始预算建议为交接后 900 秒，包括排队；到期返回 504、现有 imageId 和当时真实 `pending/processing/ready/failed` 状态及 `UPLOAD_WAIT_TIMEOUT`。不能把等待超时写成图片 failed，不会终止任务。返回前再读一次终态，已 ready/failed 则优先返回对应完成结果。正常代理超时必须覆盖接收和处理等待；异常客户端断连可能完全收不到结果，说明应到所有者图库核对，不能盲目自动重发。

等待期间图片被所有者回收/开始永久删除，或本次任务因删除而取消、记录已经清除时，立即结束等待，返回 409 / IMAGE_UNAVAILABLE 和原 imageId，标明已接收后不可用，不能伪造 not_created/failed。提交删除和成功响应之间按最终读取时的状态判定，不承诺响应发出后图片永远不再改变。

通用 API 首版不提供状态轮询或请求幂等键：重新发一次 POST 就是一次新上传，相同文件可产生新 ID。传输/代理结果不确定时，不能宣称重试绝不会重复；OpenAPI 与示例必须说明这一点。

成功结构提议：

```json
{
  "imageId": "image-id",
  "status": "ready",
  "url": "https://images.example/i/image-id",
  "actualVersion": "compressed",
  "defaultResolution": { "available": true, "code": null },
  "versions": {
    "original": {
      "url": "https://images.example/i/image-id?type=original",
      "mime": "image/jpeg"
    },
    "compressed": {
      "url": "https://images.example/i/image-id?type=compressed",
      "mime": "image/webp"
    },
    "thumbnail": {
      "url": "https://images.example/i/image-id?type=thumbnail",
      "mime": "image/webp"
    }
  },
  "processing": { "status": "succeeded", "warnings": [] }
}
```

只列真实已保存版本；`actualVersion` 表示响应生成时的默认版本解析，不保证以后不变。默认切到尚缺失的适用水印版本时，图片依然 ready/201，actualVersion 为 null，defaultResolution.available 为 false、code 为 `VERSION_UNAVAILABLE`，固定版本链接仍返回。私有图正常上传也 ready；链接访问需要所有者 Cookie，不能将此标作上传失败。处理结果还包含各版本成功/不适用/关闭原因及元数据读取警告，不能只给空泛的成功字符串。

### 10.3 OpenAPI 与示例

使用共用 Zod 输入/结果/错误 Schema 生成 OpenAPI 3.0 文档；重复字段按 multipart encoding 明确数组形式。文档包括所有状态、可空 imageId/actualVersion、权限、大小限制、等待超时和重复提交行为，不把内部 Web 接口列为公共 API。

规划 `GET /api/openapi.json` 提供不含秘密和管理数据的上传契约，`/settings/api` 提供用法与 Token 管理入口。规范中的大小默认值不冒充每个站点当前上限。文档生成应可重复且纳入检查，实际新增脚本与命令随实现提供，不声称当前已存在。

```sh
curl --request POST 'https://images.example/api/upload' \
  --header "Authorization: Bearer ${ARISO_UPLOAD_TOKEN}" \
  --form 'storageId=storage-id' \
  --form 'albumId=album-id-1' \
  --form 'albumId=album-id-2' \
  --form 'tag=Go' \
  --form 'tag=旅行' \
  --form 'visibility=private' \
  --form 'file=@./photo.jpg'
```

这是文档示例，未向真实站点发送。调用方自行提供 Token，不写入仓库、日志或可共享截图；示例不承诺 PicGo 专用适配。

## 11. 重启、错误与实现组织

持久写入前登记责任，重启按状态恢复：queued 未传文件最终到期；receiving 中断保留错误并清部分文件；validating/finalizing 先核对对象再继续或失败清理；accepted 只从 media 读取，不重复建图；清理失败保留对象路径和下一次操作。不得因进程重启无限重置失败重试预算。

暂存清理与正式候选清理复用明确对象的删除步骤；只有无在途写入且删除成功/明确不存在才解除责任。仍存对象、会话、素材与清理引用通过 `getStorageReferences(tx, storageId)` 等提供给组合入口，不能让 storage 反向导入 upload。迟到写入最终收尾仍受第 7.3 节前置约束。

预计新增 `src/server/upload/`：settings/schema、提交与会话、流接收、S3 完成、交接、清理恢复和公共契约；按真实职责拆分，不建通用任务引擎。界面位于 `src/app/upload/` 及对应组件；Route Handler 只做认证、解析与模块组合。沿用严格 TypeScript、Zod、camelCase、同步 Drizzle 事务、Pino。

日志保留 submissionId/sessionId/imageId、storageId、阶段、实际字节数、时长、底层错误与 requestId。不得输出 Bearer Token、完整签名 URL 或存储凭据；可保留受控对象 Key 帮助诊断。始终保持原图不变和责任可追溯；改变取消分界、API 完成语义或引入新部署要求须先修订规格；禁止假造成功、丢弃失败对象引用或把 HTTP 断连当处理失败。

5. **直传突然不可用。** 开始前检测不可用则自动中转并标明；已经开始直传后断网，则本文件失败，不能偷偷切链路再传一次。重新选择/提交时按最新检测结果选路。取消后的远端临时文件可能仍在清理，页面不伪报已删除。
6. **API 等待和默认链接。** 图片处理成功期间默认改成尚未生成的水印版本，上传仍成功，同时告诉调用方默认链接暂不可用，并返回已有版本链接。等待/代理超时不会把图片改成失败；再次 POST 可能生成另一张图，应先在图库核对。
