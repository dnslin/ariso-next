# 迭代与验证经验

本页归集首版交付中可复用的做法。具体业务规则仍在[业务规格](../product/CAPABILITY-MAP.md)，检查门槛仍在[执行约定](verification.md)，不在这里重复维护。

## 后续迭代

M1–M5 已完成，M5 于 2026-10-17 由用户确认手动验收通过。后续需求、缺陷与体验改进按独立 Issue 或明确范围推进，不延续旧阶段待办，也不预设新里程碑。

每项改动记录要解决的问题、修改边界、真实依赖、可观察的完成条件，以及实际验证结果。界面变化引用设计节点与必要差异，复用已批准交互；通用检查统一见[验证指南](./verification.md)，部署和恢复见[部署](./deployment.md)与[升级](./upgrading.md)。旧任务系统不再运行，首版完成结论从[阶段归档](../archive/README.md)追溯，原任务定义只在固定历史提交查看。

## 先接通真实流程，再扩展能力

M3/M4 沿用 M2 的队列、处理、查询和关系事务，按真实提供方依赖增加能力。改动前先核对实现、调用方、已安装库和既有实验；已经获得的证据先查差额，不因旧任务写着“待执行”重跑整个实验。共享文件按修改边界协调，独立路线可以并行。见[阶段经验摘要](https://github.com/dnslin/ariso-next/blob/975f63eeb3e9b19a0ace827ba3fe646565d5b2e2/docs/archive/m3-m4/sequence.md#保留的组织经验)。

用户动作要保留来源和结果：从相册进入上传后保留相册上下文，从上传结果打开版本后返回原入口，关闭弹窗恢复触发位置。搜索替换当前历史记录，分页新增历史记录；实际前进/后退行为与 URL 一起检查。未保存草稿、保存成功和重启后生效分别表达。慢速切图保留旧图和关闭入口。见[十二项 UI/UX 交付](../verification/m2-85/ui-refinement/20261015/uiux-12/README.md)。

## 浏览器检查要能发现真实失败

Safari 曾出现整页无横向滚动但表单内部被裁切。最内层 input 可收缩仍不足以让 Grid 中的 TextField 根节点收缩；修复在实际受影响根节点添加 `min-w-0`，检查同时测页面、主区和可见表单内容边界。等控件实际渲染、动画完成后取样，空表单绿灯不构成证据。用修复前的真实失败与修复后的同断言验证有效性。见[Safari 修复与双浏览器记录](../verification/safari-compat-20261016/README.md)。

浏览器截图按实际尺寸、主题和状态说明。macOS Safari 窄窗口证明桌面 Safari 的响应式表现，不能冒称 iPhone 实机；专项场景通过不能概括为全站或全部浏览器通过。设计对照与功能结果分别记录，沿用[前端共用验收](verification.md#前端共用验收)。

验证图片取消时，要证明传输已开始且随后实际中断，不能只看 DOM 中有未完成图片或最终没有 error。先保留旧版失败对照，再检查新版本日志；正常取消应关联本次请求的取消原因，不能按 `signal.aborted` 一概忽略真实读取失败。见 [v1.0.16 线上对照](../verification/releases/v1.0.16/README.md#取消日志对照)。

管理界面的媒体请求保持同源。站点公开地址变化不应改变管理 Cookie 的发送目的地，路径构造由同一提供方维护；见[图库早期优化的正式结果](../verification/library-76/README.md)。错误提示出现后检查真实焦点，浏览器等待实际导航完成，不用固定延时掩盖竞态；见[登录回归修复结果](../verification/analytics-83/README.md)。这些结论已保留在正式交付记录，不重复维护旧优化计划。

## 媒体质量比较真实编码结果

Favicon 清理元数据时必须保留解释颜色的 ICC、Gamma 与 sRGB 信息；简单使用 `-strip` 会造成真实色差。检查源文件标签、原始像素和统一色彩空间后的完整像素，避免只看编码器选项或缩略截图。细长 SVG 在目标透明画布内等比渲染，避免短边取整为零。见[Favicon 与水印修复记录](../verification/favicon-watermark-20261014/PR.md)。

同一夹具在 macOS 与 Linux 的工具行为可能不同。先证明输入包含要测试的格式/标签，再比较产品输出；不通过削弱断言掩盖跨平台差异。浏览器原型可以确认方向，真实输出才能证明编码质量。文字水印描边为 0 时显式使用 `-stroke none`；比较时固定底图、字号、透明度与质量，同时检查透明合成前的图层和真实编码结果，不能靠提高质量掩盖描边语义错误。

## 保持构建、测试与数据相互独立

先完成生产构建，再运行依赖 standalone 的集成和浏览器测试。重打包与测试同时执行曾让运行中的产物被替换，造成启动失败。资源不足时降低并发，保留超时和断言；原失败记录保留，最终完整重跑的结果单列。见[UI/UX 验证纠正](../verification/m2-85/ui-refinement/20261015/uiux-12/README.md#执行中的纠正)。

测试夹具修改配置后，在失败路径也恢复实际被修改的数据；恢复失败要与原失败一起保留。正式服务的已有数据与隔离测试数据分开，不能用写库夹具冒充真实上传和用户操作。见[品牌验证恢复修正](../verification/site-196/implementation/code-review.md)。

发布验证使用临时环境，升级保留原镜像、完整数据目录和原密钥；迁移后回退须恢复升级前完整备份。健康接口、真实登录和业务读写各自验证，不能只凭容器运行或 HTTP 200 判断产品可用。实际步骤见[部署](./deployment.md)与[升级恢复](./upgrading.md)。

- 2026-10-26 根目录 `tasks/` 的八份计划与任务表已[清空归档](../archive/tasks-20261026.md)，历史状态和接口约定通过固定提交查看；不因清理而改写未完成项。
- `archive/` 按阶段保留简洁完成结论和关键决策，原任务、准备计划与旧原型只通过固定提交追溯。历史失败、未运行和环境限制保留原结论，不批量改成通过。
- `verification/` 保存具体交付报告与少量关键最终证据。新记录先写问题、最终行为、实际命令和限制；调试流水只在本地产物目录保留，避免反复提交同一页面的逐轮截图。
- 归档不复制一套当前规则。本轮已按这些边界精炼历史原始产物：保留实际使用的源码、许可、测试输入和少量最终代表，历史文件引用固定到已核实存在的 Git 提交。删除 Git 跟踪文件只能减少当前检出体积，不会自动缩小历史仓库。

本页只是经验归集，不表示本轮重新执行了业务、浏览器、媒体或发布验证。
