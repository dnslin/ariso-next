## 实施任务模板

有界面的任务必须遵循[HeroUI 组件复用规则](../design/handoff.md#heroui-组件复用规则)，填写组件映射和自定义理由；无需界面的任务注明不适用。

```text
ID / 标题：
所属模块与里程碑：
PRD 条目：
已评审规格：
直接前置任务 ID：
交付结果：
范围 / 不包含内容：
预计修改文件：
页面入口或路由：
Figma 桌面 / 手机 / 状态节点（或无界面理由）：
HeroUI 组件清单及对应官方文档（版本沿用项目锁定依赖）：
业务组合 / 自定义组件及现成能力无法满足的具体原因（没有则写无）：
相对原型的必要差异及原因（没有则写无）：
验收条件（成功、失败、重启/权限等适用场景）：
验证命令与环境：
交付 PR / 实际结果与证据：
```

验收完成前核对全部前置的交付与证据。新增测试注明由本任务提供的文件和命令，不引用尚不存在的命令并声称通过。

## 检查点

- 任务细化：覆盖表每项首版要求和验收场景均关联实施任务，设计缺口有归属，直接依赖无环且无缺失。
- 前端评审：核对 HeroUI 组件映射、自定义理由及原型差异；验证桌面/手机、浅深色、焦点/触控和适用状态，不能用已采用组件库代替页面验收。
- 每批契约与实现：提供方、调用方和错误语义一致；每 2–3 个相关实施任务后执行真实流程和适用工程检查。
- 每个里程碑：核对前置、合并结果、设计及实际运行证据，模拟数据不能关闭完整业务。
- 第二阶段结束：PRD 全量要求及 26.1–26.13 全部具备实际证据，实际发布独立记录。
