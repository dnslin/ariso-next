## 3. 沿用的架构决策

- 单包 Next.js App Router 工程；模块目录按能力地图增长。
- prestart 完成环境检查、目录准备、迁移与必要的敏感配置预检后退出；随后 `exec` 标准 Standalone `server.js`。
- instrumentation 负责 Web 进程内的初始化；有限初始化完成后返回，不等待无限任务循环。
- CLI 和 Web 共用 runtime 源码。应用组合集中在 `src/server/startup`，基础模块不反向依赖业务模块。
- SQLite 使用现有 Drizzle 迁移器和 better-sqlite3；加密使用 Node crypto；日志使用 Pino。
- 生产产物包含 CLI、迁移器、SQLite 原生文件、静态资源和镜像验证样本，并脱离开发依赖验证。

本计划不重新选择技术栈。实施中发现依赖问题时先查当前版本的官方文档、类型和实际错误；需要改变已批准行为或架构边界时，先修订 Spec。

### R1：建立最小可构建工程

#### RUNTIME-03 实施计划（2026-09-15）

用户随后追加 GitHub CI 和 ARM64/AMD64 Docker 构建要求：补齐手动触发、当前 Next 页面的最小 Dockerfile 和双架构原生 runner 构建；在 Actions 中启动镜像并导出通过检查的产物。该增量不提前实现 R2 的持久化启动或完整镜像工具链，实际运行结果记录在 `docs/development.md`。

在 `codex/runtime-03-engineering-checks` 实施 [Issue #3](https://github.com/dnslin/ariso-next/issues/3)，复用已合入的 RUNTIME-01、02。

1. 为现有代码接入 Next Core Web Vitals、TypeScript ESLint 配置和 Spec 指定的 Prettier 风格。排除冻结 PRD、依赖、生成文件与测试输出；首次统一受检查文件的格式，不改变内容语义。
2. 提供 lint、format、format:check 和应用 typecheck 脚本。当前没有独立 runtime 编译项目，后续建立后再接入其类型检查。
3. 添加单个 Node 24 CI 作业，按冻结安装、lint、格式、类型、真实 Next 构建顺序执行。真实单元、集成与 ego 验证随后续任务接入，不加入空测试。
4. 本地执行全部检查，并验证规则能拒绝错误及忽略生成目录。记录命令与结果；远端 CI 未运行时不标为通过。

先验证依赖能在目标 Node 版本上真实安装、编译和检查，再增加业务运行能力。起始页面只作为实际应用壳和静态资源验证入口；它不会伪装成已有登录或上传功能。

安装时落实 pnpm 原生构建脚本配置。SQLite 驱动可加载性尽早验证，避免直到容器打包时才发现原生依赖没有生成。

### R2：优先打通完整启动流程

将配置读取、目录创建、真实数据库、迁移、进程入口和健康接口连成一条可执行流程。每项状态变化都通过实际进程或数据库验证。

先用真实迁移样本证明正常迁移、重复执行、故障回滚及旧产物面对新数据库的拒绝行为。样本只用于测试，生产不新增占位业务表。

独立 CLI 编译和 Standalone 打包也在本阶段接通。把运行目录复制到与项目无关的位置再启动，确认没有借用开发目录的 node_modules、迁移文件或静态资源。这样可以提前发现最主要的交付风险。

### R3：把密钥与日志接入真实入口

先验证加密函数和日志处理，再接入 prestart、Node 日志预加载和真实框架错误输出。不能只对手写字符串断言脱敏成功，必须覆盖框架把请求 URL 写入错误消息的场景。

当前没有 S3、SMTP 或 OAuth 数据表；使用真实加密测试记录验证失败语义，并保持业务预检的接入点清楚。生产代码不扫描未知字段，也不创建通用设置表。后续模块的全量秘密检查和会话失效验证仍由所属 Spec 完成。

### R4：在目标镜像里证明交付

把 R2 的实际产物放入选定 Debian/Node 镜像，先验证容器启动、挂载、日志和重启，再验证两个架构的 SQLite、ImageMagick、ExifTool 与字体样本。

图片验证脚本读取镜像中的真实 JPEG/PNG 输入，输出到临时目录；检查实际生成内容，不仅检查程序退出码或格式列表。完整 APNG、动态 AVIF 等格式矩阵由 `media` Spec 闭合。

### R5：汇总持续检查与交付入口

CI 随检查能力形成逐步接入，在本阶段完成全套汇总。不会等到最后才首次运行 lint、单元测试或集成测试。

ego-browser 技能使用真实生产服务和可见页面验证；浏览器访问、健康接口、静态资源与环境隔离均有实际断言。已验证的本地和容器命令进入开发、部署及升级说明。

发布工作流只消费已验证的产物。创建外部仓库、配置远端凭据和实际发布镜像属于后续交付操作；配置文件存在本身不等于 CI 或发布已经成功运行。
