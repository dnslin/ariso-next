## 范围和交付方式

共 **51 张业务任务卡：M3 23 张、M4 28 张**，已在原卡内拆为 **114 个勾选步骤**。[平台卡](./m3-m4-platform.md)与[体验卡](./m3-m4-experience.md)仍是范围、需求、直接前置、预计文件和验收方法的唯一来源。步骤不是新任务编号，不改变原需求归属；全部步骤完成后还要通过整卡验收。

每个步骤以一次可集中完成的 S/M 修改为目标，约 1–5 个主要实现文件，另加对应行为测试。步骤须交付可调用接口或真实页面闭环，不交付无人使用的抽象层。步骤内超过该范围时，再按实际调用边界拆分；不能把父卡描述的多个子系统塞进一次提交。父卡前置在第一步前满足，步骤顺序就是内部依赖；未满足的步骤保持待执行。

每完成 2–3 个相关步骤，执行该卡聚焦行为测试并串一次真实流程；整卡交付执行 [适用检查](./execution.md#适用检查)。下列阶段检查点另核对跨卡流程和遗留项，不替代单卡验证，也不要求不相关路线互相等待。

## 修改边界与风险

| 边界或风险                              | 执行规则                                                                           |
| --------------------------------------- | ---------------------------------------------------------------------------------- |
| media 多路线共用 schema、queue、process | 格式与水印先确定字段及调用契约；预览和重处理复用同一处理实现，不并行改同一发布流程 |
| upload / storage / media 清理责任       | 按实际写入、交接、结束顺序交付提供方；T-STO-06 等全部引用齐备再开放位置修改/删除   |
| library 与 collections 共用查询/关系    | 先完成查询契约，再接列表和封面；不复制关系校验、不恢复已取消手动排序               |
| settings/general 多模块共用页面         | 各模块独立GET/PATCH和保存组；同一页面改动串行整合，公共外壳统一回归                |
| 格式、OAuth、SMTP、S3环境缺失           | 在对应任务记录具体缺少的服务/样本；单元替身不当成真实环境证据                      |
| 回收预览与删除相互作用                  | 开始永久删除后拒绝所有者预览；旧公开外链仍拒绝回收对象，已有下载无法撤回           |

本轮沿用已评审规格，不新增产品选择。实施中若真实协议实验迫使改变外部行为或数据契约，先明确差异并交用户确认；不能靠临时兼容层隐藏问题。
