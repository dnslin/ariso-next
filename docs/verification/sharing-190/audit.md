## 发现与处理

**Required（已修复）：重复创建跳过了明确输入契约。** 原 `src/server/sharing/configuration.ts` 的 `createShare` 在 Zod 校验前读取并返回已存在分享，使同一 POST 的无效 `password: null`、客户端 `token` 字段或非法 layout 在相册未分享时返回 400，在已分享时却返回 200；原配置集成测试还把非法重复输入成功作为期望。sharing §8 明确规定协议使用 Zod schema、参数错误返回 400。现在先解析输入，再读取并返回已存在记录；仍只在没有记录时计算哈希和创建，合法重复请求返回现有配置的语义保持。实际读取 [失败回归](./configuration-invalid-create-before.txt) 和 [定向通过](./configuration-invalid-create-after.txt)，并复核配置保存没有变化。[生产 HTTP 六项重跑](./production-http-after-review.txt)通过，三种非法重复请求均返回 400，合法重复请求仍返回原配置。

**Required（已修复）：百分号编码的分享 Token 可能进入错误日志。** 原 `src/server/runtime/log-redaction.ts` 只匹配 `/s/[A-Za-z0-9_-]+`；Next 能解码合法 Token 的 `%61` 等写法，而 HTTP 故障日志使用的 `URL.pathname` 保留百分号编码，因此原规则漏掉可还原的能力地址。主执行者先增加失败回归，再将 `/s/` 后完整路径段脱敏，保留 `/unlock` 等端点和普通参数。本审计实际读取 [失败证据](./log-redaction-before.txt) 与 [17 项通过证据](./log-redaction-after.txt)。全量集成中的生产 HTTP 六项随后通过；另实际读取服务器错误记录，确认编码路径为 `/s/[Redacted]/unlock`，分享 ID、SQLite 错误及堆栈保留。最后审计修复后的 [HTTP 回归](./production-http-after-review.txt)再次通过该真实错误路径。

Next 启动模块与 Route Handler 可能包含不同的错误类构造函数。当前 HTTP 边界按受控内部错误的明确 `status` / `code` 字段识别 `SHARING_*`、`UNAUTHORIZED` 和 `INVALID_ORIGIN`，不会将正常 401 / 404 / 429 因 `instanceof` 身份差异误报为 500；未知真实依赖错误仍保留服务器诊断并只向匿名返回必要 500 提示。已读取修复前生产 HTTP 失败记录；本轮全量集成中的生产 HTTP 六项通过，覆盖该分包边界。

Node 24 的原生 TypeScript 仅剥离类型，不能执行构造函数参数属性。分享错误类当前采用普通字段和赋值，浏览器夹具的导入链不再含该新增不支持语法。旧浏览器失败证据保持；实际读取 Node 24.19.0 / TaskSpace 32 的生产协议 [定向通过记录](./browser-focused-fixed.txt) 与对应 runner / protocol JSON，已验证该真实导入路径。

健康检查的精确生产表清单及空表断言已加入 `album_shares` / `share_grants`，没有删除旧断言或改为松散匹配。已复核这四处新增行，以及健康检查与秘密预检 [八项通过记录](./runtime-fixtures-rerun.txt)。浏览器运行器同时复用既有 `setupCodes` 提取新夹具初始化码，在保存协议服务器日志前脱敏；不改生产日志或身份行为。最后 Ego 重跑实际保存的 `sharing-protocol-server.log` 中初始化码为 `[redacted]`，已直接读取核对。

没有为了规避失败削弱断言、跳过测试或添加假数据匹配。真实验证函数仅在真实密码比较完成后用等待门控制并发次序；配置、SQLite 和 grant 写入仍是真实路径。过期后恢复、旧撤销版本、验证完成起算、实际哈希异常、重启、清理及 stop 均有行为断言。
