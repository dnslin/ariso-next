存储契约、并发与测试有效性
- storageResponse 的错误 body 不包含 scan。失败 UI POST 完成后从真实 GET 读取持久扫描信息；成功 POST 消费实际扫描响应的必要字段。没有补假字段或更改生产接口。
- maintenance.scan 对同一存储复用正在运行的 Promise；后台启动即扫描全部配置，之后每60秒执行。测试允许真实 UI POST 启动或加入前一终态基准之后的新轮次。
- 审计发现并修正：终态等待后再次 GET 可能把正在运行的新轮次误作旧基准；一次 UI 刷新可能读到 running 后永远等旧界面；过晚读取 DELETE 计数会漏掉合法共用轮次的请求；恢复 gate 切换前已收到403的旧轮次可能仍被 UI POST 加入。
- 终稿只保存终态 GET 的 startedAt 字符串；准备循环有整体90秒截止，只有页面明确显示扫描中而按钮禁用时才等待真实终态并再次真实刷新；其他禁用原因直接失败。
- exact orphanPath 的 DELETE 计数在准备开始前取值。恢复时先 arm 精确 hold，再等待该 DELETE 已挂起或旧扫描已经终态，随后才点击真实 UI；不会刷新到挂起状态后禁用按钮，也不会重试或吞掉真正 UI POST 的失败。
- 保留真实 POST 状态/错误码、新 startedAt、精确 DELETE、错误 key/AccessDenied/HTTP403、计数及对象保留/删除的断言。历史记录或定向夹具成功不能代替新增真实流程。
