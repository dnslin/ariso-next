## 实现范围

备份从本地与 S3 读取数据库实际引用的文件，停用存储也使用维护读取入口纳入归档，不修改源站启用状态。S3 文件流直接进入 ZIP64 与 age 加密流，不在本地保存一份远端对象副本。必需文件缺失、长度不符或读取失败时，任务失败且不提供半成品下载。

空白新实例按原存储 ID 分别配置新 S3 endpoint、区域、Bucket、前缀、Path Style 和凭据。目标测试复用既有私有、无版本控制及无对象锁要求；R2 必须明确确认 Bucket 无锁规则。保存变化使之前测试失效；全部当前配置通过后才能开始恢复。原凭据不会用来读取原 S3，新凭据在任务文件中加密保存，响应不返回密钥。

命名空间仍为 `<新前缀>/ariso/<原存储ID>/`，拒绝原位置和相互重叠的目标。短期任务标记使用条件写入，区分同时恢复到同一位置的任务；测试同时检查提供方确实执行条件写入。恢复只清理登记的本任务对象，不扫描或删除整个 Bucket。

恢复中的 S3 文件从已解密归档直接写入新位置，归档读取验证长度与 CRC，最终 List 核对对象名称和长度。成功写入的图片不逐个再次下载。保留原图片、对象、相册、标签和分享 ID，以及默认存储、启用和停用意图。旧 S3 的 CORS 结果失效。GitHub/SMTP 等保留配置在暂存数据库中换用新实例密钥；所有内容完成后才发布 ready，部署者重启后启用。

恢复额外本地空间只计算本地文件、素材、准备数据库与 16 MiB 余量；已有归档和流写 S3 内容不重复计入。重试先清理同任务的旧 ready，邻接任务不动。

## 回归与边界

取消后的全任务清理状态禁止任何目标更换位置，只允许原坐标凭据修复。双目标回归先复现“一个目标清理失败、另一个已清理目标仍能改位置”，修复后运行 5 项协调器测试通过。另实际移除执行前的配置测试门槛，测试按预期失败；恢复原源码后 5 项再次通过。

独立评审还用 3 字节本地 HTTP 样本复现了远端延迟提交：SDK 取消已返回，但服务端随后仍可完成之前收到的 PUT。一次空 List 不能证明以后没有迟到写入。已用真实 SDK 和本地 HTTP 对图片、探测文件、任务标记、旧对象重试分别复现并修复。完整请求无确定响应时保留责任；明确 4xx 或未提供完整声明长度时可结算。观察到迟到 PUT 已提交后先持久结算 PUT，再登记删除；删除回复丢失时只观察结果，不重复发出尚未确认的 DELETE。删除确认后才释放目标，避免旧请求在新任务中迟到生效。相应两个 DELETE 用例先失败，修复后通过，此前最终故障回归为 34 项，准确范围保留在下方汇总。
