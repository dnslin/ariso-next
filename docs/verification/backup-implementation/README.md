# 本地备份与恢复实施记录

历史范围说明：本页保留 2026-10-22 至 23 的纯本地实施与当时的 S3 拒绝行为。当前 Local/S3 代码已接入，提供方、浏览器与最终复核见 [S3 实施记录](s3.md)；不将下方历史表格改写为 S3 已验证结果。

## 当前范围

已接入纯本地手动备份、服务器生成加密文件、所有者下载/取消/删除，以及空白新实例的初始化码授权、顺序上传、解密核对、公开地址确认、恢复准备和重启启用。存在任何 S3 配置（包括停用配置）时返回明确不支持，不跳过远端文件生成不完整包。

采用 ZIP64 外包标准 age v1 密码加密。密码及原配置解密材料不写任务记录；包内业务秘密在恢复库中换用新实例密钥。恢复保留账号密码、上传 Token、分享、图片版本和关系；旧会话及一次性凭据清理。目标要求相同应用版本、完整 revision 与数据库迁移版本，缺少构建身份时不开放创建备份或恢复。

备份期间关闭新修改准入，等待已准入操作及依赖任务，再暂停持久后台写入。浏览、外链和临时预览继续。准备 ready 只在所有内容同步、工作线程退出后发布，部署者手动重启才启用；completed 后不会再次覆盖后续数据。正常初始化与恢复互斥；取消清理失败保留占用和重试入口。

## 构建与打包问题记录

默认构建仍是 Turbopack。最初发生 `there must be a path to a root` import tracer panic；诊断用 webpack 构建成功，但没有以切换构建器作为修复。独立 Worker 使用 Node 内置模块入口后，默认构建实际成功，worker 仍由现有 TypeScript 编译和显式 NFT 追踪打包。

随后包纯净性测试发现 standalone 带入源码、测试、夹具和日志。Next 自身的 middleware NFT 已包含这些路径，单独重新运行 NFT 没有同样扩张；因此问题属于 Turbopack 对运行时 DATA_DIR 路径的资产追踪，不能通过打包后删除测试或全局排除掩盖。

隔离探针位于 `.data/backup-build-probe/`，仅使用已有依赖，独立输出 `.next`，没有启动 HTTP 或执行探针 API。两组有效对照：

| 对照                                                                          | 实际结果                                                                                                        | 结论边界                                                   |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 真正 `writeJobState` 的值引用，以及 force-dynamic GET 中的调用形状            | 两轮构建通过，API NFT 均 104 项，不带探针 README/log                                                            | 单独 jobs 模块未复现整仓问题，不等于组合依赖图无问题       |
| 原样 `restore-target` 副本，已有 fs ignore；随后仅给两处运行时 path.join 标注 | baseline 2 条 whole-project warning，NFT 126 项、含 README 和 10 个日志；注释后 0 条，NFT 104 项、无 README/log | 证明这两处导致全项目追踪；不证明其他更窄的路径 glob 已消失 |

主构建采用两处标注后仍出现少量 backups/restore 相关源码和测试，说明“没有 whole-project warning”不足以验收。随后根目录 join 注释曾使追踪再次扩大，已作为无效尝试撤回。最终采用四个 DATA_DIR 控制模块（jobs、runtime、restore-runtime、restore-target）通过 `process.getBuiltinModule('node:path')` 在运行时解析路径，文件系统仍保留常规 imports 和测试故障注入能力。没有全局排除或打包后删除。曾试用原生 fs 入口的过渡版本没有保留，避免绕过现有清理失败模拟。

最终 path-only 默认构建实际退出 0，并完成 native SQLite/SVG 检查；只读复核 middleware NFT 为 425 项，仓库 src/tests 均为 0，standalone 的 `src`、`tests`、`.env.local`、`.data` 均不存在。完整构建日志在任务本地 `.data/backup-product-build-native-path-only.log`。随后实际执行了完整集成、真实浏览器与ARM64容器验证；结果及准确覆盖轮次见上表，过渡包的失败没有记为通过。

探针日志、逐轮 NFT 快照和实验说明保留在任务本地目录。探针生成输出在结束后清理；主源码、主 `.next` 和用户数据不由探针修改。后续组合探针若碰到主源码并行变更，仅作诊断，不作为单变量对照证据。
