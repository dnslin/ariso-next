## 已实际验证的完整流程

1. 从空白源实例通过 HTTP 正常初始化与登录，创建上传 Token，上传真实的大于 8 MiB 的 PNG。
2. 创建相册、标签和图片关系，保存品牌图片、水印素材、受密码保护的分享和虚构 SMTP 设置。SMTP 仅保存配置，没有发送邮件。
3. 保存并读取原图、压缩图、缩略图、水印图及额外尺寸版本。
4. 持有一个已经准入的真实上传请求，创建备份。准备期间拒绝新修改，既有图片继续可读；释放上传后，上传正常完成并被收入备份，随后恢复修改能力。
5. 通过 HEAD 检查附件元信息，通过 GET 下载加密备份，并确认实际使用 age 文件格式。
6. 停止源实例并删除整个源 DATA_DIR，随后使用独立 DATA_DIR 和不同部署密钥启动空白目标实例。
7. 没有发送文件请求体时，错误初始化码即收到 401，且未创建恢复任务目录。
8. 分块上传途中重启目标实例，原初始化码失效；重置未完成上传后重新分块接收完整文件。
9. 错误备份密码产生可重试失败；正确密码重试成功并得到图片、相册、标签和原账号摘要。
10. 填写目标实例的新 publicUrl 并准备恢复。ready 前后均拒绝普通初始化覆盖，随后同端口重启完成启用。
11. 原账号真实密码登录成功，账号 ID、密码哈希、上传 Token 哈希、分享 token 和图片关系保持一致。旧登录会话及旧分享授权失效。
12. 逐一读取恢复后的所有图片版本、额外尺寸和品牌图片，比对字节长度及 SHA-256；校验水印素材实际文件。
13. 原 SMTP 设置用新部署密钥重新加密，新密钥能解出原值，原部署密钥不能解开新密文。
14. 原分享密码和原上传 Token 继续有效。新增图片、相册并修改既有图片后再次重启，全部新增和修改保留，completed 状态未重放恢复覆盖。
15. 另一个独立实例存在 S3 存储配置时，创建备份明确返回 `BACKUP_S3_UNSUPPORTED`，且不产生不完整备份任务。

所有实例、测试图片和备份均位于临时目录，测试退出后关闭进程并删除。测试没有访问既有站点数据。

## 证据边界

本记录证明本机真实打包服务的 HTTP 和本地文件恢复流程。浏览器交互、容器环境、生产部署和 S3 数据恢复不属于本次测试的通过结论。没有发布或部署。
