## 验证方式

环境：macOS arm64、Node 24.18.1、锁定 pnpm 11.19.0、生产 standalone、Ego Lite 任务空间 47。使用隔离数据库和真实本地存储上传；不修改用户正式数据。浏览器场景已注册到 `scripts/browser-plan.mjs` 的全量与独立入口。

预览响应丢失、排队呈现、相邻读取变慢与批量部分失败使用明确的浏览器注入；底层真实创建、上传和读取仍执行。此类证据不能替代真实网络故障、外部存储或 OAuth 重启验证。

本轮交叉复查发现上传内重新处理成功按钮仍写“返回图库”，已补来源文案并验证默认图库和上传动作。

### 执行中的纠正

- 首次整体集成与最终 standalone 重新打包重叠，运行产物被替换，启动相关测试失败。该轮已停止，最终构建完成后重新执行；不将该轮记为通过。
- 首次新浏览器场景把有边框控件的内部输入区误作 48px 外框。实际外框 48px、内部 46px；已改为分别验证外框和输入区，不改产品尺寸。
- 默认并发造成启动和媒体测试超时。保留断言与期限，降低到两个 worker 后，完整集成 161 个文件、1713 项通过。
- 真实页面发现手机筛选移除后的回焦丢失，以及全停用／空存储恢复视图遗漏上传返回链；两处已修复并取得行为测试和浏览器证据。
- 队列菜单手机端宽度在 85→109→121→133px 连续变化，捕获到四条 ResizeObserver 循环通知。已仅给新菜单补项目已有的最小宽度，上传分项严格错误检查随后通过。诊断插桩已移除，未过滤浏览器错误，见 [尺寸记录](evidence/resize-loop.json)。
- 排序触发器原紧凑内距会使新增指示与方向箭头靠近，已为指示预留空间；最终浏览器同时检查两者不重叠。
- 品牌保存验收会先关闭成功通知再操作下一项，避免既有品牌页通知临时覆盖底栏。这一公共通知摆放问题未扩大修改。
- 最终全仓格式检查仅有12个已有原型／评审文件格式问题。已批准原型保持冻结，不为本轮检查重写它；本轮改动和交付记录均通过格式检查。

调试运行保存在本轮 `.data/uiux-20261015-implementation/`，交付目录仅保留最终证据和必要的前后对照。

## 标题所有权

关闭流式元数据和仅改同步读取都已实际试验，仍存在标题空窗，因此未保留这些配置。最终让根布局内的 `BrandMetadata` 声明式持有唯一 `<title>` 与 favicon。路由只更新标题文本，图标替换更新原节点属性；未加入 `document.title` 写入、MutationObserver 修补或第二个兜底标题。

根布局按请求渲染，构建不读取业务数据库。首页／分享／密码恢复页移除重复标题声明，分享的描述、禁止索引与 referrer 保留。依据 [React title](https://react.dev/reference/react-dom/components/title) 的单一标题规则及 [Next usePathname](https://nextjs.org/docs/app/api-reference/functions/use-pathname) 的首个 HTML 渲染规则，标题在服务端首屏即生成。

保存品牌时沿用既有 `router.refresh()` 更新根布局；新请求读取当前数据库值。已加载页面沿用根布局品牌快照，在另一个标签页修改品牌后，需要刷新当前页面，不为本轮引入跨标签同步。

移动端使用真实 Chromium 的视口仿真，未使用实体 Safari／Android；外部存储、实际 OAuth 重启、线上部署不属于本轮验证。正式数据和已批准原型未修改。
