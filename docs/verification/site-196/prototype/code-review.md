## 首轮结论：需要修改

以下为必须修复的原型问题。行号对应首次审查快照；修复后按函数和文案定位复审。

1. **上传素材不能改变品牌文本。** `app/page.tsx` 的 `upload()`（约151–160行）成功路径调用 `setCustom(true)`，而 `custom` 同时决定站点名称和描述。从内置状态上传 Logo 或 Favicon 后，名称会由 `Ariso` 变为 `山野相册`，公开品牌也改变。这与“Logo 与 Favicon 分别更新，不随站点信息提交”不一致。将品牌文本演示选择与素材保存状态分开；素材成功只能更新本用途的模拟引用。移除 Logo 后公开页也应恢复内置标识而保持现有名称描述。

2. **结果未知时不能断言服务器配置未变。** 预览卡（约580行）的固定文字“当前配置尚未改变”同时出现在上传中和 `unknown` 状态。前者可能已经提交，后者正是无法确认提交结果。仅待提交选择态可以这样描述；上传中用提交过程文字，unknown 明确说明结果未确认并保留所选文件。已保留“服务器当前素材可能来自其他页面”的说明是正确的，不应把 URL 变化当作本文件已保存。

3. **取消及切换页面必须结束或保留明确的在途操作。** 底栏取消已禁用，但顶部返回（约368行）、卡片取消选择（约569行）和演示页选择（约173行）在 `busy` 时仍可触发。它们清除文件或切换页面后，`timerRef` 仍运行，700 ms 后模拟保存成功并强制回到设置页。原型应统一禁用在途离开入口，或在明确取消演示时清定时器、复位 busy，防止迟到成功；不能只处理底栏按钮。演示页/状态切换也需要明确地终止旧演示，避免旧任务覆盖新状态。

4. **删除状态缺口尚未补全。** “确认移除”（约473–485行）无论演示状态为何都直接清引用并显示成功。删除确认自身存在，取消不会写入，但缺少删除提交中、确认失败、结果未知、核对中/核对失败以及读回空引用后确认移除的可查看表达。T-SITE-04/DG-SITE 明确要求“素材上传或删除结果未知及核对态”；只提供上传 unknown 不能闭合这个设计缺口。使用小范围删除状态即可，无需复制完整页面或新建结果页。

## 已核对的实现与隔离

- File 只保存在当前选择 state，未克隆图库或关联对象。Blob URL 在替换/清空及组件卸载时由 effect 撤销；卸载也清理定时器。仍需修复第3项的组件未卸载时切换/取消路径。
- 明确上传失败会保留 File、预览和已保存的模拟引用；unknown 不自动再次上传，需用户明确选择服务器素材或继续上传。
- 两用途允许格式与 5 MiB 提示符合现有服务契约。原型文件输入的 `accept` 仅帮助选择，未宣称已经执行服务端内容校验；正式实现仍须消费真实400/413/415。
- `Mark` 对图片解码错误显示“素材无法读取”，没有悄悄改成默认标识。SVG 预览使用图片元素，未内联 HTML。
- 登录按钮明确通知“这是交互原型，未提交数据”。首页和分享演示已移除，避免改变其现有布局。素材成功通知明确带“原型演示”，不能记作真实成功。
- 配置差异仅排除原型生成文件与原型独立类型检查范围，沿用现有 prototype 隔离方式；未削弱产品 src 的 lint/typecheck 规则。没有依赖新增。
- 登录表单尺寸、忘记密码位置及 Modal 关闭行为由实施者根据首轮真实截图修正，属于独立设计复核范围，本审查不替代截图复核。
