# 图库组件进入与加载连续性

2026-10-12。用户明确“闪一下”发生在 `/library`，此前相册示例不能解决该页面的问题。本轮直接调整图库，继续取消淡出。

## 当前行为

- 标题、工具栏和真实卡片分别进入。透明度匀速显现 420ms，从下方 10px 归位需要 480ms；卡片错峰 55ms，最多延迟 165ms。
- 初次读取只显示简短加载状态，不再插入八张骨架格。真实缩略图首次成功加载后平缓显现，不再由 Skeleton 直接切成图片。真实零结果的空状态也单独进入，直接移除时没有淡出。
- 筛选、排序和分页请求使用 TanStack Query 的 `keepPreviousData` 保留旧卡片。请求期间禁止旧数据操作，真实结果就绪后再恢复目标查询的滚动位置。
- 手动刷新保留真实内容。加载更多模式仍回到第一批，并从空游标重新读取；分页模式读取当前页。失败仍显示错误并保留已有卡片。
- 本次图库挂载期间分别记住已进入的图片 ID 和已加载的缩略图 URL。虚拟滚动重挂已见卡片时不重新淡入；已见图片筛选补位和网格/瀑布流切换只改变位置。没有退出动画或原生页面快照。
- 缩略图继续遵守 delivery 的 `private, no-store`，没有新增图片字节缓存。图片重请求完成时也不会为已见 URL 再播放淡入。
- 减少动态效果时取消位移、重排和错峰，保留 200ms 透明度变化。右键菜单定位锚点放到 body，避免工具栏进入位移影响固定坐标。首次选择图片并直接打开右键菜单时，显式使用 HeroUI 的 `autoFocus="first"`，确保菜单立即获得键盘焦点，Escape 可关闭并恢复原卡片焦点。

使用现有 Motion 14.1.0 和 TanStack Query。相册与图库共用进入参数和减少动态效果订阅，不增加依赖。通用控件继续使用 HeroUI；新增的包装只负责真实组件动效，不添加可见布局。`LibraryScreen` 也供相册详情使用，`LibraryLoading` 也供相册图片选择使用；加载状态仍保留可访问名称及原有错误内容。本轮未重复相册详情和选择器的完整浏览器流程，相关集合单元检查已执行。
