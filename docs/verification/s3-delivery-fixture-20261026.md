# S3交付夹具与后台摘要回填隔离

PR #303第二轮CI中，健康5项及日志4项均通过；唯一失败位于S3交付测试的远端请求记录长度断言，预期28、实际29。这里比较的是远端请求数，不是访问统计值。

## 根因与修复

交付夹具实际写入原始文件并把图片标成已发布，却没有保存主分支新增的内容摘要。它被后台维护识别为需要回填的旧资产，回填的真实S3 GET与交付测试的请求记录共享端点，因时序不同干扰“签名不发起远端预检”的精确比较。

临时独立诊断实际对原夹具排队回填，观察到真实后台GET，诊断用例通过；诊断文件随后删除，不进入CI或生产。新增永久夹具回归在旧版本稳定收到`contentSha256=null`，与上传实际字节的SHA-256不符，RED退出1。

修复只给“已完成上传”的夹具填入实际上传Buffer计算的SHA-256，和正常上传路径一致，不是固定伪造摘要。生产签名、统计和后台回填代码没有修改；没有关闭、拦截或替换后台任务。

## 保持与补强的检查

- 原S3请求helper及全部原交付/权限/统计用例完整保留，特别是远端请求数精确相等断言没有改动或过滤。
- 新增夹具摘要严格等于实际原始字节摘要，且正常夹具不制造待回填记录的回归。
- 另增明确的旧资产场景：原图摘要为null，后台任务处于等待重试状态；仍要求302、签名前远端请求数完全不变、摘要仍为null、跟随签名得到原始字节。等待重试是该场景的数据状态，不修改生产调度设置，也不增加测试超时。
- 专门的历史原图回填测试完整执行，未用已知摘要代替它们的缺失摘要夹具。
