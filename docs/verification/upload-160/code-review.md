### 本轮发现与修复复核

1. Required，相册消费者忽略 `preserve` 会使未知结果结束后仍无法重新创建。首次 key 重置方案在真实页面未满足挂载行为，最终改用公共相册原有的条件挂载方式；已实际复核最终源码。测试要求未知实例重新打开仍禁用，显式结束后新实例为空且可编辑，不能把 Escape 当结束。
2. Required，默认存储在显示设置与正式事务之间变化时摘要会伪写旧名称。最终按实际 storageId 匹配名称，并增加“默认变化仍不传明确 storageId、摘要使用实际返回 ID”的单元测试。
3. Required，多选键盘 `all` 分支曾直接返回；最终合并可见全选与隐藏保留，浏览器从真实部分选择执行快捷键并要求两项均选中。
4. Required，浏览器初稿有不存在的提交 selector/刷新按钮、unknown 流程误用，以及共享数据库下错误的空夹具前提。最终使用真实摘要 selector、打开选择器刷新、正式挂载语义和明确隔离夹具。补充隐藏筛选、SPA、真实请求去重与回焦检查，未靠跳过失败或缩小断言解决。

### 选项焦点 Escape 的真实缺陷与追加修复

人工验收预览准备时发现新的 Required 产品缺陷：搜索为空、焦点位于已选列表项时，第一次 Escape 会清除选择，弹层仍打开。[修前失败报告](./reports/relations-option-escape-before-failed.json)实际保留超时、原选项 `aria-selected=false` 与触发器 `aria-expanded=true`，不是凭代码推测。审计者也实际查看[修前真实截图](./screenshots/relations-option-escape-before-light-1440.png)，已选标签消失，空搜索的弹层仍展开且原项保持焦点。此前47布局/9项通过没有覆盖这个焦点前提，不能用此前通过否认该缺陷。

审计者独立读取现有 HeroUI `ListBoxRootProps`、React Aria Components `ListBoxProps`、React Aria `useListBox` / `useSelectableCollection` 的类型与实际实现：默认 `escapeKeyBehavior='clearSelection'` 在选择非空时调用 `manager.clearSelection()` 并消费该键；`none` 则让该分支返回 false。类型说明明确允许外层负责 Escape 时使用此选项。本次最小修复仅设置已有 `escapeKeyBehavior="none"`，由原 Popover 处理关闭与回焦，没有新增自写键盘处理器，也没有更改 SearchField 有查询时先清空搜索的行为。

新增 `escapeFocusedOption` 分别覆盖相册、标签：先断言搜索为空、目标真实已选，聚焦后严格核对 activeElement 为指定 option；只发送一次原生 Escape；要求弹层与退出动画结束、触发器 expanded=false 且真实回焦；再核对全部选择 ID 与之前完全相同。该测试没有改成从搜索框 Escape，也没有发送第二次 Escape 使失败场景侥幸通过。
