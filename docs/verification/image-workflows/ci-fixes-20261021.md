# PR #294 CI 失败修复（2026-10-21）

原检查绑定提交 `be8d71f7fb3f02edde70bf38c4bac05e3b11edcc`，[Actions 39623837291](https://github.com/dnslin/ariso-next/actions/runs/39623837291) 的 checks 和 Media tools 通过，Production integration 为1232项通过、2项失败。本记录不改写该次失败结果。

## 离线依赖准备

`identity/setup-dev.test.ts` 的安装子进程使用 `extendEnv:false`，丢失了CI设置的 `PNPM_HOME`。pnpm11.19因所选store与复制的 `.modules.yaml` 不一致而重建 `node_modules`；另一store没有 `@air/react-drag-to-select@5.0.11`，于是出现 `ERR_PNPM_NO_OFFLINE_TARBALL`，尚未进入Next开发启动。

只为安装子进程保留原 `PNPM_HOME`。Next/prestart仍使用原隔离环境；`--offline --frozen-lockfile --ignore-scripts`、原时限、热重编译、初始化码不变及真实登录断言均保留。

本机最小pnpm实验确认旧环境会重建目录、保留变量后不重建且离线成功。本机默认store已有包，因此不声称本机复现了CI的缺包报错。

## 启动就绪与超时诊断

先为 `runtime/secret-preflight.test.ts` 补充失败阶段、用时、PID/端口、退出状态、stdout/stderr及原始cause；异常写入测试报告，临时目录清理后仍可诊断。原4项本地定向检查通过，不能据此将原CI失败判为偶发。

随后检查锁定Next16.3.5的实际安装源码：`start-server.js` 在加载配置及初始化请求处理器之前打印 `Ready in`。原夹具将该日志当成HTTP就绪，可能在冷启动尚未完成时就耗尽2秒请求预算。

新增一个隔离进程回归：通过该进程独有的preload延迟真实router初始化2500ms。旧逻辑实际失败，新增诊断显示已打印Ready、路由仍在初始化、进程未退出，随后出现健康请求TimeoutError。该实验复现了相同的就绪判断缺陷；原CI没有保存子进程日志，不能还原那次具体启动阶段或证明当时的负载原因。

修复让既有15000ms启动等待检查真实 `/api/health` 返回200及 `{status:'ok'}`，保留单次请求2000ms、原用例总时限和Ready日志断言。没有增大超时常量，也没有新增全局重试。原有错误密钥、损坏/篡改密文拒绝、迁移保留、不泄露密钥及恢复后不重放迁移的断言均保留。
