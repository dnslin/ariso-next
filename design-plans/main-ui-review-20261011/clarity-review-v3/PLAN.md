## 目标与范围

沿用 Ariso 当前布局、主题、公共外壳和 HeroUI。减少重复说明、宽文字行操作和无必要确认，让名称、操作归属及真实状态更容易扫读。不把全部按钮变成图标，不把所有说明藏入悬停提示，也不增加新的业务功能。

本轮范围：

1. 分享设置中未过期分享的启用/停用直切；正常态短文案。
2. 标签正常改名说明改 Tips，列表编辑/删除改图标组。
3. 后台已有按钮、侧栏和正常说明的有限文案精简。
4. 回收站记录的局部 hover 和焦点层级。
5. 访问统计切换周期时保留可识别的内容与失败状态。
6. 设置分区的同级图标一致性，不扩展为每个字段添加图标。

不在本轮重做公开认证页面、上传流程、图片详情、统计数据口径或存储生命周期。不增加 API、依赖、全站帮助框架、批量替换规则或新快捷功能。

## 高价值问题与最小修正

### 分享确认与正常说明

**位置与现象：** `src/app/shares/settings.tsx:549` 开关先进入启用/停用确认；截图中的“停用分享”弹窗只再次解释开关结果。

**额外负担：** 一个已明确表达启停的开关还要求再次确认，打断连续设置。

**最小修正：** 未过期分享的启用/停用直接提交。提交中保留当前页面和控件位置，阻止重复提交。确认成功后更新状态并用简短 Toast 反馈；失败保留可恢复状态。不要先改成成功再等待服务器。

**证据与待验：** 已确认该开关分别进入 `enable`、`disable`、`enable-expired` 分支。原型只移除前两个普通确认。过期分享仍先选新期限；轮换地址、清除密码和放弃未保存修改继续保留各自必要流程。未知结果先读取核对，不以 Toast 假装成功或再次盲写。

### 标签编辑与 Tips

**位置与现象：** `src/app/tags/list.tsx:44` 每行有两个宽文字按钮；`src/app/tags/dialog.tsx:105` 的普通改名规则进入常驻水绿说明块。

**额外负担：** 行末操作占据较多宽度，常规说明与实际错误具有近似视觉重量；标题、字段又重复原标签名。

**最小修正：** 行末采用 `Pencil / Trash2` 图标组，提示为“重命名 / 删除”。正常改名仅显示标题、名称字段和取消/保存，名称旁 Tips 说明“改名保留图片关联；不能重名或合并”。原名称保留在输入框，不再同时写入字段标签。

**证据与待验：** `explanation` 同时承载正常、冲突、失败和未知结果，不能整块删除。只有 idle 正常规则进入 Tips；重名、无效字符、失败、对象已不存在及核对入口仍直接显示。桌面悬停/聚焦可读，手机点击展开，关闭后回焦。删除确认保留对象名称和“图片不删除”的后果。

### 回收站 hover

**位置与现象：** 截图中缩略图、名称、元信息被一大片水绿底覆盖，右侧更多按钮也同时强调，行内主次不清楚。

**额外负担：** 普通悬停看起来像选择或展开状态，整行数据变成视觉焦点。

**最小修正：** 仅为回收站记录行做轻微、中性的局部提亮。默认、hover、键盘焦点、选中及菜单打开分别表达；更多按钮保持独立可识别。无位移、缩放或布局变化。

**证据与待验：** 本轮不改全局 `--default`，避免影响 Tooltip、按钮、标签抽屉及其他页面。原型需同时检查浅/深色、未选/已选、长名称和触屏；键盘焦点仍有清楚描边，不只依赖颜色。

### 统计周期切换

**位置与现象：** 本次 7 → 30 天实测内容区被卸载，出现加载态；原页面仍为同一个浏览器页面。

**额外负担：** 页面结构闪空，用户难分辨是在更新当前图表还是整个统计页面重启。

**最小修正：** 首次读取时显示加载占位；已有成功结果时保留最后成功内容，只在周期区域提示更新。标题、工具栏和图表容器不因请求中卸载。周期控件保留稳定尺寸。

**状态必须分开：** `requested` 是用户本次请求的周期；`displayed` 是当前展示内容实际所属周期；`last-success` 是最近一次成功结果。请求 30 天但仍展示 7 天时，不能把图表日期、排行、版本量标成 30 天。更新失败时直接显示例如“30 天更新失败，当前显示 7 天”，并提供重试 30 天的明确入口。

**证据与待验：** 不能只加 `keepPreviousData` 就声称失败时已保留结果。需要验证请求失败后最后成功内容仍存在，requested/displayed 不混淆，错误不被旧数据遮住。连续 7 → 30 → 90 切换时，较早返回的请求不能覆盖最新目标；今日和累计不随周期错误清空。真实日期、时区、延迟和每日等价数值表继续保留。

### 设置图标与内容归属

**位置与现象：** `src/components/site/site-form.tsx:33`“站点信息”无图标，`src/components/upload-limits/form.tsx:33`“上传限制”有 Upload 图标，`src/components/site/related-settings.tsx:119`“关联设置”无图标。

**额外负担：** 同一级分区被不同方式表达，只有某一区像重要功能；分区说明还与页头帮助重复。

**最小修正：** 同级分区统一标题图标的来源、尺寸、间距与颜色，例如站点信息 `Globe`、上传限制 `Upload`、关联设置 `SlidersHorizontal`。复用现有 Lucide，不给每个标签/输入强加图标。关联设置的重复正常说明删除，独立提交规则集中在现有帮助中。

**证据与待验：** 基本设置中站点信息与上传限制是两个独立表单、独立请求；不能为缩短文字把两个按钮都改成无归属的“保存”，更不能合并提交。原型保留底栏时采用“保存站点 / 保存限制”。其他设置分区仅按同级角色核对，不全站补装饰图标。

## 图标与文字决策

| 场景                               | 本轮方案                                                                  | 不做什么                                                 |
| ---------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------- |
| 标签列表编辑/删除                  | `Pencil / Trash2` ButtonGroup；Tooltip“重命名 / 删除”，可访问名称含标签名 | 不取消删除确认，不用 UUID 代替名称。                     |
| 品牌已配置行替换/移除              | `Upload / Trash2` 图标组，提示“替换 / 移除”                               | 未配置时仍保留“选择文件”，不让主要入口只剩孤立上传图标。 |
| 分享列表行设置                     | `Settings2` 单图标入口，名称含对应相册                                    | 只有一个动作时不为 ButtonGroup 凑新功能。                |
| Token 启停/撤销                    | 可合并已有行操作；启停保留“启用 / 停用”，撤销可图标化                     | 不用同一个 Power 图标让用户猜下一动作；撤销确认保留。    |
| 账号邮箱/密码修改                  | 各自行末短“修改”或 Pencil 图标；属于候选规则，本轮未制作该页原型          | 不跨两个设置行拼成不属于同一对象的按钮组。               |
| 保存、创建、开始上传、最终删除确认 | 保留短文字提交按钮，可带熟悉图标                                          | 不做纯图标；不把“保存后测试”“创建并启用”等不同后果藏掉。 |
| 已有图库/相册/回收站快捷操作       | 沿用现有 ButtonGroup、Lucide、Tooltip 与状态裁剪                          | 不复制第二套操作组、不把快捷动作又塞回更多菜单。         |

同一对象的并列操作才使用 ButtonGroup。独立保存、导航、互斥模式与危险确认不能因为视觉紧凑而混组。继续采用至少 44px 的独立图标命中区、清楚键盘焦点、触屏可达名称及减少动态效果支持。危险操作默认克制，hover/聚焦可表达危险性，不能让整组都像红色删除按钮。

## 保护边界

1. **独立提交不变。** 站点、上传限制、品牌、处理、邮件、GitHub 与存储各自保存；不新增总保存事务。分享密码、期限、展示仍保存各自内容。
2. **风险仍在决策位置。** 清除密码会扩大访问范围，轮换地址会让旧地址失效，永久删除不可恢复，删除相册/标签会移除关系但不删除图片；这些不能只放 Tooltip。
3. **未知不是失败或成功。** 输入和目标保留，先读回核对；不自动重发不可确认的写入。核对按钮不改名成“重试”。
4. **异步状态可辨。** 请求中禁用重复操作，成功更新真实状态，失败给恢复入口。永久清理 accepted 仍不等于完成，Toast 不替代部分失败或未核对结果。
5. **凭据和身份不缩没。** Token 完整值仅一次、密码不回显、SMTP 只测试已保存配置、待重启、生效值与保存值的差异继续直显。存储同名识别和必要诊断不因本轮短文案被删除。
6. **Tips 不是错误容器。** Tips 只承载次要规则。错误、禁用原因、实际风险及待核对内容持续可见；手机不能依赖 hover 才能获取。

## 最小实施分组

用户批准原型后，按以下顺序逐组实施；每组可独立检查，不先建设新的公共抽象。

1. **命名与现有按钮组合。** 应用批准的文案表，复用现有图标按钮和 HeroUI ButtonGroup。同步消费者、Tooltip、可访问名称与测试定位，不全局替换词语。
2. **分享与标签局部交互。** 分享普通启停去确认，保留异常/过期路径；标签仅正常说明迁入 Tips，保留原冲突及核对流程。
3. **设置分区一致性。** 同级标题补齐图标，删除重复普通说明；继续保留两个有归属的保存入口。
4. **回收站局部样式。** 只调整记录行 hover/selected/focus 对比，不改全局主题变量及清理流程。
5. **统计周期连续性。** 基于真实查询状态保持 last-success，明确 requested/displayed 和失败后的重试目标；完成行为测试后再补轻量过渡。
6. **批准范围 Figma 同步。** 实施时在既有文件中更新批准页面及适用状态，记录节点和产品差异；不重画无关历史状态。同步完成与真实产品验收分别报告。

## 原型与后续检查

原型应可交互查看：分享启停/过期、标签改名/Tips/重名/失败、图标组悬停/焦点、回收站默认/hover/选中、统计切换中/失败/重试、设置三分区及双保存。使用现有示例照片和品牌，不添加落地页、说明页或原型内教学大段文字。

正式实施后的检查计划：
