## 设计依据

- 用户本轮七张截图及文字反馈是本轮需求来源。
- 沿用 `docs/design/handoff.md` 的 Ariso 字体、颜色、侧栏、固定底栏和间距。
- 复用本地 `@heroui/react@3.2.6` 的 ButtonGroup、Separator、Tooltip、Drawer、Popover、Dropdown、Modal 和 Toast，不新增依赖。
- 图标沿用 Lucide。图标按钮有名称和悬停提示，不以图标替代必要的可访问名称。
- 使用本地 `design-with-clarity`、`frontend-ui-engineering`、`emil-design-eng` 的减负、组件复用和克制动效规则；浏览器检查使用 `ego-browser`。
- 通用做法采用上下文上传、侧边编辑、就地反馈和状态相关菜单。本轮不重新设计整站风格。

## 行为边界

### 选择与操作

- 公开的图片不出现“设为公开”；私有的图片不出现“设为私有”；混合选择可出现两种动作，仅修改需要改变的项。
- 所选图片都不属于任何相册时，不出现“从相册移出”。相册详情里移出仅解除当前相册关系。
- 选择管理只负责选择，不混入图片业务动作。全选/取消已加载不能影响其他页的选择。
- 已加载数量不等于全站数量；正式实现沿用当前查询范围和加载规则，不改成默认全站选中。
- 每个图标保持 44px 点击区域。选择面板清空后关闭，焦点回到搜索；全选后不把焦点留在禁用按钮上。

### 上传与相册

- 相册上传示例：`/upload?albumId=forest&returnTo=%2Falbums%2Fforest`。
- 相册名称从相册数据读取，不由链接中的名称字符串覆盖。
- 上传页预选当前相册，允许修改；上传完成后显示明确的“返回相册”，不依赖浏览器历史猜测目的地。
- 不同入口的草稿隔离：相册上传不覆盖独立上传页尚未提交的文件和设置。
- 点击开始时冻结本批文件及设置；失败保留输入，重试不要求重新选择。
- “从图库选择”仍为选择器，已在相册中的图片禁用并标明已添加。失败保留勾选。
- 正式实施复用已有 Uppy 控制器、上传队列和草稿机制。保留多相册、标签、存储、处理参数、目录/拖放/粘贴和后台上传能力，不复制第二套上传逻辑。

### 标签与分享

- 标签重名沿用现有规则：去首尾空白、NFC、Unicode 大小写折叠；不是简单的英文小写比较，也不把全角字转换为半角。
- 正式后台已避免新增同键记录。UI 应在新建时直接提示选择现有标签，不能误报又创建了一条。
- 抽屉应用失败不关闭，不清空勾选。正式实现应保留现有批量结果和未知写入后的查询恢复能力。
- 分享首次提交仍调用已有创建接口，创建并启用；取消/返回不会创建分享。
- 已有分享直接修改原表单。保留密码、到期时间、名称显示、停用等既有职责，不为了减少一层界面改变服务合同。

### 回收站

- 移入回收站完整成功不再弹结果框。Toast 仅说明结果，不要求再点击关闭。
- 部分失败不能只显示 Toast 后丢失失败项；应保留失败项选择和可重试反馈。
- 永久删除仍须一次明确确认。接受删除请求不等于文件清理完成，应显示“删除中”，不能提前宣称已清理。
- 删除中记录不可恢复。混选时只对可恢复项执行，成功数量不包含被跳过的记录，并保留其选择。

## 原型范围

- 包含图库、相册列表/详情、完整上传页、标签、分享管理/设置/只读预览、回收站。
- 非本轮页面在原型侧栏标记未开放，不代表正式产品功能不可用。
- 示例图片与上传是内存模拟，不验证真实服务器处理、登录、外链访问或物理文件清理。
- 未新增接口、数据库结构、依赖或兼容层。
- 本轮只在本目录新增文件；未改正式 `src`、正式测试、已有产品文档或上一轮原型。
