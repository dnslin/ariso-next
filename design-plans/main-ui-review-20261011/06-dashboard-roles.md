## Evidence chain

- Surface：`/dashboard` 与 `/analytics`。
- Problem：用户指出两页雷同。
- Design evidence：2026-10-11 使用 Figma 只读查询 `19:38`（工作台）和 `30:1225`（访问统计），两者原本都含四指标、周期、趋势、版本、热门和占用。差异主要是标题和底栏，工作台另含处理异常。用户本轮要求重新解决这一分工。
- Owner：两条 route 都调用 `src/components/analytics/page.tsx`；`screen.tsx` 现分别组合 `DashboardPanel` 的资源/待办和 `AnalyticsOverviewPanel` 的访问报表。
- Scope and affected surfaces：工作台、访问统计、现有每日访问/当前占用入口及返回来源。
- Uncertainty：下述分工已随原型批准，真实数据、零访问、旧数据、读取失败和刷新恢复已做定向检查；未执行完整默认浏览器套件。

## Design decision

| 内容                       | 总览                                                 | 访问统计                                 |
| -------------------------- | ---------------------------------------------------- | ---------------------------------------- |
| 页面名称                   | 统一叫“总览”，与侧栏一致                             | 访问统计                                 |
| 主要数字                   | 图片、相册、回收站、已登记占用                       | 所选周期访问、今日访问、累计访问         |
| 待处理事项                 | 初次失败、重新处理失败；没有异常时用一个简短正常状态 | 不重复待办面板                           |
| 7/30/90 切换               | 不提供                                               | 保留                                     |
| 趋势、版本、热门、每日数值 | 不重复展示整套报表                                   | 完整保留                                 |
| 存储信息                   | 占用摘要和详情入口                                   | 不重复大块占用摘要；保留现有占用详情入口 |
| 主要操作                   | 一个上传入口，其他内容直接链接到对应页面             | 刷新、统计说明、明细/占用详情            |

不增加近期上传、活动流、趋势预测或新的接口。总览数据全部来自已有真实计数、已登记占用和处理失败字段。

## Reuse

- 现有 OwnerShell、analytics 查询 hooks、计数类型、UsageContent、处理异常到图库的真实筛选入口和已批准单图统计。
- Exemplar：当前 UsageSummary 的 `knownBytes` / `unconfirmedObjects` 聚合方式；当前 AnalyticsFailures 的初次/重新处理区分。
- 将总览与访问统计拆成明确的内容组件；可复用查询和实际重复的小组件，不再用大段布尔分支控制同一整页。

## Changes

1. `/dashboard` 渲染资源摘要、处理异常与唯一上传入口，去掉报表周期、趋势、版本排行和热门排行。不要在标题和底栏各放一个相同上传主操作。
2. `/analytics` 渲染访问指标、周期、趋势、版本分布和热门图片；保留每日数值和当前占用的现有阅读入口。
3. 沿用已有接口，不重新实现计数和空间计算。占用有未确认对象时保留独立待核对状态；读取失败不显示为零。
4. 保留现有每日数值和占用明细阅读入口，包括已可达的总览占用详情；这不等于保留旧排行来源。管理详情的 `analyticsReturn` 只接受 `/analytics?days=7|30|90`，总览不再产生或认可排行来源，不增加兼容映射层。
5. 检查统计进入图库/回收记录、关闭详情和返回后周期/滚动/焦点的完整流程；保留永久删除图片不参与排行和历史累计保留的规则。

## Scope

- Inherit：工作台与访问统计桌面/手机及相关来源返回。
- Verify：空数据、正常数据、查询失败、旧数据、统计延迟/漏计、占用待核对、处理异常。
- Exclude：数据采集、聚合协议、排行规则、对象责任分类、单图统计布局和其他页面业务。

## Validation

- Product：两页拥有明确不同内容；相关入口真实可达，数据状态不丢失。
- Interface：两个页面的桌面/手机原型及空态/有数据示例已获批准；本轮继续对照真实产品的浅深色、短视口和适用状态。
- System：复用已有 queries 和模块边界，不新增聚合服务或数据库表。
- Repository：按现有 analytics 场景验证真实主屏、数据和来源返回。只更新因批准的信息分工而改变的展示断言，保留实际数据与状态断言；定向单测、静态、类型、构建和浏览器的实际命令及结果在本轮证据中另记。

## Stop conditions

- 需要新数据接口、额外后台任务或改变统计口径时，先提出独立决定。
- 需要取消现有阅读入口时，先在原型中明确目标并取得批准。
