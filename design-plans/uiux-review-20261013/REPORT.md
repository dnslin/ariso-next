# Ariso 全站 UI UX 设计评审

2026 年 10 月 13 日。评审基线为当前项目 `91555f28ecafce9567ea228a7e719961bda360db`。本轮只提出优化建议，未修改产品源码、业务规则或 Figma。

## 1 整体评审结论

Ariso 已有稳定的视觉语言和相当完整的失败恢复设计。最有价值的下一步是保留编辑工作和返回位置，让关键设置在提交前容易看见，并让维护入口准确指向相关对象。没有发现有充分证据支持的 P0 问题。

本报告保留 4 项 P1 和 8 项 P2。P1 集中于未保存输入丢失、列表返回丢失上下文、手机上传设置被队列推远，以及存储处理任务的错误目的地。P2 是现有流程的局部修正。没有提出全站重画、替换组件库或再做一轮装饰动效。

### 评审依据

项目依据为 [AGENTS.md](/Volumes/data/project/ariso/AGENTS.md)、完整[设计交付规范](/Volumes/data/project/ariso/docs/design/handoff.md)、[前端共用验收](/Volumes/data/project/ariso/docs/tasks/execution.md)、对应业务规格与当前组件调用链。2026 年 10 月 11 日的三轮已批准精简和 10 月 13 日的动画调整优先于旧稿及旧反馈。读取了当前 [Figma 补充分区](https://www.figma.com/design/74sT9Hrf8G4czcWeTkET5b?node-id=1081-19457)的实时导出；这不代表全站逐节点、逐像素对照已经完成。

实际读取并应用了以下本地技能：

- `using-agent-skills`：先查规范和调用链，明确范围，不把推测写成验证结果。
- `design-with-clarity`、`improve-ui`：以理解、发现、选择、执行和结果反馈审查界面；以对齐、分组和层级判断视觉表达；保留合理差异。
- `improve-animations` 及其 `AUDIT.md`、`animate`、`review-animations`：按用途、频率、节奏、可打断性、性能和减少动态效果审查运动。
- `ego-browser`：在真实浏览器中检查页面和操作路径。

四个 Agent 分别独立完成视觉、动画、交互、文案与信息架构审查，再由主 Agent 复现关键候选并交叉去重。对用户已批准的选择，不按技能中的通用数值机械判错。

项目使用 Next.js 16.3.5、React 19.3.0、Tailwind CSS 4.3.3、HeroUI 3.2.6、Motion 14.1.0、TanStack Query、Uppy、Recharts 和 YARL。现有组件足以支撑下述优化，无须为本轮建议引入新 UI 或动画依赖。

核心路径为：初始化与登录 → 上传及批次设置 → 图库与图片详情 → 相册和标签整理 → 分享设置与访客浏览 → 回收和清理。总览、访问统计及各设置页支持这些任务。

### 证据范围

全部 28 个页面路由，以及相关浮层和状态的实现与调用链均已审查。实际浏览使用现成生产构建和独立临时数据库，图片、账号、分享和存储均为评审样本。没有访问或修改用户的生产数据。

本轮实际检查包括：1440×1080 桌面、390×844 手机；图库、上传、基本设置在 360、430、768、1200 宽度的补充检查；找回密码 1024×600 短视口；三类手机深色页面；手机导航、详情、大图、选图、分享密码验证；受控的标签加载/读取失败、重置请求未知结果和处理设置核对。补充宽度样本及 25 个手机页面样本未观察到横向溢出。

这不是全部弹窗和错误组合的完整运行回归。真实 S3 连接与直传、SMTP 收件、GitHub OAuth、实际永久删除、满队列及长时间压力下帧率没有在本轮验证。相关状态通过源码与已有证据审查。新截图不能代替真实手机触控或所有历史设计状态的验收。

## 2 高优先级问题

### F01 图片处理与邮件服务切换分类后丢失未提交输入

- **优先级：P1。**
- **位置：**站点设置 → 图片处理、邮件服务。相关实现为 [processing-page.tsx:267](/Volumes/data/project/ariso/src/components/processing/processing-page.tsx:267)、[smtp-page.tsx:157](/Volumes/data/project/ariso/src/components/identity/smtp-page.tsx:157) 与 [settings-categories.tsx:64](/Volumes/data/project/ariso/src/components/shell/settings-categories.tsx:64)。
- **现状：**两页直接切换分类，编辑值随页面卸载丢失。实测把压缩质量从 82 改为 73，切到基本设置再返回后恢复为 82；SMTP 主机填写后同样恢复为空。
- **问题：**用户误切一个分类就需要重新填写。水印参数和邮件配置的输入成本尤其高。基本设置、品牌和存储已经有未保存离开处理，同类表单体验不一致。
- **建议：**仅在尚未提交且确有改动时，复用现有未保存离开确认，提供“继续编辑 / 放弃修改”。无改动时直接导航。不要把此建议扩大为阻止正在保存、发信或核对的普通站内导航，也不要把 SMTP 密码持久化到浏览器存储。
- **增加步骤的收益：**只在将丢失编辑工作的离开动作多一次选择，避免重新填写；正常浏览和提交路径不增加步骤。
- **证据：**本轮实际操作与[观察记录](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/flow-observations.json)。[未提交处理参数截图](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/processing-unsaved-1440.png)。现有 SMTP 生命周期测试允许进行中请求离页，应保持该边界。

### F02 相册和分享返回列表后重置搜索与分页

- **优先级：P1。**
- **位置：**相册列表 → 相册内容 → 返回；分享列表 → 分享设置 → 返回。相关实现为 [albums/screen.tsx:67](/Volumes/data/project/ariso/src/app/albums/screen.tsx:67)、[shares/list-screen.tsx:33](/Volumes/data/project/ariso/src/app/shares/list-screen.tsx:33)、[shares/settings.tsx:176](/Volumes/data/project/ariso/src/app/shares/settings.tsx:176)。
- **现状：**搜索词、页码和每页条数保存在页面组件中。返回地址固定为 `/albums` 或 `/shares`。实测两个列表搜索“相册 A”后进入内容/设置，再返回，搜索框均清空。相册结果从一项恢复为全部 24 项样本。
- **问题：**连续整理多个相册或分享时，每处理一个对象都要重新搜索和翻页。相册卡片进入分享设置后，也不能准确回到原列表位置。
- **建议：**沿用图库和标签现有的 URL 查询状态，保存搜索、页码和每页条数；进入内容或分享设置时携带实际来源。返回恢复该查询、滚动和触发项焦点。不要只保留一个模糊的 `from=album`。
- **操作收益：**消除每个对象处理后的重复查找，不增加操作控件或确认步骤。
- **证据：**本轮实际搜索与返回；[过滤后的相册列表](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/albums-filtered-1440.png)。分页重置由同一组件状态及固定返回路径确认，本轮没有单独执行全部分页组合。

### F03 手机多文件上传时关键设置在队列后方

- **优先级：P1。**
- **位置：**手机上传页 → 选择多张文件 → 检查本次设置 → 开始上传。[upload/screen.tsx:261](/Volumes/data/project/ariso/src/components/upload/screen.tsx:261)。
- **现状：**手机将全部队列放在“本次上传设置”之前，开始上传按钮固定在底部。390×844 选择 12 张样本后，设置区顶部在视口下方约 1484px，开始按钮却在 y780 持续可见。提交前没有当前草稿设置摘要。
- **问题：**用户需要滚过整列文件，才能确认存储、公开/私有、相册和标签；也容易在没看见这些设置时直接开始。提交后的冻结摘要不能替代提交前检查。
- **建议：**在手机队列前显示紧凑的“本次设置”摘要及修改入口，列出当前存储、可见性及相册/标签数量。修改入口定位到现有设置区。桌面继续保留右侧设置布局，不新增上传确认框或第二条固定底栏。
- **增加元素的收益：**摘要让实际提交参数在按下开始前可见；不要求用户额外展开或确认才能上传。
- **证据：**本轮仅选择文件，未提交上传。[12 张队列截图](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/upload-12-files-390.png)及[几何观察](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/flow-observations.json)。

### F04 存储引用入口不能准确定位相关对象

- **优先级：正常处理任务误导为 P1；仅缺少存储筛选为 P2。**
- **位置：**存储详情 → 引用与清理。[storage-reference-view.tsx:41](/Volumes/data/project/ariso/src/components/storage/storage-reference-view.tsx:41)。
- **现状：**“图片与版本”进入未筛选的 `/library`；“处理与删除任务”合并后统一去 `/trash`。计数来自当前存储，且包含回收图片、正常图片的排队/运行任务和删除清理任务。
- **问题：**用户已经在处理特定存储，点击后仍需重新找存储。正常图片处理任务不属于回收站；回收图片又不会在正常图库显示，入口与计数对象不匹配。
- **建议：**所有图片和回收入口携带当前 `storageId`。将正常处理和删除清理的目的地分开，分别进入相关图库图片及回收记录。必要时只补当前存储关联图片的定位信息，不新增任务中心。重处理中的图片可能仍为“已就绪”，不能仅用图片 `status=processing` 代替全部活动任务。
- **操作收益：**从阻塞数量直接找到相关对象，减少在错误列表里反复筛选。
- **证据：**“查看图片”未带筛选已在本轮实页确认，见[引用页截图](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/storage-references-390.png)。任务误导通过 [storage-references.ts:59](/Volumes/data/project/ariso/src/server/startup/storage-references.ts:59)和 [media/references.ts:31](/Volumes/data/project/ariso/src/server/media/references.ts:31)确认；本轮未创建运行中的处理任务复现该分支。

### F05 已创建分享的预览仍被禁用

- **优先级：P2。位置：**分享设置底栏。[settings.tsx:285](/Volumes/data/project/ariso/src/app/shares/settings.tsx:285)。
- **现状：**已启用且地址已确认的分享仍禁用“预览”，说明为“访客页面尚未开放”。同一评审样本的访客页已能输入密码并显示图片。
- **问题：**保存展示设置后，用户要复制地址、另开标签、粘贴才能检查。禁用原因也已过期。
- **建议：**改为“查看分享”，在新标签打开已保存且已确认的分享地址，保留设置页输入。继续遵守真实访客密码规则；地址轮换待核对时沿用地址不可用限制，不新增草稿预览或所有者绕过。
- **证据：**[禁用预览](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/share-preview-disabled-390.png)、[同一分享的访客列表](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/public-share-gallery-390.png)。历史占位原因已由后续 #192/#193 的交付替代，也符合当前占位退出规范。

### F06 相册跨页选图缺少已选内容检查入口

- **优先级：P2。位置：**相册 → 添加图片 → 从图库选择。[image-picker.tsx:212](/Volumes/data/project/ariso/src/app/albums/image-picker.tsx:212)。
- **现状：**跨页/搜索保留选择，底部只显示已选数量和清空全部。选中第一页图片后翻到第二页，该图片仍计数，但不能在当前位置逐项查看或取消。
- **问题：**误选时需要记住图片所在页或搜索词；清空全部又会损失正确选择。
- **建议：**让现有已选计数按需展开紧凑缩略图清单，允许逐张移除。借用图库已有清单模式，不搬入整套选择管理界面，也不增加添加前的强制步骤。
- **证据：**本轮跨页选图；[跨页截图](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/album-picker-cross-page-1440.png)。

### F07 修改站点时区要求用户手输标识

- **优先级：P2。位置：**基本设置 → 站点时区。[site-form.tsx:71](/Volumes/data/project/ariso/src/components/site/site-form.tsx:71)。
- **现状：**普通文本输入要求填写 `Asia/Shanghai` 等有效时区。错误文案却要求“选择有效的 IANA 时区”。IANA 时区即系统使用的地区标识。
- **问题：**修改时用户需要记住英文地区和斜杠，手机输入成本更高。“选择”的提示与无选项的界面不符。
- **建议：**复用初始化已有的可搜索时区组合及完整合法选项，保留 UTC 和现有保存规则。先不用增加一套中文城市字典，也不要用浏览器时区覆盖已保存值。
- **证据：**本轮两端设置页；现有 [setup-form.tsx:328](/Volumes/data/project/ariso/src/components/identity/setup-form.tsx:328) 与 [validation.ts:43](/Volumes/data/project/ariso/src/server/site/validation.ts:43)。

### F08 重置密码未知结果的标题与正文矛盾

- **优先级：P2。位置：**重置密码 → 请求结果未知。[reset-password-result.tsx:22](/Volumes/data/project/ariso/src/components/identity/reset-password-result.tsx:22)。

- **问题：**扫读标题会误以为密码没有变化，与实际无法确认的状态相冲突。
- **建议：**标题改为“重置结果待确认”；正文改为“未收到明确结果，密码可能已更新。请重新申请链接，再设置一次密码。”保留现有重新申请与返回登录，不自动重试旧链接。

### F09 处理设置核对表使用内部值

- **建议：**复用表单已有选项标签和九宫格中文；数字带原单位；空值按字段含义表达。只修改呈现，不改变核对、保留输入或选择保存值的规则。

### F11 图库与回收站搜索的执行方式不够明确

- **优先级：P2。位置：**图库和回收站搜索。[library-controls.tsx:129](/Volumes/data/project/ariso/src/app/library/library-controls.tsx:129)、[trash-screen.tsx:871](/Volumes/data/project/ariso/src/app/trash/trash-screen.tsx:871)。

- **问题：**从其他列表切来时，用户可能以为搜索没有生效。现有界面缺少稳定的执行线索。
- **建议：**保留大图库显式提交，将现有放大镜位置改为可识别的搜索提交操作；手机保持足够点击区并核对软键盘“搜索”提交。不要单靠输入后会消失的占位提示，也不必改成每次按键都请求。
- **证据：**本轮输入/Enter 对照与两页事件绑定。物理手机键盘未实测。

### F12 手机回收站默认工具栏多占一行

- **优先级：P2。位置：**手机回收站默认搜索与选择入口。[trash-screen.tsx:528](/Volumes/data/project/ariso/src/app/trash/trash-screen.tsx:528)、[trash-screen.tsx:877](/Volumes/data/project/ariso/src/app/trash/trash-screen.tsx:877)。
- **现状：**搜索框强制整行，44px 选择记录图标单独换到下一行。
- **问题：**在已经有三项必要筛选的手机页面，再占一行会把实际记录或空态继续推低。
- **建议：**未选择时搜索占剩余宽度，与选择图标并排；已选批量操作按需要换行。保留 44px 点击区、可用输入宽度和直接筛选，不新增筛选弹窗。
- **证据：**[390px 回收站截图](/Volumes/data/project/ariso/design-plans/uiux-review-20261013/evidence/trash-390.png)。这是局部布局建议，不是全部工具栏强制一行的规则。

## 4 交互优化建议

| 任务              | 当前额外成本               | 最小优化                   | 普通操作是否增加步骤                       |
| ----------------- | -------------------------- | -------------------------- | ------------------------------------------ |
| 编辑处理/邮件设置 | 误切分类后重新填写         | 仅在有未提交修改时处理离开 | 仅可能丢输入时增加一次选择，正常浏览不增加 |
| 连续整理相册/分享 | 每次返回都重新搜索翻页     | 恢复查询、滚动和来源焦点   | 不增加                                     |
| 手机上传一批图片  | 滚过长队列才看见参数       | 队列前紧凑摘要，按需修改   | 不强制展开，不增加确认                     |
| 存储引用处理      | 去错列表，再手动找对象     | 带当前存储并区分对象目的地 | 不增加，可减少反复导航                     |
| 核对分享效果      | 复制、开页、粘贴           | 打开已保存分享地址         | 合并成一个动作                             |
| 跨页选图纠错      | 记住页码并翻回，或清空全部 | 计数按需展开逐项取消       | 正常添加不增加                             |

不建议把这些改进合并成一个新向导。继续保留各模块独立保存、业务确认和失败核对。只有会丢失工作或有明确后果的动作才保留确认。

## 5 视觉与动画优化建议

视觉上优先实施 F03、F10、F12：让提交前设置可见、收缩短视口空白、减少默认工具栏多余行。这些变化都服务于任务，不需要换配色、增加渐变、放大标题或改造全站卡片。

应明确保留：暖白、品牌黄、水绿与深靛蓝文字；统一后台正文起点；桌面可收起侧栏与手机全屏导航；图库双列、相册大封面的合理差异；明确外标签与字段错误；固定底栏及内容避让；紧凑图标组；按需帮助；成功后留原列表并使用中性通知；失败、未知与未提交项持续可处理。

动画没有确认需要修正的 P0/P1/P2。当前组件分别进入、刷新保留真实内容、虚拟列表重挂不重播、离开直接完成都值得保留。当前普通进入透明度 420ms、10px 归位 480ms、55ms 错峰且最多延迟 165ms；减少动态效果时取消位移与错峰，保留 200ms 渐入。图库节奏已有后续用户接受记录，不能拿旧的“快、闪、突兀”再次报告为当前缺陷。

保留查看器高频切换不附加等待，统计曲线不反复绘制，数字变化采用现有短动效。上传云图标和找回 Send 一次动作是已批准的用途差异。不要补全站页面淡出、键盘操作等待、长列表装饰错峰或统一骨架。

字体核对有一项低影响规范差异：文档要求英文 Inter，但当前全局只加载 Caveat 和 Noto Sans SC。现有截图中英文与数字可读，没有观察到体验阻断，因此不计入本轮 12 项体验问题，也不排在流程改进前。若后续恢复字体规范，需同时检查混排宽度与数字换行，不借此换整套字体系统。

已删除收益不足的候选：仅为节省高度把桌面上传限制三个数字字段改成三列；无证据的浅底黄色链接；把全部圆角或照片布局强行统一；为所有加载加入骨架；按旧版 Next.js 常识误报 `retry`。没有要求删除必要的风险、权限、未知结果或一次性 Token 关闭确认。
