## 复用与审阅边界

原型直接复用产品的 `AdminShell`、`SettingsHeading`／`SettingsCategories`、HeroUI Card／Button／Modal／ComboBox／SearchField、分享设置开关、图片处理字段、找回密码外框与缩略图；新增永久删除流程还直接复用产品的 `TrashBatchWorkspaceContent` 与结果列表。色彩、字体、间距和断点来自产品样式。原型中的删除只改变本地样本，不触及产品 API 或业务数据；产品与 Figma 更新在实施记录中单独核对。

“现状”用于解释当前问题；“优化方案”用于审阅交互取舍。分享访客页使用演示密码 `123456`，并非产品密码。站点名称、图片与地址是样本。原型检查只证明原型可操作，不能代替正式页面的浏览器验证或人工验收。

## 检查与证据

本轮完整检查已在真实 Chromium 中通过：F05–F12 与新增永久删除流程分别覆盖 1440px 桌面、390px 手机，F10 另覆盖 1024×600 短视口的现状／优化对照，共 19 项流程检查、24 张流程截图。检查无原型脚本异常、产品 API 请求或横向溢出。结果见 [checks.json](evidence/checks.json)，各项截图在 [evidence](evidence) 中。

新增永久删除流程还通过独立 TypeScript 与 ESLint 检查。桌面和手机的确认、提交、结果、展开任务详情与返回已逐步操作；现状与优化态的确认／结果截图共 8 张，见 [evidence](evidence) 中的 `trash-delete-*` 文件。F10 的原型“现状”态保留原先 330px 顶部留白，用于短视口对照，不影响复用的产品组件。
