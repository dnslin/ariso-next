顶部细条是原型演示工具，不属于拟议产品界面。右侧“演示场景”可切换空结果、标签失效、保存失败、加载、旧图库指纹补齐、上传失败及 API/PicGo 响应；“重置演示”恢复初始示例。

建议按以下顺序查看：

1. 打开“没有标签的图片”，查看一张图片并添加“截图”标签。返回后该图片退出当前集合；切换“最近上传的截图”可再次看到它。
2. 在“全部图片”中添加筛选条件，点击“保存为智能集合”。可修改条件、另存、更名及删除；删除集合保留图片。修改后离开会提示是否放弃。
3. 切换“截图标签已删除”场景，查看失效规则与修复入口。刷新不会悄悄移除条件或恢复标签。
4. 到上传页选择四个示例文件，手动开始。结果分别展示新增成功、普通重复、回收站重复和失败；可查看已有图片、明确恢复回收图，以及仅重试失败项。
5. 从上传切回“最近上传的截图”，查看新增示例；再回上传检查队列保留。
6. 从演示场景打开“API / PicGo 重复错误”，点击模拟提交，查看 409、`UPLOAD_DUPLICATE`、`not_created` 与 `imageId: null`。该演示没有旧图 URL。

## 设计取舍

- 智能集合入口放在图库，使用名称选择菜单和既有条件条；不扩充侧栏，不增加独立的复杂规则编辑器。
- 条件筛选后再保存名称。调整已有集合时明确显示“未保存更改”，保存失败留在原处，允许重试。
- 集合使用当前图片数据，修改标签即可演示进入和退出。列表、数量和选择使用同一结果；批量添加标签只处理明确选中的图片。
- 重复是独立结果，不计为新增成功或可自动重试的失败。已有图片的公开性与标签不会被本次上传设置覆盖。
- 队列使用实际本地演示状态，开始时冻结设置。进入图片详情及站内切换保留队列，刷新整个浏览器则重置。
- 普通结果保持简短；标签失效、存量覆盖未完成和真实操作失败场景才显示相应说明。

## 复用与原型边界

直接复用正式 `AdminShell`、`LibraryCard`、主题选择器、字节显示、全局字体和颜色。控件使用已安装的 HeroUI 3；图标来自 Lucide；布局与新状态使用 Tailwind。公共样式与原型扫描来源在同一个 CSS 入口处理，确保共享卡片的尺寸、间距和响应式类实际生成。

参考当前[设计交付规范](../../docs/design/handoff.md)，界面家族为 `UI-LIBRARY`、`UI-DETAIL`、`UI-UPLOAD` 与 `UI-TRASH`。原型新增集合控件与重复状态，其余视觉以现有组件为基线。未修改 Figma，用户已认可本次原型，正式页面验收仍另行记录。

原型状态只存当前页面会话内存。图片数量、原图大小、日期、上传进度与响应是演示数据，不代表素材文件的实际大小，不执行真实 SHA-256、文件上传、服务端保存、S3 读写、后台任务或 API 请求。API 展示页只供评审，并非新增的产品管理页面。

本原型不复刻所有现有图库筛选、跨页数据、大图缩放及全部批量操作。重点是新增集合流程及重复处理；正式实现仍需复用和验证完整既有能力。尚未连接的侧栏页面在原型内禁用。

## 本地运行

使用 Node 24 和仓库已安装的依赖，在本目录执行：

```sh
npm run typecheck
npm run build
npm run start
```

编辑时可用 `npm run dev`。监听 `127.0.0.1:3173`，不执行生产初始化或连接数据库。生成文件由本目录 `.gitignore` 排除；根 ESLint 仅新增本原型 `.next/` 和 `next-env.d.ts` 的排除规则，防止把构建产物当源文件检查。
